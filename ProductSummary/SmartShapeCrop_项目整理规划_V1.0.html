5执行顺序与回滚保障

严格执行顺序，每档做完先验一遍再进下一档。

  1. 安全快照

    执行前先确认 git status 干净（当前已是干净状态），并对要删除的大文件做一次清单导出，存在 _archive/ 里备查。

  2. A 档：清理生成物

    按 build → dist 旧包 → 轮转日志 → 废弃 venv → pycache 顺序删。每删一项校验一次体积。

  3. B 档：归档残留物

    用「移动」而非删除，根目录 14 张图与 3 个 .bak 全部进入 _archive/，随时可还原。

  4. 冒烟验证

    运行 python main.py 启动一次，或跑一遍 pytest，确认 A/B 档未影响程序运行。

  5. C 档：结构治理（可选）

    压平 scripts 归档、集中打包配置。改完后必须重新跑一次 pyinstaller 验证 spec 路径正确。

  6. D 档：Git 瘦身（可选）

    git rm --cached 后单独提交，提交信息注明「chore: 移除调试产物与备份文件出版本库」。

!
回滚方式：A 档删除的全是可重建产物（pyinstaller 重跑即可）； B/C 档全部使用移动操作，_archive/ 内的文件按原路径放回即可完整还原； D 档用 git revert 回退提交。 不会使用 rm -rf 批量删除，所有删除项会先列清单给你确认。
