## 问题一：L 形挖角从水池设计器内联拆出独立面板

### 现象（8.31–9.1 用户反馈积累）
1. **操作路径长**：L 形与单洞/多洞同 Tab，用户需先切"水池设计器"→再切模式下拉→选 rect_lshape → 再填参数。对比圆角裁剪工具独立 Tab，L 形占 4 步 vs 其他模式 1 步。
2. **参数交叉污染**：CropDesign 对象的 `l_corner / l_cut_w_cm / l_cut_h_cm` 与单洞 `hole_w / hole_h` 字段同属一个 CropDesign。用户从 L 形切回单洞模式后，`l_*` 字段残留在 CropDesign 中，单洞渲染路径存在潜在读取错误风险。
3. **历史记录混杂**：L 形设计与水池设计器共用 `TARGET_SRC_POOL` 存储，用户在水池历史记录里混着 L 形项目、圆角裁剪历史记录，查找困难。

### 修复：新建独立 gui/lshape_panel.py（520 行，内聚 3 Worker + 1 Dialog + 独立数据流）

#### ① 独立设计对象 LShapeDesign（数据层解耦）
**不再复用 CropDesign**，全新定义 `LShapeDesign` 数据类，字段仅 L 形专有：
```python
@dataclass
class LShapeDesign:
    outer_w_cm: float = 100.0
    outer_h_cm: float = 60.0
    corner: str = 'tl'          # tl/tr/bl/br
    cut_w_cm: float = 20.0
    cut_h_cm: float = 10.0
    corner_radius_cm: float = 0.0   # L 形圆角（可选）
    material_name: str = ''
    target_name: str = ''
```
- 优势：与 CropDesign 零字段共享，切模式时状态绝不交叉污染
- 渲染时 `LShapeDesign` → 在 Worker 内部临时转为 `CropDesign(mode='rect_lshape')` 传给 image_ops（单向转换，无回流）

#### ② UI 组件全独立（界面层解耦）
`LShapePanel(QWidget)` 内含：
```
┌─ Tab（QTabWidget 最顶层与水池设计器/圆角裁剪并列）───┐
│  ┌─ 方向区（QGroupBox "挖角位置"） ──────────────┐    │
│  │  ☑ 左上  ☐ 右上  ☐ 左下  ☐ 右下           │    │  ← 4 RadioButton
│  └────────────────────────────────────────────────┘    │
│  ┌─ 尺寸区（QGroupBox "尺寸"） ──────────────────┐    │
│  │  外框宽 [___] cm   外框高 [___] cm         │    │  ← 4 DoubleSpinBox

└────────────────────────────────────────────────────────┘
```

从方向选择到导出，全部组件独立，不依赖水池设计器面板任何控件。

#### ③ Worker 全内嵌（线程层解耦）
原来散落在 3 个文件中的 3 个类全部迁移为 `gui/lshape_panel.py` 内嵌类：
- `_LShapeParseWorker`（草图识别）：原 gui/property_panel_workers.py → LShapePanel 内嵌
- `_LShapeConfirmDialog`（参数确认）：原 gui/property_panel_dialogs.py → LShapePanel 内嵌
- `_LShapeRenderWorker`（渲染）：全新渲染 Worker（水池 PoolRenderWorker 用 CropDesign，L 形渲染前先转 LShapeDesign→CropDesign，独立线程）

三 Worker 信号槽全部在 LShapePanel 内部完成信号连接，不跨文件发送信号。

#### ④ 入口接入（main.py 顶层 Tab 切换）

用户首屏即可看到 3 个独立 Tab，一步进入 L 形面板。

## 问题二：历史记录三源物理隔离

### 现象
圆角裁剪（`TARGET_SRC_CROPPER`）与水池设计器（`TARGET_SRC_POOL`）8.21 已完成两源隔离。但 L 形与水池共享 POOL 源：
1. L 形保存为历史 → 水池历史列表混入 L 形条目（点击 L 形条目 → 在水池面板中打开 → UI 字段与设计对象不匹配崩溃）
2. 水池保存为历史 → L 形历史列表混入水池矩形条目

### 根因
`core/app_settings.py` 历史记录存储仅两源，L 形缺失独立存储。

### 修复：新增 TARGET_SRC_LSHAPE 第三源

#### 存储层新增
```python
# core/app_settings.py 新增：
TARGET_SRC_CROPPER = 'cropper_history'
TARGET_SRC_POOL = 'pool_history'
TARGET_SRC_LSHAPE = 'lshape_history'   # ← 新增第三源

# 存储 Key 三物理隔离：
# QSettings Key:
#   /SmartShapeCrop/history/cropper/...      ← 圆角裁剪（独立 QSettings group）
#   /SmartShapeCrop/history/pool/...         ← 水池设计器
#   /SmartShapeCrop/history/lshape/...       ← L 形挖角（新增，全新 group）
# JSON 双通道文件：
#   %APPDATA%/SmartShapeCrop/history_cropper.json
#   %APPDATA%/SmartShapeCrop/history_pool.json
#   %APPDATA%/SmartShapeCrop/history_lshape.json  ← 全新文件
```

#### UI 层接入
- `gui/lshape_panel.py`：新增独立「打开历史记录」按钮，只读取 `TARGET_SRC_LSHAPE`；保存历史只写 `TARGET_SRC_LSHAPE`
- `gui/cropper_panel.py` / `gui/property_panel.py`：保持不变，仍只用各自源
- `gui/property_panel_poolbox.py`：删除 L 形相关 8 行历史记录代码（原混入的 POOL 源写入 L 形条目已移除）

#### 三隔离策略不变（继承 8.21 设计）
```
保留策略：今天 + 前 2 天 = 3 天
每日上限：50 条
过期清理：启动时 auto_expire_stale_records() 按日期删除
```

## 经验教训
1. **"功能嵌在另一个工具面板里"是用户体验债务**：L 形功能完整（识别+渲染+边框全部做好），但因为嵌在水池里，操作路径长 + 参数交叉污染 + 历史记录混杂，导致"功能完成 100 分，体验只有 50 分"。拆独立面板是 80% 体验提升的低成本动作
2. **独立数据类（LShapeDesign）比共享字段更安全**：共享 CropDesign 的 l_* 字段，只要有一个分支在错误模式下读取字段，就会出现"看似随机的 5% 行为偏差"。独立数据类直接从类型层面杜绝跨模式读取，编译器/IDE 就能发现错误，不需要运行时测试
3. **三源物理隔离是历史记录的设计底线**：历史记录的"混乱"会让用户放弃使用该功能——混着 3 种工具的历史，找起来比重新填参数还慢。多工具场景的历史记录必须一工具一源一存储文件一 QSettings group，物理隔离永远优于"加个 type 字段区分"（type 字段容易漏过滤）
4. **内嵌类降低跨文件依赖**：3 Worker + 1 Dialog 原来散在 3 个文件，改一个信号要跨 4 个文件 grep。全部内嵌到 lshape_panel.py 后，信号连接、接收、清理全部在一个文件 520 行内，IDE 点跳转 0 距离，维护成本大幅降低
