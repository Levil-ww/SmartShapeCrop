## 问题一：PyQt5 DLL 连环崩溃根因定位与根除（`6daba44`）

### 1.1 现象与错误堆栈
从 8.29 起用户陆续报告"启动崩溃"、"测试随机失败"、"程序时好时坏"，核心堆栈统一：
```
ImportError: DLL load failed while importing QtCore:
  The specified procedure could not be found.  (0xc0000139)
```
pytest L 形集成测试 2 条失败 100% 复现；GUI 启动 5 次中 3 次崩溃、2 次正常（看似随机，实际 Windows DLL 搜索路径优先级竞争）。

### 1.2 初判：PyQt5 版本不匹配？——误判修正
对比文件三要素（9.2 08:10 首次排查）：

| 文件 | 时间戳 | 大小 | 对应版本 |
|---|---|---|---|
| `.venv/Lib/site-packages/PyQt5/QtCore.pyd` | 8/3 14:50 | - | Qt **5.15.2** 编译的绑定（.pyd 依赖 Qt 5.15.2 入口点） |
| `PyQt5/Qt5/bin/Qt5Core.dll` | 8/3 14:50 | 6.0MB（159 DLL） | 官方 Qt **5.15.2**（与 .pyd 匹配 ✓） |
| `PyQt5/Qt5Core.dll`（**根目录**） | 9/1 14:48 | 4.9MB（36 DLL） | Qt **5.15.11**（✗ 与 .pyd 不匹配） |

pip 元数据显示：
```
PyQt5        5.15.11
PyQt5-Qt5    5.15.2
```
**初步结论（错误）**：PyQt5 5.15.11 + PyQt5-Qt5 5.15.2 = 版本不匹配。

**事后修正结论（正确）**：PyQt5 5.15.11 的 setup.py 依赖声明为 `PyQt5-Qt5>=5.15.2,<5.16.0`，而 PyPI 上 PyQt5-Qt5 历史发行**只有 5.15.2 一个版本**——「5.15.11 + 5.15.2」是**官方支持的正确组合**。版本不匹配是表象。

### 1.3 真相：`python-qt5==0.1.10` 非官方黑包覆盖写入 DLL

决定性验证（9.2 09:00 ctypes 无损判定）：
```python
# 验证 1：手动加载 Qt5/bin 正确 DLL 再 import
import ctypes
ctypes.CDLL(r'F:\SmartShapeCrop\.venv\...\PyQt5\Qt5\bin\Qt5Core.dll')  # 5.15.2 真 DLL
from PyQt5.QtCore import Qt    # ✅ 成功！

# 验证 2：手动加载根目录可疑 DLL 再 import
ctypes.CDLL(r'...\PyQt5\Qt5Core.dll')  # 5.15.11 假 DLL（4.9MB）
from PyQt5.QtCore import Qt    # ✗ 0xc0000139 崩溃！
```

→ 问题锁定：**根目录 `Qt5Core.dll` 不是官方 PyQt5 的 Qt5 5.15.2 DLL，而是某个来源不明的 5.15.11 DLL 混入覆盖写入**。

追查来源：
```
pip show -f python-qt5
Name: python-qt5
Version: 0.1.10
Author: Marcus Ottosson  ← 非 Riverbank Computing（PyQt5 官方作者）
Summary: "PyQt5"          ← 故意伪装成官方包名
Files:
  PyQt5/Qt5Core.dll       ← 往 PyQt5 目录覆盖写入自己的 DLL！
  PyQt5/Enginio.dll       ← 更多污染
  PyQt5/Qt.pyd            ← 绑定覆盖
  PyQt5/QAxContainer.pyd  ← ...
```

**机制**：Windows 加载扩展模块时**扩展模块所在目录优先于 PATH**。PyQt5/__init__.py 虽把 `Qt5/bin` 加入 PATH，但 QtCore.pyd 位于 PyQt5 根目录 → 加载时优先命中根目录的 `Qt5Core.dll`（python-qt5 写入的 5.15.11 版本）→ 5.15.2 编译的 .pyd 在 5.15.11 DLL 中找不到新增入口点 → 0xc0000139。

**定性**：用户/脚本先前某次 `pip install PyQt5` 时误装 `python-qt5`（PyPI 搜索第一个结果因名称近似排前），该包恶意/无知地把自己的 DLL 写入官方 PyQt5 目录，破坏整套绑定。8.29–9.1 期间"程序出各种各样问题"的**首要根因就是这个非官方包**。

### 1.4 恶性副作用：`pip uninstall` 损坏包时清空整个 site-packages

处置中尝试 `pip uninstall -y PyQt5 PyQt5-Qt5 PyQt5_sip` 卸载损坏的 PyQt5，结果：
```
FileNotFoundError: [WinError 3] The system cannot find the path specified
  → 随后 pip / numpy / PIL / cv2 / psd_tools / pytesseract / pytest 全部丢失
  → site-packages 整个被清空（除了 2-3 个无法删除的锁定文件）
```

**机制**：pip 处理损坏 RECORD 文件时（python-qt5 写入的文件不在 PyQt5 RECORD 中，反向卸载时文件归属混乱），触发「回滚失败 → 清理全部已安装」的兜底逻辑，连带卸载所有包（含 pip 自身）。

**恢复手段**：`python -m ensurepip --upgrade` 重建 pip（升级到 pip 26.1.2）+ 从三要件恢复（见 1.5）。

## 经验教训（事故教训级，永久存档在 memory）

### 6.1 PyQt5 组合的正确认知
- **PyQt5 5.15.11 + PyQt5-Qt5 5.15.2 是官方正确组合**，不要因版本号"看似不匹配"判断为"版本冲突"。PyPI 上 PyQt5-Qt5 只有 5.15.2 一个版本（PyQt5 5.15.11 的依赖声明恰好要求 5.15.2）
- 真正的"版本不匹配"：**DLL 时间戳 + 大小 + pip 版本三对照不一致**才是判定依据；版本号文字差异不作数

### 6.2 python-qt5 永久黑名单
- 非官方包 `python-qt5==0.1.10`（作者 Marcus Ottosson，非 Riverbank）故意伪装成 PyQt5，向 PyQt5 目录覆盖 DLL。**requirements_clean.txt 永久排除 + 所有安装脚本不得出现该包名**
- 任何 pip install 命令中写 `pip install qt` / `pip install pyqt`（模糊包名）都可能命中近似包，必须写全称 `PyQt5`

### 6.3 损坏 venv 的处置原则
- **绝不就地卸载损坏包**：`pip uninstall` 损坏包时，因 RECORD 文件异常会清空整个 site-packages（包括 pip 自身）
- **正确流程**：① `pip download -r requirements.txt -d wheels_backup/` 先备份轮子 → ② `pip freeze > snapshot.txt` 先快照 → ③ 直接 `mv .venv .venv_broken_DATE` 备份后**新建 venv 重装**，不要碰旧包内部

### 6.4 ctypes DLL 加载无损判定法
排查 DLL 兼容性不要反复卸载/重装（10+ 分钟且有 6.3 风险），用 `ctypes.CDLL(绝对路径)` **先**加载指定路径 DLL，再 `import PyQt5`：
- 成功 → 该 DLL 是兼容的
- 失败 → 该 DLL 是不兼容的
成本 5 秒，无损。永久手法。

### 6.5 项目整理瘦身的操作顺序
