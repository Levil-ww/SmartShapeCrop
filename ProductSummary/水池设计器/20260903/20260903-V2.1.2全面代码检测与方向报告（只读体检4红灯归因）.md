## 二、4 项测试红灯的真实归因（勿误判为代码 bug）

### 红灯 1：`test_pool_lshape_flow.py:73` — 挖角区渲染出纯白 (255,255,255)
**提交来源**：9.3 当日 `29584a6`「T2 L形纯白背景」。
**判定**：✅ **有意改变语义，不是 bug**。
- 原测试断言：`assert lshape_cut_region_mean() == expected_beige(245,238,218)`（旧逻辑用池底背景色）
- 9.3 修复后：挖角 = 镂空语义 → 必须纯白(255,255,255)（已写入 memory 硬约束）
- **处理建议**：更新测试期望值为纯白，附带注释引用 memory 硬约束。不需改代码。

### 红灯 2：`test_pool_lshape_flow.py:105` — 同一文件对称断言
同红灯 1，纯白语义变更同步更新测试即可。

### 红灯 3：`test_pool_lshape_flow.py:179` — `assert 100.0 == 101.0`（挖角 +1cm 损耗补偿）
**现象**：测试期望渲染后的几何挖角 = 设计值 + 1cm（即 100→101），但 `property_panel_layers.py:87` 注释明确写：
> 「挖角值直接取成品真值，**不做额外损耗补偿**」

**判定**：⚠️ **需业务拍板**（印刷 1cm 误差是致命级）。
- 9.3 T1 已将损耗补偿统一挪到 `LShapeDesign._to_crop_design()` 转换层（即 L 形独立面板是 +1cm 的），但水池设计器内联 L 形路径的 `PoolRenderWorker` 里还残留"直接传真值不加 1"的代码。
- 与 T1 commit `25376b3`「损耗回传」语义一致：识别层传真值，渲染层 +1，但旧水池内联 L 形渲染分支没有走 +1 流程。
- **处理建议**：若 L 形内联水池模式也要支持，按 LShapeDesign 规则统一 +1cm；若不支持（推荐用户走独立 L 形 Tab），在测试里用 `@skipif` 标记仅在独立面板场景运行。本次因只读未改代码。

### 红灯 4：`test_f5_f14_fixes.py` — `FileNotFoundError: packageV2.1.py`
**根因**：测试文件第 14 行 `import packageV2.1` 硬编码了旧路径。实际文件已于 9.2 commit `0fe8adc` 移入 `package/packageV2.1.py`。
**判定**：✅ **测试硬编码过时，不是代码 bug**。
- 修正：`import sys; sys.path.insert(0, 'package')` + `import packageV2_1` 或直接改 import 路径。

→ **4 红灯的真实分布**：2 项 = 9.3 T2 有意语义变更（需同步改测试）、1 项 = 业务拍板级分歧、1 项 = 测试路径过时。**零项是核心代码逻辑错误。**

## 三、被推翻的 2 项子代理误判（实测纠正，很重要）

### 误判 1：「`core.rounded_corner` 模块不存在 → `test_rounded_corner.py` 是僵尸测试」
✅ **纠正**：`python -c "import core.rounded_corner"` **成功**。
- 机制：`core/compat/__init__.py` 用 `sys.modules` 注册了 4 个旧路径别名：
```python
# core/compat/__init__.py：设计考究，同源校验
sys.modules['core.rounded_corner'] = core.corner
sys.modules['core.psd_loader'] = core.psd
# ... 另 2 个别名
```
- 测试正常收集运行，不是僵尸。

### 误判 2：「`property_panel_layers.py:399` from core.psd_loader → 必然 ImportError → PSD 导出必崩溃」
✅ **纠正**：同样走 compat 别名，`import core.psd_loader as psd_module` **成功**，功能正常。
- 结论：**这 2 处不是技术债，是兼容设计**，不需要修。子代理只读了文件表面 `import X` 没查 compat 层。
