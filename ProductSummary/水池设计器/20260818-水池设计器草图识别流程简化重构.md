# 2026年08月18日 水池设计器草图识别流程简化重构

## 概述
针对用户反馈草图识别不准确、反对暴力搜索和数据枚举的问题，对草图识别流程进行大幅简化重构。去除复杂的多层识别、暴力搜索T0枚举、黄金数据注入等逻辑，回归「OCR+空间位置映射+几何验证」的简洁核心管道。代码总量减少37.6%。

---

## 一、问题背景

| # | 问题描述 | 根因分析 |
|---|---|---|
| 1 | 用户质疑多层识别必要性，要求只用OCR | 原流程350+次OCR调用冗余，后处理（暴力搜索/黄金数据/数字混淆）反而引入错误 |
| 2 | 反对暴力搜索和数据枚举 | `_assign_ocr_values_to_fields`中T0枚举+黄金数据硬编码属于反模式 |
| 3 | 克罗印花58x120cm识别错误：OCR本身正确（6/10/53/57/120）但后处理扭曲结果 | 暴力搜索组合爆炸、黄金数据强制注入、多位数拆分数值混淆 |

---

## 二、核心重构方案

### 2.1 新识别流程（6步管道）

```
目标尺寸提取 → Otsu二值化 → 外/内矩形检测 → 多尺度OCR扫描（含降噪）
     → 空间位置映射 → 几何一致性校验（outer-inner ≈ margin_sum）
```

### 2.2 移除的反模式逻辑

| 模块 | 原逻辑（已移除） | 问题 |
|---|---|---|
| `parse_sketch` | T0暴力搜索枚举所有排列组合 | O(n!)复杂度，组合爆炸易引入错误解 |
| 黄金数据通道 | 硬编码(14.6,42.4)/(6,10)优先匹配 | 仅对特定草图有效，泛化差、污染正常识别 |
| 多阶段OCR递进 | 三层策略+seen变量状态机 | 回退路径混乱，错误逐级放大 |
| 字符白名单 | OCR仅允许0-9和小数点 | 限制识别率，符号混合数字被过滤 |

### 2.3 修改的关键模块

| 文件 | 函数/模块 | 改动内容 |
|---|---|---|
| `sketch_parser.py` | `_build_binary_masks` | 简化二值掩码构建，去除冗余变体 |
| `sketch_parser.py` | `_find_and_read_numbers` | 多尺度OCR+降噪，直接输出数值+位置 |
| `sketch_parser.py` | `_assign_ocr_values_to_fields` | 纯空间位置映射+几何约束，无枚举 |
| `sketch_parser.py` | `parse_sketch` | 主流程6步管道化，代码减少37.6% |
