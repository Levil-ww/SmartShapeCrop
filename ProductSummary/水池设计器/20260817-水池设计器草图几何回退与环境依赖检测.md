# 2026年08月17日 水池设计器 草图几何回退与环境依赖检测

## 概述
用户要求程序识别三张草图（图一、图二、图三）的外框、内孔和边距数据。测试时发现OCR识别返回空值，经排查确认用户环境缺少pytesseract Python包导致OCR功能被跳过。本篇涵盖13:07、13:44、13:46三次修复，包括：空间推理函数新增、几何比例回退方案、以及Tesseract环境检测。

---

## 问题一：草图OCR识别不准（13:07）

### 现象
合成草图测试中部分字段识别偏差，子图OCR失真导致文字扭曲。

### 根因
1. 子图裁剪后做OCR时图像失真，文字被拉伸扭曲
2. 预测性OCR位置在内框内侧，实际标注在外框外侧
3. 全图OCR替换策略过于激进，覆盖了合理值

### 修复（sketch_parser.py）

| 修复项 | 说明 |
|---|---|
| 新增`_assign_margins_by_spatial_reasoning`函数 | 基于OCR数字bbox的空间位置与8字段语义位置做映射打分 |
| 修正预测性OCR位置 | OCR ROI放在外框外侧而非内框内侧，匹配标注习惯 |
| 优化合并逻辑 | 空间推理结果优先级高于方向标签匹配 |
| 改进全图OCR替换策略 | 未经裁剪/缩放的全图OCR识别更准确，降低子图OCR权重 |

### 验证
使用合成草图测试，所有8个字段均与期望值完全匹配。

## 问题二：环境缺少pytesseract导致OCR空值（13:44）

### 现象
三张实际草图样例识别时，OCR数值字段全部为空，边距无法计算。

### 根因
用户环境已安装Tesseract OCR引擎（`E:\Tesseract-OCR\tesseract.exe`），但Python包`pytesseract`未安装，导致OCR调用被跳过，返回空候选池。

边距字段设计为仅依赖OCR识别，无几何回退机制，因此无法从外框/内框几何关系推算边距。

### 修复（sketch_parser.py）

修改`_geometry_fallback_values`函数，当目标尺寸存在时，通过像素几何比例计算边距作为回退方案：

```
边距计算逻辑：
- 根据草图中外框和内框的像素比例
- 结合目标外框尺寸（来自文件名或模板匹配）
- 按比例推算内孔尺寸和四边边距
```

### 验证结果
| 草图 | 误差范围 | 状态 |
|---|---|---|
| 图一（外框+内孔+边距） | <0.3cm | ✅ 通过 |
| 图二（外框+内孔+边距） | <0.3cm | ✅ 通过 |
| 图三（外框+内孔+边距） | <0.3cm | ✅ 通过 |

安装pytesseract后可切换到更高精度的OCR识别模式。

## 问题三：Tesseract环境状态确认（13:46）

### 诊断结果
| 组件 | 路径/状态 |
|---|---|
| Tesseract OCR引擎 | ✅ 已安装，位于 `E:\Tesseract-OCR\tesseract.exe` |
| pytesseract Python包 | ❌ 未安装 |

### 影响分析
- `pytesseract`是Python调用Tesseract的接口层
- 未安装时，所有OCR功能被跳过，走纯几何回退路径
- 几何回退可满足基本使用，但精度低于OCR+几何联合模式

### 建议
安装pytesseract以启用高精度OCR模式：
```bash
pip install pytesseract
```

## 经验教训
1. **边距计算必须有几何回退**：仅依赖OCR识别边距是脆弱设计，OCR失败时应通过几何关系（外框-内框=边距之和）推算
2. **环境依赖需前置检测**：程序启动时应检测pytesseract/Tesseract可用性，而非运行时静默跳过OCR，避免用户困惑
3. **子图裁剪OCR易失真**：对局部区域裁剪再放大OCR容易导致文字扭曲，优先使用全图OCR+位置映射
4. **空间推理优先级应高于方向标签**：OCR数字的真实bbox位置比方向标签猜测更可靠
