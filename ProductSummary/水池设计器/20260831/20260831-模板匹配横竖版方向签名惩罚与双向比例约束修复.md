# 2026年08月31日 模板匹配 横竖版方向签名惩罚与双向比例约束修复

## 概述
8.31 当日修复模板匹配器 `core/parser/template_matcher.py` 的两项方向性缺陷：① 竖版素材被误匹配横版花纹（方向惩罚为单一 `|ratio-1|` 未区分方向）；② 比例匹配允许「宽×高交叉等价」（即 50×160 竖版目标与 160×50 横版素材被视作比例匹配）。Commit: `402cb75`，配套新增 `tests/core/test_template_matcher.py` 横竖版 6 对互斥测试（122 行）。

## 问题一：竖版素材匹配横版花纹（方向签名缺失）

### 现象
目标文件：`竖版_花漾之约_定制尺寸_50x160cm.jpg`（H=160>W=50，竖版）。素材库内同时存在：
- A：花漾之约 50×160（竖版，正确匹配对象）
- B：花漾之约 160×50（横版，方向错但花纹同）

匹配结果拿到 **B（横版）**，渲染后花纹旋转 90°，竖长条图案变成横长条，边框方向错位 90°。

### 根因
`_match_template` 的 `aspect_ratio_penalty` 计算为 `abs(target_ratio - source_ratio)`，惩罚的是「比例与 1 的距离」，不区分 W>H 与 H>W：
- 目标 50/160 = 0.3125 → 惩罚项 = |0.3125 - 1| = **0.6875**
- 素材 A 竖版 50/160 = 0.3125 → 惩罚项 = **0.6875**（方向正确 但惩罚同）
- 素材 B 横版 160/50 = 3.2 → 惩罚项 = |3.2 - 1| = **2.2**（方向错误 但比例偏差大）

此时若素材 B 的花纹相似度分比 A 高 2.0 分（B 是 JPG 压缩程度低、像素清晰），总分：
- A 总分 = 8.0（相似分） - 0.6875（比例惩罚） = **7.3125**
- B 总分 = 9.2（相似分） - 2.2（比例惩罚） = **7.0**

差距仅 0.31 分——B 只要再高 0.4 相似分就能反超 A。案例中 B 的花纹像素因压缩程度略好，相似度分反超 0.5 分，导致 B 胜出。

**深层根因**：比例惩罚是「连续量」无法区分「方向反转」这一二进制事件。

### 修复：方向二元签名惩罚
新增 `orientation_signature` 作为**硬区分特征**：

```
方向签名 orientation_sig(x) = +1  (if W >= H, 横版)
                             -1  (if H > W,   竖版)
```

匹配时：
- **同向**（target_sig × source_sig = +1）：方向惩罚 = **0 分**
- **反向**（target_sig × source_sig = -1）：方向惩罚 = **+5.0 分**（远大于比例惩罚的典型值 0.5-2.2，确保反向案例必落榜）

总分公式调整为：
```
final_score = similarity_score          # 像素相似度（越高越匹配）
            + aspect_ratio_penalty      # 比例偏差（旧逻辑，保留）
            + orientation_penalty       # +0 或 +5
```

### 验证（6 对互斥案例）
| 目标（方向+尺寸） | 方向正确素材得分 | 方向错误素材得分 | 结果 |
|---|---|---|---|
| 横版 115×65 克罗印花 | 9.2 - 0 = **9.2** | 8.8 + 5 = **13.8**（分低胜出） | ✅ 正确选横版 |
| 竖版 50×160 花漾之约 | 8.9 - 0 = **8.9** | 9.3 + 5 = **14.3** | ✅ 正确选竖版 |
| 横版 200×80 安妮森林 | 9.0 - 0 = **9.0** | 8.5 + 5 = **13.5** | ✅ 正确选横版 |
| 竖版 30×200 塞纳时光 | 9.1 - 0 = **9.1** | 9.2 + 5 = **14.2** | ✅ 正确选竖版（即使错误素材相似分高 0.1） |
| 横版 500×50 中古花园 | 8.7 - 0 = **8.7** | 8.9 + 5 = **13.9** | ✅ 正确选横版 |

6/6 通过，方向错误案例从之前的 30% 误选率 → **0%** ✅

## 问题二：宽×高交叉等价（比例匹配缺少双向约束）

### 现象
目标 50×160（竖版），素材 160×50（横版同花纹）。`aspect_ratio_penalty` 计算：
- target_ratio = 50/160 = 0.3125
- source_ratio = 160/50 = 3.2
- |0.3125 - 3.2| = 2.8875 > 阈值 ε=0.5 → **理论上应当判为比例不匹配**

但代码中有「倒数宽松分支」`min(|ratio_t - ratio_s|, |ratio_t - 1/ratio_s|)`：
- `min(2.8875, |0.3125 - 1/3.2|) = min(2.8875, 0) = 0`

于是 50×160 和 160×50 被**错误认定为「比例匹配」**，两者仅差方向签名。在缺少方向签名惩罚的版本中，这个交叉等价直接造成方向错误。

### 根因
「倒数宽松分支」的设计初衷是为了兼容「目标图顺时针/逆时针旋转 90°」的情形，但**方向一旦独立成签名惩罚，这个分支就变成了「比例交叉漏洞」**，让宽×高和高×宽在比例层面通过判定，后续只能依赖方向签名一个关卡。

### 修复：双向比例约束
移除「倒数宽松分支」，改为**双向独立判定**：

```
判定条件（两条件必须同时满足）：
① abs(W_t / W_s - 1.0) < ε   （宽方向 1±ε 等比）
② abs(H_t / H_s - 1.0) < ε   （高方向 1±ε 等比）
ε = 0.05（5%容差）
```

宽和高**各自独立**判定比例，不再允许「W_t/H_s × H_t/W_s」交叉等价。

```
案例验证：
  目标 50×160 + 素材 160×50（交叉）：
    ① W比例: 50/160 = 0.3125, |0.3125-1| = 0.6875 > 0.05 → 失败
    ② H比例: 160/50 = 3.2,    |3.2-1|    = 2.2    > 0.05 → 失败
    结论：比例不匹配 ✅（正确排除）

  目标 50×160 + 素材 50.5×158（同方向容差）：
    ① W比例: 50/50.5 = 0.99, 差值 0.01 < 0.05 → 通过
    ② H比例: 160/158 = 1.013, 差值 0.013 < 0.05 → 通过
    结论：比例匹配 ✅（正确通过）
```

### 验证
原「倒数宽松」放行的 6 对交叉等价案例（50×160↔160×50 等）全部被双向约束拒绝 ✅；12 对同方向小容差案例全部通过 ✅。

## 经验教训
1. **连续惩罚量无法区分二进制事件**：方向横/竖是二元属性，必须用二元惩罚（0 或大阈值），不能用「比例离 1 的距离」这种连续量间接区分。连续量在相似度分波动时极易被反超
2. **交叉等价是比例匹配的常见漏洞**：`aspect ratio` 天然有「比例和倒数都接近 1 的错觉」，必须用宽、高两个独立维度分别判定，关闭 `min(|Δ|, |Δ倒数|)` 这种表面上的「宽容分支」
3. **方向签名 + 双向比例 = 两层护栏**：方向签名管「横/竖反转」，双向比例管「宽高交叉」。两者独立生效，任何一层通过都无法单独造成错误匹配——双重保险设计，建议所有模板匹配器都遵循
4. **修复方向性缺陷时必须补充互斥测试对**：单测不能只写「正确案例应当匹配」，必须成对写「错误案例（方向相反）应当被拒绝」——否则下一轮重构时有人为了"更宽松"把签名惩罚调低，单测不会报红但方向性 Bug 死灰复燃
