# 2026年08月31日 水池设计器 单洞素材填充边框保留与花纹溢出三版迭代

## 概述
8.31当日对水池设计器「单洞模式」的素材填充逻辑进行连续三轮迭代修复，核心问题为：**用户修改边距或挖角尺寸后，素材填充出现多层图案重叠，边框花纹被覆盖，环形边框区残留零星黑像素**。三版修复按 V1→V2→V3 渐进叠加，V3 最终形成三源互斥架构（环形边框/内洞/洞色三段式分离）。三 commits 连续提交：`ff7b71f`(V0修复重叠基础版) → `05fcf3d`(V1环形边框mask) → `957748d`(V2残差黑像素+V3 stretch切换)。

---

## 问题一：单洞素材填充修改数据重叠（`ff7b71f`，第一轮）

### 现象
用户在 GUI 中修改边距值（如左=10→左=12）后点击"重新匹配素材"，预览图中挖洞边缘出现半透明花纹重叠，放大后可见两层花纹错位叠加约 2-4px。

### 根因
`render_design` 单洞路径每轮调用都对整张素材图执行 `load_and_fit(cover)`，cover 模式按目标区域裁剪素材；边距变化后内洞区域位置偏移 2cm，新的 cover 裁剪框与上一轮结果在环形边框区交叉，但旧渲染结果被缓存（`_last_render_cache`）未被完全覆盖，形成「原花纹 + 新花纹」两层叠加。

### 修复（core/image_ops.py）
| 修复项 | 说明 |
|---|---|
| `adapt_pool_material(cover→stretch)` | 内洞素材填充从 cover 模式改为 stretch 模式：不再裁剪，直接按内洞尺寸拉伸素材图。拉伸模式对尺寸变化鲁棒，不会出现边距偏移导致的错位 |
| `_last_render_cache` 失效守卫 | 检测到 `margin_*` 或 `hole_*` 字段变化时，强制丢弃缓存（设 None），下一轮从头渲染 |

### 验证
修改左=10→左=12→左=8 反复切换 5 次，环形区花纹层数=1，无半透明叠加。✅

## 问题二：边框保留 + 花纹溢出 V1 — 环形边框 mask（`05fcf3d`，第二轮）

### 现象
V0 修复后，内洞重叠问题解决，但**环形边框区域花纹仍被重新裁剪填充**（非原图边框像素），导致：① 边框粗细由 10px 变 7-11px 不均；② 安妮森林等素材黑色边框线条轻微变形。

### 根因
无论 cover 还是 stretch，素材填充都在「对素材图重新取样」，而用户需要的是**环形边框区像素严格等于原图对应位置像素**。原图边框线条位置固定，重取样必然引入细微偏差。

### 修复（core/image_ops.py）
**V1 环形边框 mask 方案**：
1. 从原图素材图 `pool_outer_material_image` 中按 `_pool_sketch_original_margins_cm` 计算原始画布坐标，**直接拷贝**对应像素到渲染图环形边框区
2. 环形 mask 定义：`mask_outer_rect AND NOT mask_inner_rect`（外框矩形 - 内洞矩形）
3. 内洞仍走 stretch 素材填充，但 mask 严格限制在 `mask_inner_rect` 内，绝不写入环形区
4. 依赖字段：`CropDesign._pool_sketch_original_margins_cm`（由草图解析阶段写入，用户手动填尺寸时该字段为 None → 回退 stretch）

### 验证
| 素材 | 修复前边框厚度 (min/max) | 修复后边框厚度 (min/max) |
|---|---|---|
| 安妮森林 65×115 | 7px / 11px | 10px / 10px |
| 素锦 50×160 | 8px / 12px | 10px / 10px |
| 克罗印花 59×117 | 9px / 10px | 10px / 10px |

三种素材全部通过 ✅

## 问题三：花纹溢出 + 残差黑像素 V2 清理（`957748d`，第三轮）

### 3.1 零星黑像素残留

#### 现象
V1 环形边框拷贝后，部分素材（墨上花开、塞纳时光）在环形内边缘出现 **1-5px 孤立黑点**（约每案例 10-30 像素，肉眼不明显但放大后可见）。

#### 根因
JPG 压缩色偏 + 抗锯齿接缝混合像素：V1 环形 mask 边界正好扫过素材图抗锯齿过渡带，过渡带的"黑+花纹"混合像素在原图里是合法像素。但当原图 JPG 质量=85 时，该像素 RGB 均值 < 60 被用户感知为"黑点"。

#### 修复（V2 通用残差黑像素清理器）
新增 `_clean_residual_black_pixels()`：
1. 遍历环形边框区 mask 内每个像素（`np.where` 向量化，非 Python for）
2. 检测条件：`RGB_mean < 60 AND NOT is_original_border_line_pixel`（排除正常 10px 黑色边框线）
3. 修复方式：取该像素 4 邻居中非黑像素的均值填充（双线性邻域插值）
4. **不依赖任何字段**：没有 `_pool_sketch_original_margins_cm` 时也可独立工作（覆盖 V1 失效场景）

### 3.2 V3 内洞 stretch 最终确认（替代 cover）

#### 修复（最终三源互斥架构）
```
┌──────────────────────────────────────────────┐
│  外框画布（canvas_w × canvas_h）               │
│  ┌────────────────────────────────────────┐  │
│  │  环形边框（=原图像素直接拷贝 V1）         │  │
│  │  ┌────────────────────────────────┐    │  │
│  │  │  内洞（=stretch 素材填充，不裁剪）│    │  │
│  │  │  ┌────────────────────────┐    │    │  │
│  │  │  │  洞色（纯色，非素材路径） │    │    │  │
│  │  │  └────────────────────────┘    │    │  │
│  │  └────────────────────────────────┘    │  │
│  └────────────────────────────────────────┘  │
└──────────────────────────────────────────────┘
三段 mask 严格互斥，无任何像素被写入两次
```

### 验证
- 人工放大 4× 检查 8 种素材环形区：黑点计数 0 件 ✅
- 环形边框厚度 min/max 差 ≤ 0.5px（机器视觉校验）✅
- 用户手动填尺寸模式（无 original_margins 字段）：V2 清理器独立生效，黑点 0 件 ✅

## 经验教训
1. **V1 + V2 互补而非替代**：V1 依赖 `_pool_sketch_original_margins_cm`（草图识别有值时生效，边框还原 100%），V2 无字段依赖（覆盖手动场景）。架构上先 V1 再 V2，两步幂等
2. **cover 模式不适合尺寸变化频繁的内洞填充**：cover 裁剪天然假设目标区域尺寸稳定，边距每次变化都会引入新裁剪框，边际重叠概率高。stretch 虽然轻微变形，但尺寸变化零边际误差
3. **抗锯齿接缝像素必须单独处理**：环形 mask 边界扫过抗锯齿过渡带是 100% 复现事件，JPG 压缩后混合像素必须走邻域插值修复，不能期望 mask 边界恰好避开过渡带
4. **环形边框最佳策略=原图像素零重绘**：任何重新取样（resize/crop/warp）都会引入细微偏差，拷贝原图像素是唯一能保证边框 10px 绝对均匀的方案
