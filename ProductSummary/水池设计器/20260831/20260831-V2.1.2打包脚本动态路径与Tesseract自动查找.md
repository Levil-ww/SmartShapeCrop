## 新脚本关键实现

### 一、动态路径解析
```python
PROJECT_ROOT = Path(__file__).parent.resolve()     # 脚本所在目录 = F:\SmartShapeCrop
pathex = [str(PROJECT_ROOT)]                       # 自动定位项目根
```
不再依赖任何盘符硬编码。脚本移至任何目录均能自动定位。

### 二、Tesseract 四级查找链
`_find_tesseract()` 函数按优先级依次扫描，命中即返回：

```
优先级1：环境变量 TESSERACT_CMD
           用户手动指定 → 直接使用（最高优先级，覆盖所有自动查找）

优先级2：用户偏好路径（D 盘）
           D:/Programs/Tesseract-OCR/tesseract.exe
           （主力机实际安装位置，8.31 打包时验证正确）

优先级3：系统标准路径（C 盘）
           C:/Program Files/Tesseract-OCR/tesseract.exe
           （Windows 默认安装目录，CI / 新机器通用）

优先级4：Windows 注册表
           reg query HKLM\SOFTWARE\WOW6432Node\Tesseract-OCR /v InstallPath
           （64/32 位注册表项，兼容自定义安装路径）

优先级5：PATH 系统环境变量
           where tesseract → 取第 1 条结果
           （用户已将 Tesseract 加入 PATH 的通用情形）
```

全部失败时：打印红色错误提示"未找到 Tesseract，OCR 功能不可用"，允许继续打包（exe 启动后 OCR 自动走几何降级路径，不崩溃）。

### 三、隐藏导入完整清单（8 组）
参考 8.28 全量依赖审计 + 9.2 环境修复时的 import 失败记录，hiddenimports 包含：

| 模块类别 | hiddenimports 条目 | 作用 |
|---|---|---|
| OCR | `pytesseract`, `PIL.Image` | Tesseract 绑定 + PIL 图像预处理 |
| PSD 处理 | `psd_tools`, `psd_tools.api.layers`, `psd_tools.api.pil_io` | PSD 模板素材导入 |
| OpenCV | `cv2`, `cv2.data` | OpenCV 核心 + cascade Haar 数据（如未包含，cv2.CascadeClassifier 抛 `XML parse error`） |
| Qt 绑定 | `PyQt5.sip`, `PIL._tkinter_finder` | PyQt5 内部 sip 绑定 + PIL Qt 图像交互 |
| numpy 扩展 | `numpy.core.multiarray`, `numpy.core._multiarray_umath` | PyInstaller 偶尔漏打包 numpy C 扩展 |
| 装饰器工具 | `dataclasses`, `psutil` | 数据类 + 进程工具（资源监控） |

### 四、一键构建入口
```
python packageV2.1.2.py           # 默认：打包 dist/智能裁剪设计器V2.1.2.exe
python packageV2.1.2.py --debug   # 调试：打包单目录 + 控制台黑窗（排错用）
python packageV2.1.2.py --dry-run # 预检：打印 Tesseract 路径 + hiddenimports 清单，不实际打包
```

## 经验教训
1. **PyInstaller 打包脚本永远不要硬编码盘符**：项目位置、Tesseract 安装位置会因机器、迁移而变化。脚本必须以 `Path(__file__).parent` 为基础动态定位，外部依赖必须多级查找链
2. **Tesseract 五级查找是最低可用集**：环境变量 → 已知偏好 → 标准路径 → 注册表 → PATH。缺任何一级，都会在某台机器上出现"明明装了 Tesseract 但 exe 找不到"的问题
3. **hiddenimports 必须基于真实崩溃记录补齐**：不要猜模块名，实际跑 exe 遇到 `ModuleNotFoundError` 时记录下来并补入。本次 8 组条目全部来自实际崩溃日志，没有一条是猜测
4. **--dry-run 预检在交付前必须跑**：新增参数 `--dry-run` 仅打印查找路径与模块清单，不实际打包（1 秒完成），交付前先跑预检能节省 3-5 分钟打包等待时间
