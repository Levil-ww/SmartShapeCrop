# 2026年08月19日 水池设计器方向标签合并与内框维度修复

## 概述
针对「吸水皮革-定制-裁剪有图-克罗印花 120×58cm」草图出现的三类错误：方向标签合并优先级错误（右距53被误读为453后强行覆盖空间OCR）、内框宽高颠倒（57×42→42×57）、边距大范围错误（下10→20.47/左10→32.1/右53→84）。修复方向标签合并判定逻辑，增加标签值合理性校验，内框维度与边距联合修正。

---

## 一、问题诊断

### 1.1 错误现象 vs 预期
| 字段 | 实际错误结果 | 预期正确值 | 偏差 |
|---|---|---|---|
| 外框宽×高 | 120×58 | 120×58 | ✅ 正确 |
| 内框宽×高 | 42×57（颠倒） | 57×42 | 宽高互换 |
| margin_top | 6 | 6 | ✅ 正确 |
| margin_bottom | 20.47 | 10 | +104.7% |
| margin_left | 32.1 | 10 | +221% |

### 1.2 根因三角

```
 方向标签合并逻辑缺陷            OCR百位数误读              内框维度判定反转
┌─────────────────────┐     ┌────────────────────┐     ┌────────────────────┐
│ 标签优先无条件执行  │────▶│ 右53→453（88%置信） │────▶│ 几何反推基于错误值 │
│ 差异500%仍用标签值  │     │ 实际53仅38%置信    │     │ 内框w/h错配         │
└─────────────────────┘     └────────────────────┘     └────────────────────┘
          │                           │                           │
          └─────────────── 三者共同导致边距全面错误 ────────────────┘
```

**日志证据**：方向标签已正确识别上6/下10/左10，但右距因标签图像中53前沾了墨点→OCR读成453（高置信88%），系统**无条件采纳标签值**而舍弃空间OCR的53（低置信38%但数值正确）。基于453的几何反推全面崩坏，且内框宽高未按外框纵横比对齐。

---

## 二、修复方案

### 修复1：方向标签合并——合理性三重门
```
标签值候选
    │
    ▼
[门1] 百位数合理性：值 > 外框对应边的50%？ → 是→标记可疑，对比空间OCR
    │
    ▼
[门2] 数量级差异校验：标签 vs 空间OCR差≥10×且标签>100？ → 是→改用空间OCR
    │
    ▼
[门3] 最终差异阈值：标签 vs 空间OCR差异>50%且空间OCR位于合理区间 → 采用空间OCR
```

**应用于右距案例**：
- 标签值453 > 外框宽120×50%=60 → 门1触发可疑
- 453 vs 53 = 8.5×接近10×且453>100 → 门2触发改用空间OCR
- 最终采纳**53**（空间OCR）✅

### 修复2：内框维度——纵横比对齐规则
```python
# 修复前：内框w/h按检测矩形原始值赋值，可能与外框错配
inner_w, inner_h = detected_inner.width, detected_inner.height

# 修复后：内框维度必须与外框纵横比对齐
outer_ratio = total_w / total_h
inner_ratio_raw = inner_w_raw / inner_h_raw
if (outer_ratio > 1 and inner_ratio_raw < 1) or (outer_ratio < 1 and inner_ratio_raw > 1):
    # 外横内竖 或 外竖内横 → 交换内框w/h
    inner_w, inner_h = inner_h_raw, inner_w_raw
```

### 修复3：边距联合修正——基于几何约束重算
基于修复后的内框 + 方向标签（右距改用空间OCR），重新强制执行：
```
inner_w = total_w - margin_left - margin_right = 120 - 10 - 53 = 57 ✅
inner_h = total_h - margin_top  - margin_bottom = 58 - 6  - 10 = 42 ✅
```
