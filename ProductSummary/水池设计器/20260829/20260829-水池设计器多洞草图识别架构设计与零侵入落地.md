# 2026年08月29日 水池设计器 多洞草图识别架构设计与零侵入落地

## 概述
8.29上午针对水池设计器的"矩形嵌套挖洞"功能扩展到**多洞（Multi-Hole）**场景：即一张草图中包含2个及以上内挖矩形框。工作分为三部分：
1. 使用ADR（架构决策记录）形式给出分阶段实施方案；
2. 明确方向标签在多洞场景的必要性（结论：非必需，以空间位置判定为主）；
3. 以"加法扩展、零侵入"原则落地首版实现——新增独立文件与字段默认值，原有单洞逻辑零修改。

涉及8条子问题，核心新增文件为 `core/pool_designer/sketch_parser_multihole.py`，验证规模：21新单测 + 230+回归全部通过。

## 问题一：矩形嵌套挖洞需支持2+个内挖矩形框（08:55）

### 现象
当前水池设计器仅识别1个内挖矩形（单洞），用户的实际设计稿中常出现并排2个或3个内挖框（典型的双孔桌垫、双孔餐垫等），程序直接忽略多余的框。

### 架构决策（ADR分阶段方案）
| 阶段 | 名称 | 职责 |
|---|---|---|
| ① | 多内矩形检测 | 扩展现有矩形检测器输出数量上限（原1→8），同时过滤装饰性、过小、比例异常矩形 |
| ② | 多洞区域划分 | 按x/y坐标将画布切分为N个独立洞区域（Zone），每个Zone关联唯一候选矩形 |
| ③ | OCR数值空间绑定 | 针对每个Zone独立执行"方向字+数值token就近绑定"逻辑，使用箭头/方向字辅助 |
| ④ | 几何校验 | 每洞宽高+四边边距必须≤外框尺寸；所有洞之间不得重叠；洞面积之和不得超过外框70% |
| ⑤ | 输出结构扩展 | HoleInfo新增逐洞字段，全局holes[]数组承载全部洞信息，缺失时fallback为传统单洞 |

## 问题二：多洞场景方向表达方式（08:55）

### 需求分歧
用户最初建议使用方向箭头（←→↑↓）或"上下左右"汉字直接标记，需判断是否强制要求。

### 决策
| 维度 | 结论 |
|---|---|
| **强制性** | 方向字/箭头在多洞场景**非必需** |
| **主判据** | 依赖洞bbox的空间几何位置：token中心落在某洞的"上/下/左/右"80像素缓冲带内，即绑定该洞的该边距 |
| **辅助增强** | 若草图中确实存在方向字/箭头，作为confidence加权项（权重×1.5），但不改变绑定结果 |
| **设计理由** | 真实手绘草图常省略方向字、仅标数值。空间几何为主判据能覆盖90%用例，方向标签作为锦上添花 |

## 问题三：零侵入实现原则（08:55）

### 约束
- 必须100%向后兼容现有单洞流程与测试；
- 不修改 `sketch_parser.py` 主流程任何已验证分支。

### 落地策略
| 策略 | 具体操作 |
|---|---|
| **独立文件** | 新建 `core/pool_designer/sketch_parser_multihole.py`，所有多洞逻辑收敛此处 |
| **默认值字段** | `HoleInfo` 新增 `margin_top/bottom/left/right`（逐洞版），默认值=全局margin字段，保持单洞语义等价 |
| **入口可选** | sketch_parser主流程中仅当"检测到候选矩形数≥2且几何校验通过"才调用multihole模块，否则走旧路径 |
| **输出双轨** | 同时填充 `design.rect_hole`（单洞兼容字段）和 `design.holes[]`（多洞新增字段），下游渲染器二选一 |

## 问题四：多洞输出结构扩展（08:55）

### HoleInfo结构调整（字段均带默认值）
```python
@dataclass
class HoleInfo:
    # ---- 已有单洞字段 ----
    hole_index: int = 0                # 0=单洞兼容，1..N=逐洞
    x_cm: float = 0.0                  # 左上角x（相对画布）
    y_cm: float = 0.0                  # 左上角y
    w_cm: float = 0.0                  # 洞宽
    h_cm: float = 0.0                  # 洞高
    corner_radius_cm: float = 0.0

    # ---- 8.29 新增逐洞字段 ----
    margin_top_cm: Optional[float] = None     # 单洞时=全局margin_top
    margin_bottom_cm: Optional[float] = None
    margin_left_cm: Optional[float] = None
    margin_right_cm: Optional[float] = None
    inner_w_cm: Optional[float] = None        # = 洞宽（后续内挖花纹对齐用）
    inner_h_cm: Optional[float] = None
    material_id: Optional[str] = None         # 每洞独立素材占位
```

### 全局承载
- `PoolDesign.holes: List[HoleInfo]`，长度=1时等价于旧版单洞，下游全兼容。

## 问题五：多洞空间位置判定算法（08:55）

### 核心思想
对每个候选矩形 `R(x, y, w, h)`，在其四周划定4条"绑定缓冲带"：
- 上带：`[x-20, x+w+20] × [y-80, y]`
- 下带：`[x-20, x+w+20] × [y+h, y+h+80]`
- 左带：`[x-80, x] × [y-20, y+h+20]`
- 右带：`[x+w, x+w+80] × [y-20, y+h+20]`

### 绑定流程
1. 所有数值 token → 遍历4个洞×4条带共16个候选区；
2. token中心落入即算命中，落入多个时取中心到对应边最短距离；
3. 方向字/箭头命中时给该区confidence +1.5倍权重。

### 碰撞处理
若两个洞的缓冲带重叠，使用洞的中线（x_mid / y_mid）作为分界，保证唯一归属。

## 关键决策沉淀
1. **空间几何为主、方向字为辅**：方向字非强制，避免用户因漏画方向字导致解析失败。
2. **零侵入铁律**：新功能独立文件+默认值，单洞分支零改动才能保证230+历史用例100%通过。
3. **输出双轨**：新旧字段并存且等价，下游（渲染/GUI/导出）可渐进式接入多洞而不同时改全链路。
