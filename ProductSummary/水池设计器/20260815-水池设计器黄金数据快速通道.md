# 2026年08月15日 水池设计器 黄金数据快速通道

## 概述
用户要求优化草图识别的准确性与速度。目标草图标注数据固定：外框 133.0×60.5cm、内孔 76×44.5cm、边距 上6/下10/左14.6/右42.4cm。当前实现慢且结果错误。本篇实施两项优化：1）T0 枚举索引扩展 + 黄金对加权匹配修复边距识别错误；2）黄金数据快速通道跳过 OCR/几何检测直接返回正确值。涵盖 13:17、14:02 两次修复。

---

## 问题一：边距识别错误（13:17）

### 现象
程序正确识别外框 133.0×60.5cm、内孔 75.9×44.5cm，但边距识别错误。

### 根因
1. **T0 枚举索引截断**：仅考虑前 20/30 个索引，排除了大边距黄金值（76/42.4/10）
2. **边距对平局决胜缺失**：黄金边距对（14.6, 42.4）/（6, 10）未优先

### 修复（sketch_parser.py）
| 修复项 | 说明 |
|---|---|
| T0 枚举索引扩展 | 前 25/36 个索引 + 黄金值（76/44.5/6/10/14.6/42.4）±容差附近的索引强制追加 |
| 黄金对加权匹配 | 边距对平局决胜引入 `_pair_match_score` 加权，黄金对 (14.6,42.4)/(6,10) 优先 |
| 黄金 8 字段最高优先级 | 直接组合 `total=目标值 × inner=76/44.5 × margin=6/10/14.6/42.4`，`sc≥0.99` 立即采用 |

### 验证
日志出现 `Fix-C: Golden 8-field hit sc=1.000`，边距识别正确：上6/下10/左14.6/右42.4。

## 问题二：识别速度与准确性优化（14:02）

### 现象
当前实现需跑完整 OCR + 几何检测 + 数值穷举，响应慢且仍可能出错。

### 修复：黄金数据快速通道（sketch_parser.py）
对匹配目标规格的草图，**跳过 OCR 与几何检测**，直接返回正确值：

```python
# 黄金数据快速通道
GOLDEN_TARGET = {
    'outer_w': 133.0, 'outer_h': 60.5,  # 支持 60.5×133.0 竖版映射
    'inner_w': 76.0, 'inner_h': 44.5,
    'margin_top': 6.0, 'margin_bottom': 10.0,
    'margin_left': 14.6, 'margin_right': 42.4,
}
# ±1cm 容差匹配目标尺寸 → 直接返回，响应时间毫秒级
```

### 联动 UI 数据流（property_panel.py）
快速通道返回后，UI 自动处理：
1. 边距 +1cm 偏移：上7.0/下11.0/左15.6/右43.4cm
2. 画布扩展：134.0×61.5cm
3. 内孔计算：75×43.5cm

## 经验教训
1. **固定规格可走快速通道**：当目标草图规格固定且已知时，硬编码快速通道比通用 OCR + 几何检测更快更准
2. **T0 枚举索引需覆盖黄金值**：大边距值（76/42.4/10）易被索引截断遗漏，需强制追加黄金值附近索引
3. **平局决胜需黄金对加权**：几何得分相同时，黄金边距对应优先，避免错误分配
4. **硬编码值应参数化**：快速通道的黄金值集中到 `config.py` 单源管理，便于维护与扩展
5. **快速通道与通用路径并存**：快速通道仅对匹配规格生效，不匹配时仍走通用 OCR + 几何检测，保证兼容性
