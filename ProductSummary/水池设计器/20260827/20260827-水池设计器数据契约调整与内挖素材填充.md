# 2026年08月27日 水池设计器 数据契约调整与内挖素材填充

## 概述
8.27当日针对水池设计器进行了4轮修复，涵盖：画布尺寸识别与边距噪声修复（克罗印花65x115误识别）、数据契约调整与GUI内挖数据显示、内挖素材填充功能设计与多轮修复（含背景花纹遮盖修复+移除纯色填充+空白挖空失败修复）、裁剪输出修复（多余背景像素+两侧黑色边框+简单拉伸模式）。涉及13条子问题，核心修改集中在`core/image_ops.py`、`gui/property_panel.py`和`core/geometry.py`。

## 问题一：画布尺寸识别与边距噪声修复（08:22）

### 现象
目标文件`双面格-定制-裁剪有图-克罗印花;65x115CM剪裁有图`被错误识别为画布尺寸116.0x54.0cm，OCR拒绝正确的`右=41.0cm`边距值。

### 根因
1. 状态机信任层级错误，权威模式未锁定target外框
2. 边距合理性上限未区分权威/非权威模式，权威模式下有效大值被拦截

### 修复（sketch_parser.py）
| 修复项 | 说明 |
|---|---|
| 状态机信任层级修正 | 权威模式应锁定target外框尺寸 |
| 边距上限区分模式 | 权威模式放宽限制，非权威模式保持严格限制 |

### 验证
测试通过 ✅

## 问题二：数据契约调整与GUI内挖数据显示（10:59~11:35）

### 现象
边距值处理方式需调整：应严格使用识别值，不再加1cm损耗偏移；内挖尺寸需由画布尺寸减去边距得出；GUI需显示内挖数据。

### 数据契约变更
| 字段 | 旧规则 | 新规则 |
|---|---|---|
| 画布尺寸 | 草图外框 | 草图外框 + 1cm损耗 |
| 边距 | 识别值 + 1cm | 严格识别值（不加1cm） |
| 内挖尺寸 | 独立识别 | 画布尺寸 - 边距（inner_w=canvas_w-margin_left-margin_right） |

### 修复（property_panel.py）
| 修复项 | 说明 |
|---|---|
| 边距处理逻辑 | PoolRenderWorker和`_on_sketch_parsed`中margin不再+1cm |
| 内挖尺寸计算 | 从68x45改为69x46（derived from canvas - margins） |
| GUI状态显示 | `_on_pool_finished_ok`显示画布尺寸/内挖尺寸/边距值 |
| 显示格式 | 画布122x59cm / 内挖69x46cm / 边距上8下12左6右41 |

### 验证
单元测试通过 ✅

## 问题四：裁剪输出修复（13:48~14:10）

### 4.1 裁剪后多余背景像素（13:48）

### 现象
裁剪后生成的图片有多余像素，尺寸不正确。

### 根因
`_edge_extend_fill`使用单点颜色填充，产生突兀色块。

### 修复（image_ops.py）
| 修复项 | 说明 |
|---|---|
| 镜像/对称延展 | `_mirror_extend_top_bottom()`和`_mirror_extend_left_right()`采样源图内容翻转填充 |
| 小延展量保持原行为 | ≤5%用简单边缘延展 |

### 验证
输出尺寸匹配，边缘延展自然 ✅

### 4.2 两侧黑色边框（14:00）

### 现象
裁剪后图片左右两侧出现宽黑色边框。

### 根因
源图黑色细线被`_edge_extend_fill`延展成宽边框。

### 修复（image_ops.py）
| 修复项 | 说明 |
|---|---|
| `_estimate_outer_border` | 检测源图黑色边线厚度 |
| cover模式优先 | 避免黑边延展 |
| 单点采样避外框 | 大延展时取内容区中心单点像素填充 |

### 4.3 简单拉伸模式（14:10）

### 现象
需参考`pack_BigMagicCompany_copy`项目改用简单拉伸模式。

### 修复
参考pack项目使用简单拉伸模式，完整保留源图边框线条不产生黑边（轻微变形可接受）。

### 验证
输出无黑边，边框线条完整 ✅

## 经验教训
1. **数据契约需明确**：画布尺寸=草图外框+1cm损耗，边距=严格识别值（不加1cm），内挖尺寸=画布尺寸-边距，三者关系必须清晰
2. **素材填充跳过边框带**：只要存在任何水池素材（外框或内挖）即跳过边框带渲染，保留背景花纹
3. **镜像延展优于单点填充**：边缘延展使用镜像/对称方式替代单点颜色填充，避免突兀色块
4. **黑边检测+cover优先**：`_estimate_outer_border`检测源图黑色边线厚度，cover模式优先避免黑边延展
5. **简单拉伸模式可接受轻微变形**：参考pack项目，完整保留源图边框线条不产生黑边比保持宽高比更重要
6. **模式切换需清理动态属性**：CropDesign模式切换时清理动态属性，避免残留状态导致功能失败
