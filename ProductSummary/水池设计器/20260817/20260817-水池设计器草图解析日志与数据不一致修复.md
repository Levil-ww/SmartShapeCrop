# 2026年08月17日 水池设计器 草图解析日志与数据不一致修复

## 概述
用户反馈：草图解析日志显示真实标注与最终解析结果不一致。具体案例：目标文件名解析为「吸水皮革-定制-裁剪有图-克罗印花」，花型=克罗印花，尺寸=58.0×120.0cm，布局=竖版；但草图真实标注为另一组数值。经深入诊断，发现为**四重叠加Bug**，每层单独看似"防御性设计"，叠加后导致正确的边距搜索逻辑被层层跳过，最终输出错误结果。本篇在16:58完成完整诊断与修复方案。

---

## 现象对比

| 维度 | 草图标注（真值） | 程序最终输出（错误） |
|---|---|---|
| 产品匹配 | 吸水皮革-定制-裁剪有图-克罗印花 | ✅ 正确 |
| 外框尺寸 | （草图实际值，日志可见） | ❌ 58.0×120.0cm（被边距值冒充） |
| 内孔尺寸 | （草图实际值，日志可见） | ❌ 错误（与边距混淆） |
| 四周边距 | （草图实际值，日志可见） | ❌ 完全错位 |
| 布局方向 | （根据标注应为） | ❌ 竖版（方向错误） |

## 四重叠加Bug诊断

### Bug 1：聚焦OCR无合理性校验，外框尺寸被误判为边距

| 项 | 说明 |
|---|---|
| 模块 | sketch_parser.py，方向标签→聚焦OCR候选生成路径 |
| 现象 | 方向标签检测到"横版/竖版"关键词后，沿标签方向做ROI OCR，识别到外框值58、120（大数值），但**未经合理性校验就放入边距候选池** |
| 后果 | 边距候选池混入了58、120这种显然是外框的大数值，后续数值分配时边距max被错误拉高 |
| 修复 | 聚焦OCR结果进入候选池前，按字段语义做值域过滤：<br>• 外框候选：40~200cm<br>• 内孔候选：30~150cm<br>• 边距候选：2~80cm<br>超出范围的值直接丢弃，不进候选池 |

---

### Bug 2：聚焦OCR结果使用前缺乏检查，跳过合理边距搜索逻辑

| 项 | 说明 |
|---|---|
| 模块 | sketch_parser.py，L2→L3过渡的"结果可用性判断" |
| 现象 | 只要聚焦OCR返回了≥1个值（即使全是Bug1混入的外框大数值），代码就认为"L2已得到有效结果"，**直接跳过L3全图OCR兜底**，也跳过了几何比例回退路径 |
| 后果 | 候选池里全是错误的边距值（被Bug1污染），本该用于兜底的L3全图OCR和几何回退都未执行，直接在垃圾候选池里做T0枚举 |
| 修复 | 聚焦OCR结果使用前增加**语义合理性检查**：<br>• 边距候选池4个值的最大值不应超过外框候选池最小值的70%<br>• 超过则判定聚焦OCR失败，回退执行L3全图OCR + 几何回退 |

---

### Bug 3：全图OCR替换逻辑数量级不符时破坏候选池

| 项 | 说明 |
|---|---|
| 模块 | sketch_parser.py，全图OCR→候选池合并逻辑 |
| 现象 | 全图OCR识别到一批值（含正确的外框/内孔/边距），与现有候选池合并时使用"并集追加"模式，不做数量级一致性检查。导致Bug1污染的边距值（58/120）与正确值共存 |
| 后果 | T0枚举时评分函数无法区分"正确边距6/10"和"错误边距58/120"，sc=1.000的错误解与正确解同时存在，随机选到错误解 |
| 修复 | 全图OCR结果合并时增加**候选池净化**：<br>• 先按外框→内孔→边距的顺序，确定每个字段的合理数量级区间<br>• 合并时丢弃与该字段数量级差≥5倍的值<br>• 同时执行"inner/margin互斥"检查（见同日一致性校验文档） |

---

### Bug 4：方向标签搜索候选未过滤外框尺寸，且无返回值安全门

| 项 | 说明 |
|---|---|
| 模块 | sketch_parser.py，方向标签→候选尺寸映射 |
| 现象 | 方向标签（横版/竖版）的bbox附近搜索数字时，搜索半径2cm范围内可能同时包含外框标注和边距标注。代码**取最高置信度的数字作为外框尺寸**，但最高置信度可能恰好是边距值（如"120"字体比"58"大、墨更浓） |
| 后果 | 外框尺寸被错误赋值为边距值（120），后续所有几何计算基于错误外框，导致内孔/边距全盘错误 |
| 修复 | 方向标签搜索时：<br>• 搜索半径内返回Top-3候选（不是只取Top-1）<br>• 增加**返回值安全门**：外框尺寸两个值（w/h）取完后，若两者乘积<400cm²（小于A4面积一半），直接判为异常，舍弃Top-1取Top-2<br>• 若Top-3均不通过，则放弃方向标签路径，回退几何检测 |

## 四重Bug叠加效果示意

```
草图上传 → 方向标签检测到"竖版"
              ↓
Bug4: 方向标签搜索半径取了边距值120作为外框（而非真值58）
              ↓
Bug1: 聚焦OCR把外框值58、120直接放入边距候选池（无值域过滤）
              ↓
Bug2: 候选池非空 → 判定"L2有效" → 跳过L3和几何回退（无合理性检查）
              ↓
Bug3: 全图OCR正确值合并进来，但与污染值共存（无数量级净化）
              ↓
T0枚举：错误解（外框120+边距58...）也满足 sc=1.000
              ↓
最终输出：外框58×120，边距/内孔完全错位
```

## 修复方案汇总

| Bug | 修复模块 | 核心机制 | 测试要点 |
|---|---|---|---|
| 1 | 聚焦OCR候选生成 | 语义值域过滤（外框40-200/内孔30-150/边距2-80） | 边界值测试：1cm、200cm等极端值不进候选池 |
| 2 | L2→L3过渡判断 | 边距max ≤ 外框min×70%，否则回退 | 构造候选池全是大边距值的用例，验证会触发回退 |
| 3 | 全图OCR候选合并 | 数量级一致性净化 + inner/margin互斥 | 正确值与污染值共存时，正确值保留污染值剔除 |
| 4 | 方向标签搜索 | Top-3候选 + 面积安全门 + 失败回退 | 搜索半径内含外框+边距多个值时，取正确的外框值 |

## 预期修复后行为

1. **方向标签路径更可靠**：不再被搜索半径内的边距值误导，有Top-3和面积安全门双重保护
2. **候选池不再被污染**：语义值域过滤在入口处挡掉明显错误的值，保证候选池"血统纯正"
3. **回退路径不被跳过**：即使L2路径返回了值，也会做合理性检查，异常则强制回退L3
4. **T0枚举解空间干净**：数量级净化+互斥检查保证候选池内的值组合不会出现伪自洽错误解
5. **最终输出正确率**：该案例（克罗印花）以及类似的四重叠加场景应输出与草图标注一致的8字段

## 经验教训
1. **防御性设计叠加可能反向**：每层看似"多返回一些值留后路"是防御性设计，层层叠加后反而把错误值带进了核心路径，变成"攻击性设计"
2. **候选池入口必须严格**：值从各路径进入候选池时应严进宽出（入口过滤），而非宽进严出（靠评分函数区分），入口过滤比评分函数更高效且不易出错
3. **回退触发条件不应仅看"是否有值"**：有值≠有效值，应看值的质量（数量级、语义合理性），否则等于用垃圾值放弃了兜底路径
4. **搜索Top-1是危险习惯**：任何搜索场景（OCR位置、几何检测、方向匹配）只取Top-1时，一旦Top-1是噪声就全错；取Top-K再做二次校验可靠性大幅提升
5. **Bug叠加诊断需自顶向下分层**：四重叠加Bug不能从结果反推（结果已是层层污染后），必须从输入开始逐层跟踪每一步的输出与预期对比，才能剥离出每层独立的问题
