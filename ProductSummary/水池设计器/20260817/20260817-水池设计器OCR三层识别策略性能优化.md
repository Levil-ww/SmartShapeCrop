# 2026年08月17日 水池设计器 OCR三层识别策略性能优化

## 概述
用户反馈CAD尺寸草图识别错误，尽管数据标注清晰，并指出识别操作冗余，要求优化逻辑以提高准确性、灵敏度和性能。控制台日志显示多位数识别失败（如36、60、112被拆分为单个字符）、OCR调用冗余（单次识别约350次Tesseract调用）以及回退路径混乱导致错误放大。本篇涵盖09:36、09:51、09:56三次修复。

---

## 问题一：多位数识别失败 & OCR调用冗余（09:36）

### 现象
1. 多位数识别失败：36、60、112等被拆分为单个字符
2. OCR调用冗余：单次识别约350次Tesseract调用
3. 回退路径混乱：错误层层放大

### 根因
1. 原`_find_and_read_numbers`函数未处理多位数合并逻辑
2. 无针对性ROI，全图暴力扫描导致调用次数爆炸
3. 多层回退无清晰边界，上层失败直接污染下层结果

### 修复（sketch_parser.py）

| 修复项 | 说明 |
|---|---|
| 三层递进策略 | L1方向标签快速通道 → L2针对性ROI OCR → L3全图OCR兜底 |
| 新增`_ocr_targeted_region`函数 | 多位数合并 + 精准ROI区域识别 |
| 新增`_build_targeted_rois`函数 | 为8个字段（outer_w/h、inner_w/h、margin_*）生成1-2个候选ROI位置 |
| 重写`_find_and_read_numbers` | 三层递进，OCR调用从约350次降至最多12次 |
| 移除冗余代码 | 删除旧的多层嵌套回退逻辑 |

## 问题二：字符白名单限制 & 多层冗余流程（09:51）

### 现象
字符白名单限制导致数字识别率低；多层回退流程造成性能差和错误难溯源。

### 根因
1. 过度严格的字符白名单过滤了合法数字
2. 多层嵌套回退路径导致错误传递链过长

### 修复（sketch_parser.py）

| 修复项 | 说明 |
|---|---|
| 新增`_robust_ocr_subimage`函数 | 双通道互补 + 多尺度投票提升OCR识别效果 |
| 优化OCR识别流程设计 | 简化`_find_and_read_numbers`函数代码结构 |
| 多位数合并逻辑 | 解决相邻数字token拼接问题 |

---

## 问题三：seen变量类型错误导致崩溃（09:56）

### 现象
草图解析异常：`'set' object does not support item assignment`

### 根因
`_robust_ocr_subimage`函数中`seen`变量从`set()`初始化，却使用字典赋值语法`seen[key] = value`。

### 修复（sketch_parser.py）
将`seen = set()`改为`seen = {}`，统一为字典类型。此错误导致`_find_and_read_numbers`在数值去重/聚合阶段崩溃。

## 经验教训
1. **三层递进策略是性能关键**：先快速通道（方向标签）→ 再精准ROI → 最后全图兜底，保证"快且准"
2. **多位数合并不可省略**：OCR对相邻数字常拆分输出，必须显式合并相邻token
3. **变量类型需严格一致**：Python的set和dict初始化语法相近（`{}` vs `set()`），但赋值操作完全不同，需注意
4. **OCR调用需设上限**：无限制的暴力OCR既慢又容易引入噪声，设定最大调用次数可防性能退化
