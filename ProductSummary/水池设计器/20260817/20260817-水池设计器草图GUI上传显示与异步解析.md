# 2026年08月17日 水池设计器 草图GUI上传显示与异步解析

## 概述
用户要求上传草图后能直接在程序GUI界面显示草图图片，消除鼠标悬浮预览效果，并实现"立即显示、后台解析"的交互体验——避免上传后长时间无反馈的卡顿感。本篇涵盖10:10（同步显示）和11:20（异步解析）两次功能迭代。

---

## 问题一：草图上传后无法直接显示（10:10）

### 现象
上传草图后，图片仅在鼠标悬浮时以tooltip形式预览，无法在主画布区域直接查看。清除草图后画布状态不正确。

### 修复

#### 修改文件：`gui/property_panel.py` + `gui/main.py`

| 模块 | 修改内容 |
|---|---|
| property_panel.py | 新增 `sketch_loaded` 信号，草图加载完成后发射 |
| main.py | 新增 `_on_sketch_loaded` 方法，接收信号后更新主画布 |
| 画布显示 | 通过 `canvas._full_image` 属性设置，居中等比缩放显示 |
| 清除逻辑 | 清除草图时发送 `None`，画布回到设计渲染或清空状态 |

### 显示效果
- 草图上传后：直接显示在左侧主画布居中等比缩放区域
- 清除草图后：画布自动回到设计渲染模式或清空
- 模板匹配流程：不受影响，草图显示与模板匹配解耦

## 问题二：草图显示延迟 & UI阻塞（11:20）

### 现象
草图上传后需要等待5-10秒才能看到图片，期间界面完全冻结无响应。原因是`parse_sketch`在主线程同步调用，阻塞了Qt事件循环。

### 根因
```
原流程（同步阻塞）：
用户点击上传 → 主线程调用 parse_sketch() → OCR识别(耗时) → 解析完成 → 显示图片
                                 ↑
                           期间UI完全冻结
```

### 修复方案：异步显示 + 后台解析

#### 修改文件：`gui/property_panel.py`

| 组件 | 说明 |
|---|---|
| `_SketchParseWorker`类 | 继承`QThread`，后台线程执行草图解析 |
| `_pool_load_sketch_from_path`方法 | 立即显示图片（QPixmap直接加载），无需等待解析 |
| `_pool_auto_parse_sketch`方法 | 异步触发`_SketchParseWorker`，解析在后台进行 |
| `_on_sketch_parsed`回调 | 解析完成后回填GUI数值，标记OCR字段 |
| 旧任务终止 | 启动新解析前终止未完成的旧任务，避免结果覆盖 |
| SpinBox优化 | 使用`blockSignals`减少`valueChanged`重复信号触发 |

```
新流程（异步非阻塞）：
用户点击上传 → 立即加载并显示QPixmap（<100ms） → 启动后台线程解析
                                                    ↓
                                           OCR识别 + 几何计算（后台）
                                                    ↓
                                         解析完成 → 信号回调 → 回填GUI数值
```

### 关键细节
1. **立即显示**：QPixmap文件读取在主线程完成（快），解析移到后台（慢）
2. **线程安全**：Qt信号/槽机制天然跨线程安全，无需手动加锁
3. **任务取消**：用户连续上传时，旧解析任务需`terminate()`，防止旧结果覆盖新上传图片
4. **防信号风暴**：批量回填8个SpinBox值时使用`blockSignals(True)`包裹，避免触发8次重绘

## 验证结果
| 指标 | 修复前 | 修复后 |
|---|---|---|
| 草图显示延迟 | 5-10秒（等解析完） | <100ms（立即显示） |
| UI交互 | 解析期间完全冻结 | 全程可操作（按钮、切换面板等） |
| 连续上传 | 可能出现结果错乱 | 旧任务终止，结果正确 |
| 匹配模板流程 | 正常 | 不受影响 |

## 经验教训
1. **显示与解析解耦**：用户最关心的是"我传的图对不对"，先显示图片再解析，体验提升显著
2. **耗时操作必须异步**：任何超过200ms的操作都不应在Qt主线程执行，否则必然卡顿
3. **后台任务需可取消**：用户连续上传/操作是常态，必须提供终止机制防止脏数据
4. **信号优化不可忽视**：批量更新多个UI控件时，临时阻断信号可大幅减少不必要的重绘和回调
5. **QThread优于线程池**：Qt生态内用QThread+信号槽，比Python标准库`threading`更安全可靠
