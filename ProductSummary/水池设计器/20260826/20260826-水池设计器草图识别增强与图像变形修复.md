# 2026年08月26日 水池设计器 草图识别增强与图像变形修复

## 概述
8.26当日针对水池设计器进行了7轮修复，涵盖：草图识别颜色与方向增强（Phase1）、草图识别鲁棒性（Phase2各向异性距离场+几何自洽穷举）、图像变形修复（stretch→cover）、过度裁剪修复（三重校验+tile平铺）、预览图优化（异步分级渲染+8.21版参考）、模板匹配与定位修复、画布尺寸识别与边距噪声过滤。涉及21条子问题，核心修改集中在`core/pool_designer/sketch_parser.py`、`core/image_ops.py`和`gui/canvas_widget.py`。

## 问题一：草图识别颜色与方向增强 Phase1（08:55~09:51）

### 现象
草图标注使用彩色（红色）文字，直接灰度化后识别率低；小数字（如"6"）识别困难；方向字与数值任意顺序排列时无法匹配；"下8"被Tesseract误识别为"下0"。

### 修复（sketch_parser.py）
| 修复项 | 说明 |
|---|---|
| Phase1颜色增强 | LAB a*通道提取红色 + HSV红色掩码 + 灰度融合，无红字时0ms额外开销 |
| 小数字专项识别 | 6倍缩放 + PSM 10/7模式，仅在标准扫描后字段缺失时触发 |
| 双向正则匹配 | 处理方向/数值任意顺序的单token和双token场景，单次1.8μs |
| "下8→下0"修复 | 几何自洽校验作安全网，形状相似导致Tesseract误识别时纠正 |

### 验证
性能<20%增加，边距误差为0 ✅

## 问题三：水池设计器图像变形修复（10:55~11:10）

### 现象
图库素材图在尺寸修改后出现变形，优化前未出现此问题。

### 根因
`core/image_ops.py`中水池模式frame material适配使用`stretch`模式，强制拉伸竖版57.5×120cm图片适配横版122×51cm画布，导致宽高比改变。PIL默认不处理EXIF方向也存在潜在变形。

### 修复（image_ops.py）
| 修复项 | 说明 |
|---|---|
| stretch→cover模式 | 保持宽高比，等比缩放后裁剪超出部分 |
| 等比contain缩放 | 水池预览使用contain保持比例 |
| EXIF方向处理 | 确保图片方向正确 |

### 验证
37项测试通过 ✅

## 问题四：水池设计器过度裁剪修复（11:25~11:52）

### 现象
修复变形问题后，图像完整性丢失，过度裁剪导致花纹缺失。正确样式应如图3所示四边花纹完整。

### 根因
`adapt_pool_material`函数中旋转逻辑优先信任文件名方向而非像素方向，导致花纹素材规格方向与画布方向相反，产生极端裁剪。

### 修复（image_ops.py）
| 修复项 | 说明 |
|---|---|
| tile平铺填满画布 | auto_rotate参数方向对齐，扩充`_looks_like_tile`识别花纹素材 |
| 三重校验保守策略 | 像素vs画布/文件名vs画布/比例一致性，默认信任像素方向 |
| 四边花纹完整 | 确保顶/左/右/底四边花纹均完整保留 |

### 验证
37项测试通过 ✅

## 经验教训
1. **颜色增强需条件触发**：LAB a*通道+HSV红色掩码仅在检测到红色标注时触发，无红字时0ms额外开销，避免性能影响
2. **各向异性距离场解决非共线关联**：方向字与数值不在同一直线上时，各向异性距离场能有效关联
3. **几何自洽穷举是安全网**：当OCR识别不确定时，几何自洽穷举校验能纠正错误分配
4. **默认信任像素方向**：文件名方向可能与实际像素方向不一致，应以像素方向为准
5. **三重校验需适度**：过严的三重校验会导致素材被错误拒绝旋转，需简化为关键校验
6. **边距噪声需双保险**：合理性检查+方向标签预过滤双保险策略，防止花纹文字误识别为数字
