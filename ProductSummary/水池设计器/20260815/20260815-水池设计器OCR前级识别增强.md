# 2026年08月15日 水池设计器 OCR 前级识别增强

## 概述
修复方向矫正与自洽保护后，控制台仍无输出且草图识别数据未变化（内孔 69.56×42.44cm，边距归零）。排查发现两个根因：1）日志级别默认 WARNING 导致 DEBUG 修复日志被过滤；2）**OCR 前级识别不足**——全图 OCR 仅识别到 2 个数字（42.4、69.6），缺少 76/44.5/14.6 等关键值，导致后续分配算法无米下锅。本篇实施 OCR 前级三重增强。

---

## 根因分析

### 日志过滤问题
`log_setup.py` 默认日志级别为 WARNING，导致修复日志被过滤。调整后新日志显示 OCR 实际仅识别到 2 个数字，问题根源在 OCR 前级而非分配算法。

### 运行入口问题
用户可能通过 exe 而非源码运行，导致修改不生效。要求用户用源码运行：
```powershell
D:\SmartShapeCrop\.venv\Scripts\python.exe D:\SmartShapeCrop\main.py
```

## 三重增强方案（sketch_parser.py）

### 增强 1：全图 OCR 多策略组合
针对小字单字符（如 "6"）识别困难，采用多缩放 + 多预处理 + 多 PSM 模式组合：

| 维度 | 配置 |
|---|---|
| 缩放倍率 | 4× / 5× |
| 预处理变体（6 种） | 原始 / 自适应二值化 / CLAHE 对比增强 / 反色 / 反色二值化 / 反色 CLAHE |
| PSM 模式（7 种） | 11 / 12 / 6 / 4 / 7 / 8 / 13 |
| 字符白名单 | 带数字白名单 + 不带白名单双配置 |

置信度阈值降低至 **-1**，保留高倍率放大后低置信度但正确的小字识别结果。

### 增强 2：子图 OCR + 3×3 分块兜底
1. **子图截取**：截取草图外框区域（`outer_rect`）子图单独重跑 OCR
2. **3×3 分块兜底**：将子图按 3×3 网格分块，每块独立 OCR，合并结果至主 OCR 池
3. **去重合并**：所有 OCR 命中按 bbox 去重后汇入候选池

### 增强 3：自动保存诊断截图
自动保存 6 张关键区域截图至 `logs/` 目录，便于排查：
| 截图 | 区域 |
|---|---|
| `dbg_outer_rect.png` | 外框区域 |
| `dbg_inner_rect.png` | 内框区域 |
| `dbg_gap_top.png` | 上边距间隙 |
| `dbg_gap_bottom.png` | 下边距间隙 |
| `dbg_gap_left.png` | 左边距间隙 |
| `dbg_gap_right.png` | 右边距间隙 |

## 经验教训
1. **OCR 前级不足会导致分配算法失效**：再精巧的分配算法，没有足够的候选值也无法工作。需先保证前级识别完整性
2. **小字单字符需多策略组合**：单一 PSM 模式 + 单一预处理对小字（如 "6"）识别率极低，必须多缩放×多预处理×多 PSM 组合
3. **诊断截图自动化**：关键区域自动截图能大幅缩短排查时间，避免每次手动裁剪
4. **日志级别陷阱**：默认 WARNING 会吞掉 DEBUG 修复日志，排查时需先确认日志级别
5. **exe 与源码运行差异**：exe 打包后修改不生效，排查时需确认实际运行入口
