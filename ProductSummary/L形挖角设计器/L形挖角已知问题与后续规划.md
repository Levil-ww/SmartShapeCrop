## 第一部分：已知软肋（3 条，交付可接受，P3 低优先级跟踪）

### 软肋 SR-1：OCR 小尺寸文字 D/C 归属错位（cut_h 误差 1–3%）

#### 现象
合成图测试用例（字体 18px，极限小尺寸场景）中，标注 `D 2`（表示挖角 cut_h=2cm）的 OCR 检测 bbox 中心**越过凹角线**（D/C 分界线），被程序误归为"外框尺寸 D"而非"挖角尺寸 C"→ cut_h 计算从 2.00 变成 1.94（差异 0.06cm = 3%）。

#### 根因
Tesseract 检测小尺寸字符时，bbox 框会放大 1-2px（抗锯齿扫描带），导致 18px 小字的 bbox 中心跨越了凹角几何分界线几像素 → 归属方向错误。

#### 缓解情况（已有兜底，可接受）
- **像素比例兜底**：阶段 2 的 Step 7 几何校验中发现 `cut_h 计算值 > outer_h × 50%`（不可能为真挖角尺寸，因为挖半面以上应判定为矩形）时，触发归属错位兜底——自动用外框几何差（outer_h - 保留区高度 = cut_h）替代 OCR 值。阶段 3 审计时的合成 4 向验证中，cut_h 误差最大 3%，最小 1.3%。
- 用户真实草图分辨率更高：用户 A4/300DPI 扫描草图通常字体 ≥ 36px，bbox 放大 2px 不会越过凹角线（凹角宽度至少 50px+），此现象大幅缓解。
- 确认对话框留有手动修正入口：用户即使看到 cut_h 有 1.94 而非 2.00，可在 _LShapeConfirmDialog 直接改。

#### 修复建议（P3，不紧急）
在 OCR 归属判定中增加「bbox 边缘距离」加权：当 bbox 中心距离凹角线 < 2px 时，不信任该方向归属，降级使用几何值。避免极限小字体场景下 1-2px 的越界误判。

### 软肋 SR-2：PyQt5 DLL 损坏导致 L 形集成测试失败（非代码问题，但用户环境需警惕）

#### 现象
`.venv` 安装了非官方 `python-qt5==0.1.10` 黑包时，PyQt5.QtCore 导入 0xc0000139 崩溃 → test_pool_lshape_flow.py 集成测试全失败。

#### 根因
见 9.2 环境治理文档：非官方包 python-qt5 向 PyQt5 目录覆盖写入自己的 Qt DLL，破坏官方绑定与 DLL 入口点一致性，导致 5.15.2 编译的 .pyd 在 5.15.11 DLL 中找不到入口点。

#### 缓解情况（9.2 已在主力开发环境解决，交付侧依赖用户环境）
- 主力开发机 venv：9.2 重建 F 盘 venv + 白名单 requirements_clean.txt 排除 python-qt5 → 环境 100% 稳定
- exe 交付：PyInstaller 打包时 DLL 从 venv 干净复制，不受用户本地 Python 环境影响 → V2.1.2.exe 中 Qt DLL 100% 正确（无需用户装 python-qt5）
- 用户源码运行：三要件永久备份在 `.workbuddy/`，用户按 requirements_clean.txt 装依赖即可规避

#### 预防措施（已固化在项目中）
- `requirements_clean.txt` 白名单：**明确没有 python-qt5 条目**，任何 `pip install -r requirements_clean.txt` 不会误装
- `packageV2.1.2.py` 构建：从 venv 拷贝 DLL，exe 交付零本地依赖
- `.workbuddy/memory/2026-09-02.md` 永久记录：python-qt5 = 黑包，禁止进入环境白名单（团队共享记忆）

### 软肋 SR-3：L 形裁剪不支持多 L 形挖角 & 多方向复合

#### 现象
用户案例：大型水池（1200×500cm）需要**两个对角 L 形挖角**（左上 tr + 右下 br 各挖一个角），或「L 形 + 中间圆洞」复合挖角。当前 LShapeDesign 只支持一个 corner 方向 + 一个 cut_w/h，无法表达多挖角复合。

#### 根因
阶段 1 的两矩形减法设计只针对「单 L 形缺一角」几何，设计时未考虑多 L 形布尔运算。LShapeDesign 数据结构为单 corner + 单 cut。

#### 缓解情况（用户可走水池多洞 + L 形拆分导出）
- 阶段 2 支持水池多洞（rect_multi_hole）：用户可分别导出 L 形 A 与 L 形 B 两次，PS 合成（或水池多洞作为近似替代，效果稍差但可接受）
- phase4 独立 Tab：至少单 L 形操作效率提升了

#### 修复建议（见后续规划 F-1：多 L 形挖角嵌套，P2 中优先级）

## 第二部分：后续规划（4 条，按 ROI 优先级 P0–P3 排序）

### 规划 F-1（P2 中优先，3–4 周工作量）：多 L 形挖角 + 中间洞复合支持

#### 需求来源
阶段 3 用户案例 1200×500cm 双对角 L 形（tl+br 两向各挖）+ 阶段 2 用户反馈「L 形中间还要留个 50×50cm 圆洞放水管」。约 5% 超高阶案例需复合。

#### 设计方向
- LShapeDesign 扩展为 `List[SingleLShape]`：支持 1–4 个 corner 方向各一个 cut（每个 corner 最多挖一个）
- 布尔运算支持：最终 L 形 mask = OuterRect − Σ（每个 corner 的 CutRect）− 中间 Hole/Ellipse 集合
- UI：独立面板增加「挖角列表 QListWidget」，支持添加/删除/编辑挖角项（当前单 corner 映射为列表长度为 1）
- 兼容性：单 L 形自动映射为列表长度 = 1，老数据零迁移

#### 预期收益
覆盖 5% 复合案例（当前需 PS 合成），消除用户"程序做不了复合 L 形"的抱怨。

### 规划 F-2（P1 高优先，1–2 周工作量）：L 形草图 corner 自动检测 + 外框尺寸完整检测（不依赖 OCR/文件名）

#### 需求来源
阶段 3 降级路径目前需要用户"选目标文件带尺寸名"才能拿到外框尺寸（走 name_parser）。如果用户只有一张"裸 L 形草图 jpg"无文件名信息且机器没装 Tesseract，只能手动填尺寸（不友好）。

#### 设计方向（纯计算机视觉，不依赖 OCR）
- **corner 方向检测**：阶段 3 已验证四象限白占比 100% 正确，可直接作为 corner 自动检测（无 OCR 也能跑）
- **外框尺寸完整检测（核心难点）**：不依赖 OCR 数字，通过「外框矩形长宽比 + 板材常用尺寸先验库」推测（2440×1220mm 标准板 / 450×33 水池板 / 200×100 常用比例等）+ L 形四条边像素长度比例对齐
- **cut 尺寸检测**：用凹角白矩形拟合 + corner 方向确认，无需 OCR 字母 C/D

#### 预期收益
用户只有一张裸 L 形草图也能一键识别（Corner/Cut 100% 自动，外框尺寸靠先验库推荐后再微调），彻底去掉「OCR 引擎/文件名尺寸」两个前置依赖。用户操作步骤从"选图+确认/改数值"→ "点识别 → corner/cut 自动对，只需确认外框"。

---

### 规划 F-3（P2 中优先，1 周工作量）：L 形素材方向匹配惩罚机制

#### 需求来源
阶段 4 独立面板的素材匹配目前复用 template_matcher 的方向签名（横/竖二元），但 L 形有 4 个 corner 方向，即使素材是横版，corner=tl 和 corner=br 的花纹也需要**镜像/翻转**才能对齐素材图方向。当前没有 corner-aware 的方向匹配，偶尔出现"素材方向正确但 L 保留区花纹恰好反了"的现象。

#### 设计方向
- 在 template_matcher 的 orientation_signature（二元：±1）基础上增加 L 形专属 corner_signature（四元：tl/tr/bl/br）
- corner-aware 方向变换打分：tl-corner 的素材查询 = 原图 0° 分 + 原图镜像分 + 原图翻转分 × 对应 corner 加权（对应 corner 方向变换后分值最高的那个变换为最终匹配）
- 确认对话框增加「自动变换」复选框：勾选后自动对素材图执行 0°/镜像/翻转 × 4 corner 的 8 种组合，选中匹配分最高的一种（用户也可手动切换查看效果）

### 规划 F-4（P3 低优先，2+ 周工作量）：L 形裁剪结果导出 DXF 矢量格式（对接切割机床）

#### 需求来源
用户反馈：目前只能导出 JPG 栅格图，数控切割机需要 DXF 矢量格式（矢量闭合轮廓坐标）。用户目前要把 JPG 导入 CAD 手工描 L 形轮廓（耗时 10–30 分钟/张）。

#### 设计方向
- 矢量 DXF 导出：从 LShapeDesign 直接构建闭合多段线（Polyline），不需要经过像素级渲染路径（不依赖 render_design）
- L 形轮廓几何表达为 6 顶点（两矩形减法得到的六角形）多段线：
  ```
  corner=tl 时的外轮廓（6 点，顺时针）：
    (cut_w, 0) → (outer_w, 0) → (outer_w, outer_h) → (0, outer_h) → (0, cut_h) → (cut_w, cut_h) → 回 (cut_w, 0)
  ```
  其他三方向为坐标镜像/翻转，无算法复杂度（直接几何变换）。
- 圆角半径支持：若 corner_radius_cm > 0，把 4 个非凹角的 90° 折角替换为对应的圆弧段（DXF ARC 指令）
- 可选：增加 DXF 导出对话框，设置图层名 / 颜色索引 / 板材厚度备注（对接切割车间工艺要求）

#### 预期收益
消除用户从 JPG→CAD 手工描图的重复性劳动（10–30 分钟/张 → 1 秒矢量导出），打通「设计 → 加工」最后一公里。属于 L 形功能从"设计辅助"升级到"生产辅助"的关键一跳。
