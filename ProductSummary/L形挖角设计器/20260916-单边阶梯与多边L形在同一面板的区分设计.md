# 单边阶梯 L 形 vs 多边 L 形 — 同一面板内如何区分

> 文档日期：**2026.09.16** ｜ 项目版本 **V2.2.2** ｜ 文档版本 **V1.0**
> 承接：`20260916-单边阶梯L形挖角可行性分析与实现建议.md`（V2.0）
> 回答：既然都集成在 L 形面板，**两种形状靠什么区分？**

---

## 〇、一句话答案

> **不需要让用户选择「这是多边 L 形还是阶梯」—— 形状是参数的必然结果，不是用户的选项。**
>
> 判据只有一条：**按锚定角（anchor）分组，看某组是否有 ≥2 个成员。**
>
> - 每组各 1 个 → 多边 L 形（各自挖一个角）
> - 某组 ≥2 个 → 该角是阶梯
> - 两者共存 → 混合形状（自动支持，无需额外设计）

---

## 一、为什么「不需要用户选」

### 1.1 用户的输入本来就不含「形状名称」

用户拿到一张草图，看到的是**尺寸标注**，不是「形状类型」。他要表达的是：

```
右上角：先退 10cm、下沉 6.5cm，再退 8.5cm、下沉 3.5cm
```

而不是「我要一个单边阶梯」。**形状是这些尺寸的几何后果。**

> 如果让用户先选「多边 L 形 / 阶梯形」，反而制造了一个**新问题**：
> 用户选错了怎么办？选了阶梯但只填一级怎么办？
> —— 这类「需要用户先分类」的设计，是把系统的认知负担转嫁给用户。

### 1.2 两种形状在数据上是同一件事

现有 UI 已经是「4 行挖角，每行 = 角位 + 宽 + 高」：

```python
# gui/lshape_panel.py:851
def get_cuts_cm(self) -> list[dict]:
    cuts = []
    for enabled, combo, width, height in self._corner_rows:
        if not enabled.isChecked() or width.value() <= 0 or height.value() <= 0:
            continue
        cuts.append({
            'corner': combo.currentData(),   # ← 角位
            'cut_w_cm': width.value(),        # ← 宽
            'cut_h_cm': height.value(),       # ← 高
        })
    return cuts[:4]
```

**多边 L 形** = 填两行，角位选 `tr` 和 `bl`
**单边阶梯** = 填两行，角位都选 `tr`

区别只在**角位是否重复**。用户填完参数，形状自然就确定了。

## 二、判据：按 anchor 分组

### 2.1 三种情形

| 情形 | anchor 分组 | 语义 |
|---|---|---|
| 每组各 1 个 | `tr×1, bl×1` | **多边 L 形** —— 两个角各挖一个 |
| 某组 ≥2 个 | `tr×2` | **单边阶梯** —— 右上角分两级挖 |
| 混合 | `tr×2, bl×1` | **阶梯 + 多角** —— 自动支持 |

### 2.2 实测验证

```
单角L形            anchor 分组: tr×1
多边L形            anchor 分组: tr×1  bl×1
本例阶梯           anchor 分组: tr×2(阶梯)
混合(阶梯+多角)     anchor 分组: tr×2(阶梯)  bl×1
```

**判据在 `CutRect` 模型下天然成立，无需任何额外字段。**

### 2.3 代码落点

```python
def group_by_anchor(cut_rects: list[CutRect]) -> dict[str, list[CutRect]]:
    """按锚定角分组 —— 这一步同时完成「形状识别」与「约束校验」。"""
    groups: dict[str, list[CutRect]] = {}
    for r in cut_rects:
        groups.setdefault(r.anchor, []).append(r)
    return groups

# 形状类型无需存储，按需推导：
#   all(len(g) == 1 for g in groups.values())  → 多边 L 形
#   any(len(g) >= 2 for g in groups.values())  → 含阶梯
```

**注意**：这个 `group_by_anchor` 不只用于「区分形状」，它同时是**几何约束校验的入口**（见 §4）。**一个分组函数服务两个目的**，这是设计上的收敛点。

## 三、UI 上怎么自然呈现（不需要「模式切换」）

### 3.1 关键改动：角位不再唯一，改为「父行 + 子行」

**现状**（4 个平级行，角位互不关联）：

```
☑ 挖角1   [右上角▾]  宽 [10.0]  高 [6.5]
☐ 挖角2   [左下角▾]  宽 [ 0.0]  高 [0.0]
☐ 挖角3   [左上角▾]  宽 [ 0.0]  高 [0.0]
☐ 挖角4   [右下角▾]  宽 [ 0.0]  高 [0.0]
```

**改为**（父行选角位，子行只能「继承父角位」或「换一个新角」）：

```
☑ 右上角   宽 [10.0]  高 [ 6.5]
   └ ☑ 第2级  宽 [ 8.5]  高 [ 3.5]    [+ 追加一级]
☐ 左下角   宽 [ 0.0]  高 [ 0.0]
   └ ☐ 第2级  宽 [ 0.0]  高 [ 0.0]
```

**用户的操作序列**：
1. 想挖一个角 → 勾第 1 行，填宽高（= 单角 L 形）
2. 想挖两个不同的角 → 勾两行的角位（= 多边 L 形）
3. 想在同一角挖阶梯 → 在该行下点「+ 追加一级」（= 阶梯）

> **用户从头到尾没被问过「你要哪种形状」** —— 他只是照着草图填尺寸。
> 形状是填法的自然结果。

### 3.2 识别回填时的呈现

识别层产出后，UI 按 anchor 分组自动展开子行：

```
识别结果：右上角 2 级
  ☑ 右上角   宽 [10.0]  高 [ 6.5]     ← OCR: 10 / 6.5
     └ ☑ 第2级  宽 [ 8.5]  高 [ 3.5]  ← OCR: 8.5 / 3.5
```

**用户一眼就能看出「这是阶梯」** —— 因为界面上就是两行缩进。不需要额外的「形状：阶梯形」标签。

### 3.3 是否需要一个「形状」只读标签？

**建议加一个，但只读、不参与设计**，纯作**确认辅助**（对齐 G3 闸口「人工核对」的设计意图）：

```
形状预览：右上角 2 级阶梯 · 外框 93.5 × 55.0 cm
```

放在「边余量」提示旁边。它的作用是让用户在点「生成预览」前，**用一句话确认自己填的形状对不对** —— 但**不影响数据，也不要求用户选择**。

## 四、这个判据的额外收益：几何约束自然分层

`group_by_anchor` 同时解决了「两种形状的约束规则不同」的问题 —— 这是原方案里一块没讲透的地方。

### 4.1 现状约束对阶梯是错的

`core/geometry.py:308-324` 现有约束：**同一条边上所有 cut 的边尺寸之和 < 边长**

```python
edge_limits = (
    ('上边', ('tl', 'tr'), 'cut_w_cm', inner_w_cm),   # ← 同边求和
    ...
)
edge_sum_cm = sum(float(cut_by_corner[corner][size_key])
                  for corner in corners if corner in cut_by_corner)
if edge_sum_cm > edge_length_cm - edge_clearance_cm:
    raise ValueError(...)
```

**对多边 L 形**：`tr(28) + bl(30)` 是「两个角各占一段边」，求和合理 ✅
**对阶梯**：`tr(10) + tr(8.5)` 是「同一个角逐级内收」，**求和是语义错误** ❌

（实测：用 `tr+br` 拼同边阶梯被拦 —— `尺寸和 28cm 必须小于外边长度 24cm`）

### 4.2 分层后的规则

```python
groups = group_by_anchor(cut_rects)

for anchor, rects in groups.items():
    if len(rects) == 1:
        # —— 多边 L 形路径：沿用现有规则（该 cut 不越界）——
        assert_rect_within_outer(rects[0])
    else:
        # —— 阶梯路径：规则完全不同 ——
        #   1) 各级沿边错位必须单调（逐级内收或逐级外扩）
        #   2) 各级不得互相重叠
        #   3) 最外层级不得越出外框
        assert_monotonic_offsets(rects, anchor)
        assert_no_overlap(rects)
        assert_within_outer(max_extent(rects))

# —— 跨角仍走「同边求和」（这条对多边 L 形有效，对阶梯已在上方排除）——
for edge, corners, key, length in edge_limits:
    # 每角只取「最外层级」参与跨角求和
    total = sum(outermost(groups[c])[key] for c in corners if c in groups)
    assert total < length - clearance
```

**关键点**：跨角求和时，每个角只取**最外层级**参与 —— 因为阶梯的总占用就是最外层级的尺寸。

### 4.3 一个分组函数，服务三件事

| 用途 | 说明 |
|---|---|
| ① **形状区分** | 某组 ≥2 → 阶梯 |
| ② **约束分层** | 单级走旧规则，多级走阶梯规则 |
| ③ **渲染出口** | 按组遍历，每组展开成 N 个 cut |

> 这就是为什么「不需要单独的『形状类型』字段」—— **形状是分组的副产品，不是独立状态。** 不需要存储，不需要同步，也就不会有「状态与实际不一致」的 bug。

## 五、与「多边 L 形」的对照总结

### 5.1 数据形态对照

| | 多边 L 形 | 单边阶梯 |
|---|---|---|
| **anchor 分布** | 各不相同（tr, bl） | 全部相同（tr, tr） |
| **offset** | 全为 0 | 逐级递增（0 → 10） |
| **每级都贴两条外廓边？** | 是 | 仅最外层贴，内层贴一条 |
| **现有支持** | ✅ 已支持 | ❌ 未支持 |
| **识别层能否检测** | ✅ 能 | ✅ **能**（实测 `n_detected=2`） |
| **缺什么** | —— | **`offset` 字段 + 分组约束** |

### 5.2 用户视角对照

| 场景 | 用户怎么填 |
|---|---|
| 右上挖一个角 | 勾 1 行，选「右上角」，填宽高 |
| 右上 + 左下各挖一个角 | 勾 2 行，分别选「右上角」「左下角」 |
| 右上挖两级台阶 | 勾 1 行选「右上角」，点「+ 追加一级」再填一级 |
| 右上台阶 + 左下挖角 | 上面两种填法组合 |

**全程没有任何「形状模式」选择。**

## 六、需要你确认的问题

### 6.1 关于「级与级的关系」是否必须单调

本例是**逐级内收**（10/6.5 → 8.5/3.5，尺寸递减）。

问题：**是否需要支持「逐级外扩」？** 即第二级比第一级更大（如 5×3 → 12×8）。

- **若只需内收** → 约束和 UI 都更简单，`offset` 可自动推导（= 上级尺寸），用户少填一个数
- **若需外扩** → `offset` 必须让用户显式填写，多 2 个输入框

**这直接决定子行的输入框数量（2 个 vs 4 个）**，是 UI 设计前必须定的。

### 6.2 关于「最多几级」

本例 2 级。实际业务最多几级？

- 2 级 → 子行只加 1 层，UI 最简单
- 3–4 级 → 需要支持继续追加
- 不限 → 需要滚动区域

### 6.3 关于「子行的角位是否可改」

子行的角位**建议锁定继承父行**（不允许改，避免出现「同一子行既是父角又是别的角」的歧义）。

是否同意这个约定？若用户想在第 2 级处「转角到另一条边」，那已是另一种形状（需要新设计），建议暂不支持。

## 七、结论

### 7.1 回答「怎么区分」

> **不区分 —— 因为不需要区分。**
>
> 「多边 L 形」与「单边阶梯」是**同一套参数（锚定角 + 沿边错位 + 宽高）的两种取值形态**。
> 判据是**按锚定角分组后，看某组是否有 ≥2 个成员**，这是一个**纯推导**，不需要用户选择，
> 也不需要新增「形状类型」字段。

### 7.2 三条设计原则

1. **不要让用户选形状类型** —— 用户脑子里只有尺寸，没有形状分类。让他填尺寸，形状自己浮出来。

2. **形状是推导结果，不是存储状态** —— 用 `group_by_anchor()` 按需推导。存一个「shape_type」字段会引入「状态与实际不一致」的 bug 面。（本项目「静默失效」类 bug 的一大来源就是两个地方各自维护同一语义。）

3. **一个分组函数服务三件事** —— 形状区分、约束分层、渲染遍历。收敛在一个函数里，就不容易改了一处漏一处。

### 7.3 UI 一句话

> 现有 4 个平级挖角行 → 改为**「父行（选角位）+ 可折叠子行（同角追加级）」**。
> 用户靠「填几行、点几次追加」表达形状，界面靠「有没有缩进」呈现形状。
