## 二、可行性分析：V1.0 → V1.1 的估算修正

### 2.1 需求还原

草图尺寸链：外框 143×62.8cm，右上挖角 28×8cm，左下挖角 30×12.8cm。
几何本质是 **`矩形 − cut₁ − cut₂ − …` 的布尔差集** —— mask 差集天生支持复合挖角，这一层不复杂。

### 2.2 V1.0 的核心估算错误

**V1.0 把「草图识别多角化」当成了需要从零发明算法的活**，列为「硬骨头 ②」估 7–10 天。

实测复检推翻了这一判断：**多挖角的几何数据现有代码早已算出** —— 凸包差异法算出 2 个连通域、`approxPolyDP` 的 tier2 里躺着 7 个双凹角候选，只是被三个「单角收敛点」掐成了 1 个。

> **这不是算法问题，是优先级问题。**

### 2.3 V1.1 修订对照

| 项目 | V1.0 | V1.1 | 依据 |
|---|---|---|---|
| 识别层工作量 | 7–10 天（硬骨头 ②） | **3–5 天** | §5 实测复检 |
| 硬骨头数量 | 2 层 | **1 层**（仅边框补全） | §5 实测复检 |
| 预计总工期 | 3–4 周 | **2.5–3 周** | §4 + §5 |
| 识别层章节 | 无（仅文字描述） | §5 三条通道逐条实测 | 新增 |
| 闸口设计 | 无 | §6 三级闸口 G1/G2/G3 | 新增 |
| 手动修正通路 | 无 | §7 架构现状 + 缺口 + 修正矩阵 | 新增 |
| 第一期范围 | 完全跳过识别，全手动填数 | 解除三个单角收敛点，识别给出**角落 + 尺寸建议值** | §9 策略修正 |

### 2.4 三条设计主线

| 主线 | 要点 | 章节 |
|---|---|---|
| **解除收敛** | 识别层不需新算法，只需把 `argmax` / `or 短路` / `max` 三处收敛换成按 bbox 四角分桶 | §5 |
| **加装闸口** | 现有失效模式是「静默丢掉一个角，却报告识别成功」，需 G1/G2/G3 状态反馈 | §6 |
| **兜底修正** | 手动修正通路 **2026-09-03 就已铺好**（识别只写建议值，用户可就地编辑），只需扩为 N 行 | §7 |

## 四、识别层三个收敛点解除（`7524f30`）

### 4.1 实测复检证据

合成草图 143×62.8cm，4px/cm，tr cut 28×8，bl cut 30×12.8：

| 通道 | 实测结果 | 被截断原因 |
|---|---|---|
| 凸包差异法 | `gap` 连通域**恰好 2 个**：27.5×8.0 触碰【右、上】、29.5×12.8 触碰【左、下】 | `best_label = 1 + argmax(areas)` 只取最大 |
| approxPolyDP tier2 | 躺着 **7 个** `n_verts=8 / 凹角数=2` 的候选，凹角 (115.2, 8.0) 与 (29.8, 50.0)，**误差 <0.2cm** | `_tier1 or _tier2` 短路 |
| 第三条通道 | 同样算出多角数据 | `max(score)` 只取一个 |

**修复前输出**：`corner='bl'`, `cut=29.5×12.75cm`, `n_verts=6`
—— **静默丢掉右上 28×8，且报 success**。

### 4.2 三处收敛点定位与改造

| 位置 | 收敛形态 | 改造方向 |
|---|---|---|
| `_detect_by_convex_hull:343` | `1 + argmax(areas)` | 保留全部连通域，按 bbox 四角分桶 |
| `_collect_approx_candidates:705` | `_tier1 or _tier2 or _tier3` | 合并候选，不再短路 |
| `:587` | `max(score)` | 按角位分组取最优 |

### 4.3 新增判据：「触碰 ≥ 2 条 bbox 边」

区分**真凹角**与**文字噪点**的**拓扑性质**判据，替代单纯面积阈值 —— 凹角必然同时触碰两条外框边，文字噪点通常只触碰一条或不触碰。

### 4.4 工程量

- `services/sketch_parser/lshape_sketch_parser.py`：`+410 / −175`
- 新增 `tests/core/test_multi_corner_detection.py`：166 行

## 五、G1 结构一致性闸口（`300c3dc` + `3bfabc3`）

### 5.1 要解决的失效模式

**静默丢掉一个角，却报告识别成功** —— 用户看到「识别成功」却拿到不完整结果，是比崩溃更危险的问题。

### 5.2 实现

审计字段**先于** OCR/尺寸求解写入，确保部分结果也能说明检测到的角数：

```python
# G1 审计字段先于 OCR/尺寸求解写入，确保部分结果也能说明检测到的角数。
n_detected = geo.get('n_detected', 1)
result.notches_detected = n_detected
result.notches_consumed = 0

_progress(40, "OCR 识别尺寸数值...")
...

# —— G1 闸口：检测到的凹角数 vs 实际消费数 ——
n_consumed = 1  # 第一期：下游管线仍为单角，只消费 1 个
result.notches_consumed = n_consumed
g1_blocked = n_detected != n_consumed
result.success = not g1_blocked
msg = (
    f"L 形识别{'成功' if not g1_blocked else '部分完成'}（corner={geo['corner']}, "
    f"外框 {dims['outer_w_cm']:.1f}×{dims['outer_h_cm']:.1f}cm, "
    f"挖角 {dims['cut_w_cm']:.1f}×{dims['cut_h_cm']:.1f}cm, 自洽={sc:.2f}）"
)
if g1_blocked:
    all_corners = geo.get('all_corners', [])
    unused = [c['corner'] for c in all_corners[n_consumed:]]
    msg += (
        f" ⚠️ G1 闸口：检测到 {n_detected} 个凹角，当前仅应用 {n_consumed} 个"
        f"（{geo['corner']}），其余角位 {unused} 需手动补充"
    )
```

`debug` 同步新增 `n_consumed` 与 `g1_blocked` 两个字段，供 UI 与测试断言。

### 5.3 测试语义反转（关键）

`tests/core/test_multi_corner_detection.py` 的断言由 `assert res.success` **反转为** `assert not res.success`：

```python
-            assert res.success, f"应成功（含 G1 告警）: {res.message}"
+            assert not res.success, f"G1 应阻止不完整结果报告成功: {res.message}"
             assert res.notches_detected >= 2
             assert res.notches_consumed == 1
             assert res.notches_detected > res.notches_consumed, "G1 闸口应触发"
+            assert res.debug.get('g1_blocked') is True
             assert '⚠️' in res.message
+            assert 'G1 闸口' in res.message
```

**这是「闸口真正生效」的证明** —— 从「有告警但报成功」变成「不完整就不报成功」。

同步新增单角向后兼容断言：`assert res.notches_consumed == 1`（单角不应有 G1 告警）。

### 5.4 三级闸口设计（V1.1 §6）

| 闸口 | 判据 | 落点 |
|---|---|---|
| **G1 结构一致性** | `notches_detected != notches_consumed` 即降级 success | 已实施 |

## 六、切边补边越界修复（`87b3634` + `097e00c`）

### 6.1 现象

用户报告：**垂直切边或水平切边的某一层在切角处画超了，进入了不该画的区域**。

### 6.2 像素级取证

| 量 | 值 | 说明 |
|---|---|---|
| 缺口左边界 | x = 417 | 垂直切边所在列（缺口在右） |
| 缺口下边界 | y = 79 | 水平切边所在行 |
| 产品内容上界 | y = 62 | 越界区就压在它上方 |
| 被覆盖列 | x = 402 ~ 416 | 15 列被纯色整段覆盖，边界极锐利（x=400 正常） |
| 越界竖条厚度 | ≈ 15 ~ 16 px | 与缺口下方水平切边厚度**完全吻合** → 同源同层 |

**已排除的干扰项**：

- 缺口内部越界为 **0 像素**（60×60 合成画布受控实验，两条路径实测）
- 内凹角的 `max(dx, dy)` 分层经形态学验算**等价于方形结构元腐蚀**，正是矩形边框应有的直角结果，**不是 bug**

### 6.3 根因：三条件叠加，缺一不可

| # | 条件 | 位置 | 形态 |
|---|---|---|---|
| ① | `outer_rect = 整个 canvas`，补边无产品边界可裁 | `image_ops.py:1286/1294` | `outer_rect=_canvas_rect` |
| ② | `cut_h_px = lshape.cut_h + _ir_y`，缺口下边界**越过产品顶边** | `image_ops.py:1266` | 放大因素 |
| ③ | 补边**从画布边缘起铺** | `lshape_border.py:1126/1128/1130`、`lshape_border_route.py:464-467` | `b[0:yc, ...]` 硬编码 y 起点 = 0 |

### 6.4 修复方案（A 档）

为两条补边路径统一新增 `inset_top` / `inset_right` 内缩量，**默认 0 使既有行为逐像素不变**。

**关键设计 —— 内缩量不需要按角落分别推导**：

```python
inset_top   = cut_h_px - lshape.cut_h   # 缺口 y 方向多扩出来的部分
inset_right = cut_w_px - lshape.cut_w   # 缺口 x 方向多扩出来的部分
```

调用侧这两个差值**天然等价于「cut 越过产品内容的那一段」**，四个角落（tl / tr / bl / br）一律成立 —— 无需按角分别写映射，**这是本次改动能把七处签名收拢到两个参数的原因**。

在「缺口翻转到右上角」的归一化坐标系里，语义固定为：

| 参数 | 约束对象 | 实现 |
|---|---|---|
| `inset_top` | 垂直切边的 y 起点 | `y_lo = max(y_lo, inset_top)` |
| `inset_right` | 水平切边的 x 终点 | `x_hi = min(x_hi, W - inset_right)` |

**内凹角为什么不受影响**：角部分层区域在 `y > yc`，而 `yc = inset_top + lshape.cut_h > inset_top` 恒成立，所以角部永远落在产品内容之内，无需额外夹紧。同理 `inset_top ≥ yc` 的退化输入会被夹紧为整条垂直带跳过，不会抛异常。

**顺带覆盖旧路径**：原计划只改两个 `patch_*` 函数，实施时发现 `compute_cut_edge_bboxes`（旧 `detect_pool_material_borders` 路径）有**完全相同的越界结构** —— 若不改，走旧路径的素材仍会画超。故一并加内缩裁剪，否则这次修复只能算「三分之二」。
