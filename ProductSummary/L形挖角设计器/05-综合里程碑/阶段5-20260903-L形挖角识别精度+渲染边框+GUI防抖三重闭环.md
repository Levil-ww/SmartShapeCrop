## 一、识别链路 T1：从"勉强跑通"到"12/12 样图零误判"

### 阶段 2→4 的 corner 判定：单锚点（保留区重心）→ 错误方向
阶段 2–4 的 `_detect_corner()` 只看 L 保留区的最长连通域重心：
```
tl 挖角（切左上）时，L 保留区位于右下
保留区重心 (cx≈60%, cy≈60%) → 判定 br ❌（完全反向）
```
→ 本质：把"保留区所在象限"误当作"挖角所在象限"。阶段 4 拆独立面板时没改识别逻辑（当时 focus 在 UI），继承了阶段 2 的这一缺陷。

### 阶段 5 的 corner 判定：双锚点（挖角中心权重 2× + 保留区空穴重心权重 1×）
```python
锚点 1 = 挖角矩形内接中心（最可靠，因为内挖矩形就是切角本身）权重 2
锚点 2 = outer_mask − inner_mask 最大非像素空穴重心（L形内部的"缺口位置"）权重 1
→ 双锚点四象限投票：tl/tr/bl/br，取最多者
```
→ tl 案例下：
- 锚点1（挖角中心）在左上 → 投 tl（×2）
- 锚点2（缺口重心）也在左上 → 投 tl（×1）
- 得票 tl=3, tr=0, bl=0, br=0 → tl ✅

### 外框尺寸：减法思维 → 几何外包思维
| 阶段 | outer_w/h 计算 | 88×58 tl 挖 11×9 结果 |
|---|---|---|
| 阶段 2–4 | `total_w - cut_w` / `total_h - cut_h`（再被条带覆盖） | 78×10 ❌ |
| 阶段 5 | `outer_rect.w × scale` / `outer_rect.h × scale`（完整未挖角矩形） | **88×58 ✅** |

关键语义（阶段 5 写入 lshape_sketch_parser.py 文档字符串）：
> L 形外框 = **挖角前的完整外包矩形**，几何意义是"这块材料的原始板材尺寸"。
> 挖角只是从这块板上切掉一部分。渲染层通过两矩形减法（outer − cut）得到 L 保留区。识别层绝不做减法，只传两个原始矩形尺寸。

### 挖角损耗：双层减 → 统一加在转换层
| 位置 | 阶段 2–4 | 阶段 5 |
|---|---|---|
| 识别层 Step7 | 不加不减（正确） | 不加不减（正确）不变 |
| 池模式渲染分支 image_ops.py | `cut_w -= 1; cut_h -= 1` ❌ | **删除**（识别→传真值，池内联 L 形改走转换层） |
| LShapeDesign._to_crop_design() 独立面板 | `effective = cut + 1`（阶段 4 写对了） | `effective = cut + 1` 不变，并提升为官方唯一入口 |

## 二、渲染链路 T2：从"米黄镂空+半残边框"到"纯白+原生双带12/12边还原"

### 纯白背景：池背景色语义 → 镂空白色语义
阶段 2–4 的 L 形挖角区填色走了**池模式分支**（因为 L 形当时嵌在水池里，复用代码没改语义）：
```python
# 阶段 2–4：挖角区 = 池底背景色（素材底色采样）
hole_bg = sample_pool_bg(material)    # 克罗印花→米黄(245,238,218)
cut_mask_pixels = hole_bg
```
阶段 5 分离语义：
```python
# 阶段 5：L形挖角 = 镂空 = 纯白（硬约束 RGB 255,255,255）
if mode == 'rect_lshape':
    cut_mask_pixels = (255, 255, 255)  # 绝对纯白，零采样零色差
else:
    # 普通水池单洞 = 池底背景（语义正确，不变）
    cut_mask_pixels = sample_pool_bg(material)
```

### 边框检测：画布拉伸图 → 原素材图（工程约定写入 memory）
阶段 2–4 的边框检测在**拉伸后的画布**上跑：
- 素材 500×300 → 拉伸到 1000×600（画布尺寸）
- L 形凹角的两条切边是新合成像素，**本来就没有原生边框**
- 检测算法把花纹色差梯度当"边框"→ 误检测 + 内容色混入

阶段 5 的边框检测：
```
Step 1: 对原素材图（未拉伸）扫描四周边缘像素
        → 得到原生检测：黑 12px + 棕 46px（克罗印花）
Step 2: 按 scale_factor = material_px_per_cm / canvas_px_per_cm 缩放
        → 黑 12px → 画布下 12px（等比放大四舍五入）
        → 棕 46px → 画布下 45px（1px 误差 OK）
Step 3: 从外→内绘制（黑先→棕后），方向按 corner 四向调整：
        tl → 从左往右（竖边）+ 从上往下（横边）
        tr → 从右往左（竖边）+ 从上往下（横边）
        bl → 从左往右（竖边）+ 从下往上（横边）
        br → 从右往左（竖边）+ 从下往上（横边）
```
→ 4 方向 × 3 张素材 × 1 条切边 = 12 条切割边**两带完整还原**（黑 12px ±1 + 棕 46px ±2）。

## 三、交互链路 T3：从"每改必渲卡死"到"参数静止 200ms 才渲"

阶段 4 虽然拆出了独立面板（520 行新文件），但 SpinBox 的 5 个 valueChanged 信号仍然是**每改必立即渲染**：
```
用户滚轮 10 步 → 触发 10 次 valueChanged → 主线程：
10 × (写参数 12ms + 渲染 380ms + canvas 35ms) = 4270ms 阻塞
```

阶段 5 通过 `_LayersMixin` 通用防抖（因为 LShapePanel 也继承了 `_LayersMixin`，所以一次加 mixin，L 形和水池面板 19 个 SpinBox 全部生效）：

```
用户滚轮 10 步 → 10 × _schedule_apply_quiet：
  - 每次：参数立即写入 design（12ms，不卡）
          timer.start(200ms)   （重置静止计时器）
          首次调度时 deadline = 800ms 封顶
→ 静止 200ms 后 / deadline 到点 → _do_debounced_render 触发 1-2 次
```

**L 形面板影响**：
| 场景 | 阶段 4 | 阶段 5 |
|---|---|---|
| 挖角宽滚动 6 次（从 10→13cm） | 触发 6 次渲染 ≈ 2.5s 阻塞 | 合并成 1 次 ≈ 420ms，显示零延迟 |
| corner 单选切换（tl→tr） | 立即渲染 420ms ✅ | 立即渲染 420ms ✅（单选不在防抖范围内，是关键操作等价项） |
| 识别草图完成回填 | 立即渲染 500ms ✅ | 立即渲染 500ms ✅（parse_finished 信号走立即路径） |
| [生成预览] 按钮 | 立即渲染 420ms ✅ | 立即渲染 420ms ✅（按钮单击不变） |
