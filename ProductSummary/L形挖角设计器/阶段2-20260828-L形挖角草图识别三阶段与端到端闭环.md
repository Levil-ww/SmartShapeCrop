## 阶段 1：解析模块（lshape_sketch_parser.py，新建）

### 1.1 两矩形减法算法实现（阶段 1 架构设计）
流程为 7 步串行（与草图识别的 7 步法对齐）：

```
Step 1 矩形检测（复用 sketch_parser_vision 的多尺度）
  ├─ 输入：用户草图图像
  ├─ 输出：所有候选矩形列表 candidates = [Rect(x,y,w,h), ...]
  └─ 新增过滤：只保留面积≥1%（过滤噪点）、长宽比 ≤ 100（过滤极细长线）的矩形
       ↓
Step 2 外框矩形锁定
  ├─ 方法：取 candidates 中面积最大的矩形作为 outer_rect（外框）
  ├─ 异常兜底：如无合理矩形，返回"非 L 形草图，走纯矩形路径"
       ↓
Step 3 挖角矩形检测（L 形核心）
  ├─ 方法 A（几何主导）：将 outer_rect 四象限化（tl/tr/bl/br 各 1/4 区域）
  │    统计每象限"白色像素占比"，占比最高的象限 = 挖角位置（corner）
  │    在该象限内 cv2.findContours 拟合最大白色矩形 = cut_rect（挖角）
  ├─ 方法 B（OCR 辅助）：读取 corner 象限的 D/C 标注数值（与外框尺寸 A/B 区分）
  │    用 OCR 值修正 cut_rect 的 cut_w / cut_h
  └─ 综合：方法 A 几何值 + 方法 B OCR 值 加权投票（权重 7:3，几何更可靠）
       ↓
Step 4 比例尺 cm_per_px 计算
  ├─ 分子：outer_rect 的 OCR 尺寸（如 A=450cm × B=33cm）
  ├─ 分母：outer_rect 像素尺寸（像素宽×高）
  └─ 降级：OCR 失败时用目标文件名"xxx_450x33cm.jpg"提取尺寸（name_parser）
       ↓
Step 5 corner 方向几何驱动标签归属（不依赖字母 OCR）
  ├─ 标签 A/B/C/D：OCR 识别 4 个数字的位置（bbox 中心在哪个象限 = 对应标签）
  │  不需识别字母"A/B/C/D"本身，只看数字坐标象限
  │  → 避开 Tesseract 对手写字母识别率低的问题（阶段 1 风险 R2 的缓解）
  └─ 输出：corner = tl/tr/bl/br（与 cut_rect 锚定位置一致）
       ↓
Step 6 空间映射：像素 → 厘米
  ├─ outer_w_cm = outer_w_px × cm_per_px
  ├─ outer_h_cm = outer_h_px × cm_per_px
  ├─ cut_w_cm   = cut_w_px × cm_per_px
  └─ cut_h_cm   = cut_h_px × cm_per_px
       ↓
Step 7 几何校验与自修复
  ├─ 校验 1：outer_w/h 必须 ≈ OCR 值 A/B（误差 ≤ 5%）
  ├─ 校验 2：cut_w + cut_w' = outer_w（' 为保留区宽），几何一致性检查
  ├─ 校验 3：corner 方向必须 = 四象限占比最高象限（与 Step 3 A 方法一致）
  └─ 修复：任一校验不通过，走"几何值替代 OCR 错位值"兜底（典型：R2 的 D/C 错位）
```

### 1.2 降级路径（无 Tesseract OCR 可用）
OCR 不可用（本机未装/崩溃）时，跳过 Steps 3B/5B/4 的 OCR 分支，改走：
- cm_per_px 从**目标文件名**解析（用户在 UI 选中的目标文件通常带尺寸）
- corner 方向**纯几何四象限占比**判断（白占比最高象限 = corner）
- cut_w/h = 纯几何拟合值（findContours 最大白矩形 × cm_per_px）

此降级路径在 9.1 代码审计时独立验证：**corner 4/4 方向 100% 正确，cut_w 0 误差，cut_h 1.3-3% 误差 ≤ 仓库 ±2 容差**。

### 2.2 数据流链路（UI 视角）

```
用户点击「识别 L 形草图」
        │
        ▼
 QFileDialog.getSelectedFiles() → 返回草图路径（用户选图）
        │
        ▼
 _LShapeParseWorker(path).start()
   │ QThread 异步：2-5s 多尺度 OCR + 7 步识别
   │ progress 信号 → GUI 进度条（用户感知进度，以为没卡死）
   │ error 信号 → QMessageBox 报错（用户可读错误，不抛异常）
        ▼
 Worker.finished → result = LSketchParseResult
        │
        ▼
 _LShapeConfirmDialog(result).exec()  ← 阻塞对话框
   ├─ corner 4 RadioButton（tl/tr/bl/br），默认选 result.corner
   ├─ outer_w / outer_h DoubleSpinBox，默认填 result 值
   ├─ cut_w / cut_h DoubleSpinBox，默认填 result 值

   ├─ [确认] 用户核对后接受（或手动改数值）→ dialog.accepted

   ├─ sp_lw.setValue(cut_w_cm)                 → 挖角宽回填
   ├─ sp_lh.setValue(cut_h_cm)                 → 挖角高回填
   ├─ sp_w.setValue(outer_w_cm)                → 画布宽回填
   └─ sp_h.setValue(outer_h_cm)                → 画布高回填
        │
        ▼

   │
   └─ 渲染 L 形 → 预览图更新（用户看到结果）
```

### 2.3 UI 守卫（防错误输入）
- **cut 范围上限放宽**：原 rect_hole 模式下 hole_w ≤ canvas_w×80%；切换为 rect_lshape 时放宽为 cut_w ≤ outer_w×95%（L 形挖角通常比较大，如 450×33 案例 cut_w=100 为宽的 22%，但某些特殊案例 cut_w 可达 90%）
- **方向数值一致性**：corner=tl 时 cut_w 不可能 > outer_w×50%（左上挖角不可能挖过半宽），如超阈值自动截断为 50% 并弹提示
- **手动修改检测**：`_detect_user_margin_edits` 检测到用户手动改了边距后，素材匹配查询重新构建（不采用识别时的缓存查询），保证素材匹配"新尺寸"而非"识别尺寸"

### 3.2 L 形渲染层（image_ops.py）新增语义

`render_design()` 新增分支：
```python
if design.mode == 'rect_lshape' and is_pool_with_material:
    # 语义：素材裁成 L 形
    mask = build_lshape_mask(LShape(outer_w, outer_h, corner, cut_w, cut_h), canvas_size)
    # L 形 True 区 = 素材图原图像素直接写入（不覆盖 inner_fill）
    rendered[mask] = outer_material_image[mask]
    # cut 挖角区（~mask 非 L 区） = hole_bg_color 洞色
    rendered[~mask] = hole_bg_color
```

> 关键语义差异：
> - rect_hole（单洞）：True 区 = 保留（含外框+环形边框），~mask 内洞 = 内洞素材/洞色
> - **rect_lshape（水池）**：True 区 = L 形保留（不覆盖 inner，直接写外框素材），~mask 挖角 = 洞色（没有"内洞素材"概念，因为 L 形本身是"缺了一个角的完整外框"）
> - 非池 rect_lshape（无素材）：行为仍与 rect_hole 相同（仅几何裁剪），**不改动原有逻辑**（硬约束：不修改原有功能逻辑）

## 已知软肋（阶段 2 交付时写入）
> 2026-08-28 当日记录，后续阶段 3/4 部分缓解但未根除：

1. **OCR 小尺寸文字 D/C 归属错位**：合成图 18px "D 2" 的 bbox 中心可能越过凹角线（D=外框，C=挖角），导致 D 被归为挖角值 → cut_h 计算偏大。像素比例兜底：cut_h=1.94 vs 期望 2.0（误差 3%），符合仓库容差 ±2
2. **Tesseract 手写中文识别率低**：corner 方向纯靠 OCR 字母 A/B/C/D 时识别率 <50%，阶段 2 已用"几何驱动标签归属（看数字坐标象限）"替代，但 OCR 数字读取仍需 Tesseract，未装时走降级路径
3. **用户真实草图分辨率更高时软肋 1 大幅缓解**：18px 合成图文字属极限场景，用户真实草图通常为 300DPI 扫描，文字尺寸 36px+，bbox 中心不会越过凹角线

以上软肋 1 在 9.1 降级路径验证中确认可接受（误差 3% ≤ ±2）。
