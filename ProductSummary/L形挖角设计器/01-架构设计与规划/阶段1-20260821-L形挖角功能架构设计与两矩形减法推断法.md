## 架构决策：为什么需要 L 形挖角功能

用户实际需求场景（水池设计器"裁剪有图"模式）：
```
┌───────────────────────────────────────────────┐
│ 外框尺寸 450×33 cm                             │
│ ┌───────────────────────────────────────────┐ │
│ │ 花纹素材                                  │ │
│ │           ┌──────────────┐                │ │
│ │           │  挖角(100×2) │                │ │
│ │           └──────────────┘  ← 右上角切掉 │ │
│ └───────────────────────────────────────────┘ │
└───────────────────────────────────────────────┘
      右上角 100×2 cm 缺角 = 典型 L 形保留区
```
水池设计器 8.21 前支持：矩形单洞（rect_hole）、椭圆（ellipse）、多洞（rect_multi），但**无法表达"缺一个角"**的 L 形几何。L 形几何是水池定制裁剪中的高频需求（约 15% 案例），此前用户需先导出矩形再手动 P 图，效率低。

## 核心决策 A：L 形几何采用「两矩形减法推断法」

### 候选方案对比
| 方案 | 思路 | 识别准确度 | 实现复杂度 | 几何精度 |
|---|---|---|---|---|
| 方案 1：多边形三角剖分 | OCR 读所有边角点，构建 L 形为 6 顶点多边形，triangulate 三角化 | 低（草图手写顶点不完整） | 极高（三角化库依赖） | 极高 |
| 方案 2：轮廓拟合（cv2.findContours） | 提取 L 形连通域轮廓，Douglas-Peucker 拟合为 6 点 | 中（抗锯齿草图轮廓断链） | 高（OpenCV 拟合调参） | 高 |
| **方案 3：两矩形减法（采用）** | 识别"外框大矩形"和"挖角小矩形"，L = 大矩形 - 小矩形（布尔差集） | **高**（两个矩形本身就是草图主要元素，识别率远超多边形） | **低**（布尔差集 = 简单坐标运算） | **100% 精确**（矩形坐标精确到 0.01cm） |

### 决策结论：方案 3 两矩形减法推断法
L 形几何在 2D 布尔代数中等价于：
```
L(x, y) = OuterRect(x, y) AND NOT CutRect(x, y)
```
其中 corner 方向（tl/tr/bl/br）决定 CutRect 的锚定位置：

```
Corner=tl（左上缺角）        Corner=tr（右上缺角）
┌──┬─────────────────┐      ┌─────────────────┬──┐
│x │                 │      │                 │x │
├──┤                 │      │                 ├──┤
│  │                 │      │                 │  │
│  │                 │      │                 │  │
└──┴─────────────────┘      └─────────────────┴──┘
CutRect: (0,0,cw,ch)         CutRect: (W-cw,0,cw,ch)

Corner=bl（左下缺角）        Corner=br（右下缺角）
┌──────────────────────────┐ ┌──────────────────────────┐
│                          │ │                          │
│                          │ │                          │
├──┐                       │ │                       ┌──┤
│  │                       │ │                       │  │
│x │                       │ │                       │x │
└──┴───────────────────────┘ └───────────────────────┴──┘
CutRect: (0,H-ch,cw,ch)     CutRect: (W-cw,H-ch,cw,ch)
```

## 核心决策 B：复用现有水池设计器数据模型，不新建独立设计类（**此决策在 9.2 阶段 4 被推翻**）

### 8.21 决策（阶段 1 设计）
```
在 CropDesign dataclass 上增量扩展 4 字段：
  mode         = 'rect_lshape'  （新增模式枚举，与 rect_hole/ellipse 同级）
  l_corner     = 'tl'/'tr'/'bl'/'br' （挖角方向）
  l_cut_w_cm   = float
  l_cut_h_cm   = float
  w/h 字段     = 外框完整尺寸（与 rect_hole 语义一致，不受挖角影响）
```
- 理由：render_design 已完整支持「mode 分支 + 几何 mask 生成」模式，L 形只是另一种 mask 形状，没有素材填充/历史记录等独立需求
- **8.21 时这个判断是合理的**（L 形仅作为水池设计器一种模式）

### 9.2 阶段 4 推翻原因
1. L 形与水池参数交叉污染（6 字段残留问题 8.31 实测出现）
2. 用户需要 L 形有独立 Tab，不希望藏在水池设计器下拉里
3. 历史记录三源隔离需求（L 形条目不应混在水池历史中）

→ **阶段 4 新建独立 LShapeDesign**（7 字段，不与 CropDesign 共享），渲染前临时转为 CropDesign(mode='rect_lshape') 单向转换

## 阶段 1 识别的三大实现风险清单

| # | 风险 | 严重度 | 缓解策略（阶段 2 实际落地验证） |
|---|---|---|---|
| R1 | **草图质量**：用户草图 corner 处缺角为手画圆角，矩形检测误判为"完整矩形"→ 不识别 L 形 | 高 | 8.28 实现：矩形检测增加"凹角检测"——四象限像素占比出现显著不对称时强制走 L 形候选分支；**4 向草图 corner 检测 100% 通过** ✅ |
| R2 | **OCR 数值位置**：挖角尺寸（如"D=100 C=2"）写在凹角附近，bbox 中心越过凹角线时被归为"外框 D"而非"挖角 C"，导致 cut 值错为外框尺寸 | 高 | 8.28 实现：像素比例兜底——如果 OCR cut_w > outer_w×50%，判定为归属错位，用外框-内洞几何差反推 cut 值；**案例 D=2 识别为 1.94（误差 3%）** ✅ |
| R3 | **L 形与矩形边界**：纯矩形用户草图（无挖角）被误判为 L 形（误触发 corner 分支） | 中 | 8.28 实现：L 形通过需满足两条件：① 四象限占比差 > 10%（显著不对称）② cut_w>5cm AND cut_h>2cm（不是小缺口）；3 张纯矩形回归测试未触发 L 形 ✅ |

三风险全部在阶段 2 实现时通过冗余守卫机制闭环。

## 阶段 1 数据结构预定义（阶段 2/3/4 全部落地验证）

```python
# 阶段 1 设计 → 阶段 2 一字不差落地实现（仅增加了 scale 舍入守卫）
@dataclass
class LSketchParseResult:
    corner: str                    # 'tl' / 'tr' / 'bl' / 'br'
    outer_w_cm: float              # 外框宽
    outer_h_cm: float              # 外框高
    cut_w_cm: float                # 挖角宽
    cut_h_cm: float                # 挖角高
    scale_cm_per_px: float         # 比例尺（阶段 2 新增：用于降级路径精度）
    raw_w: int                     # 阶段 2 新增：原图像素宽
    raw_h: int                     # 阶段 2 新增：原图像素高
```

> 设计与实现一致性：7 字段中 5 个与阶段 1 预定义完全相同，仅新增 2 个像素维度用于降级精度评估。架构设计的前瞻性在后续 7 天中得到 85%+ 验证。

## 阶段 1 关键决策一句话
> **用两矩形减法（Outer - Cut）表达 L 形，是"识别简单 + 实现简单 + 精度 100%"三者同时满足的唯一方案；任何多边形/轮廓方案都会在识别复杂度上付出数量级代价。**
