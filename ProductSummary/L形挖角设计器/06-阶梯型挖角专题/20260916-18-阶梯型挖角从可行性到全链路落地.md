## 二、9.16 可行性分析（`10b7a5b`）

### 2.1 实测取证

用真实草图跑通全链路，结果出乎意料——**识别层数据基本全对**：

| 项 | 真实值 | 识别值 | 判定 |
|---|---|---|---|
| 外框宽 | 93.5cm | 93.5cm | ✅ |
| 外框高 | 55.0cm | 55.0cm | ✅ |
| 凹角数量 | 2 | 2 | ✅ |
| 级1（宽×深） | 10 × 6.5 | 10.0 × 6.5 | ✅ |
| 级2（宽×深） | 8.5 × 3.5 | 8.5 × 3.5 | ✅ |
| corner 标签 | 应可区分两级 | 两个都是 `tr` | ❌ **根因** |

### 2.2 根因定位

`corner ∈ {tl, tr, bl, br}` 只回答「凹角朝向哪个 bbox 角」，不回答「它是该角的第几级、沿边错位多少」——**是表达能力不足（模型缺口），不是算法没算出来**。

### 2.3 核心方案：CutRect 列表化

```python
@dataclass
class CutRect:
    anchor: Literal['tl', 'tr', 'bl', 'br']  # 锚定角
    offset_x_cm: float   # 沿水平方向错位量
    offset_y_cm: float   # 沿垂直方向错位量
    w_cm: float          # 矩形宽
    h_cm: float          # 矩形高
```

**表达能力**：
- 旧单角 L 形 = `CutRect('tr', 0, 0, 30, 8)`
- 旧多边 L 形 = `[CutRect('tr',0,0,30,8), CutRect('bl',0,0,30,13)]`
- 阶梯两级 = `[CutRect('tr',0,0,10,6.5), CutRect('tr',10,6.5,8.5,3.5)]`

> **旧模型是新模型的严格子集**（offset 恒为 0），兼容成本极低。

### 2.4 面板决策：集成，不新开

| 维度 | 集成（推荐） | 新开面板 |
|---|---|---|
| 几何本质 | 阶梯是 L 形的超集 | 复制整套链路 |
| 识别层 | 已能算出全部数据 | 同样要复用 |
| 渲染链路 | `build_lshape_mask` 已是列表入参 | 100% 重写 |
| 历史记录 | 复用 `TARGET_SRC_LSHAPE` | 需第四源 + 白名单 |
| 隐性收益 | 绕过 2 个静默失效硬编码坑 | — |

### 2.5 工期预估（修订后）

| 期 | 内容 | 原估 | 修订 |
|---|---|---|---|
| ① CutRect 模型 + 几何层 | 数据模型 + build_lshape_mask + 兼容层 | 3–5 天 | 2–3 天 |
| ② 识别层改造 | all_corners 补 anchor/offset | 4–6 天 | 1–2 天 ⬇️ |
| ③ GUI 交互 | 同角位子行 | 2–3 天 | 2–3 天 |
| ④ 边框补全 | 非 bbox 角凹角 | 4–6 天 | 3–5 天 |
| **合计** | | **13–20 天** | **8–13 天** ⬇️ |

识别层从 4–6 天降至 1–2 天，原因是**实测发现数据已在手边，只需换公式而非新算法**。

## 三、9.16 面板区分设计（`10b7a5b` 第二文档）

### 3.1 核心原则：不区分，因为不需要区分

> **「多边 L 形」与「单边阶梯」是同一套参数的两种取值形态。**
> 判据：按 anchor 分组，某组 ≥2 个 → 阶梯。
> 形状是推导结果，不是存储状态。

### 3.2 UI 设计：父行 + 子行

```
现状（4 个平级行）：              改为（父行 + 可折叠子行）：
☑ 挖角1  [右上角▾]  宽  高       ☑ 右上角   宽 [10.0]  高 [ 6.5]
☐ 挖角2  [左下角▾]  宽  高          └ ☑ 第2级  宽 [ 8.5]  高 [ 3.5]   [+ 追加一级]
☐ 挖角3  [左上角▾]  宽  高       ☐ 左下角   宽 [ 0.0]  高 [ 0.0]
☐ 挖角4  [右下角▾]  宽  高          └ ☐ 第2级  宽 [ 0.0]  高 [ 0.0]
```

用户操作：想挖阶梯 → 在该行下点「+ 追加一级」。全程没有「形状模式」选择。

### 3.3 约束分层

`group_by_anchor` 同时解决约束问题：
- **单级（多边 L 形路径）**：沿用旧规则（不越界）
- **多级（阶梯路径）**：单调错位 + 不重叠 + 最外层不越界
- **跨角求和**：每角只取最外层级参与

> 一个分组函数，服务三件事：形状区分、约束分层、渲染遍历。

## 七、关键架构决策与理由

| # | 决策 | 理由 | 反例教训 |
|---|---|---|---|
| 1 | **集成进 L 形面板，不新开** | 阶梯是 L 形超集；不新增 mode/历史源可绕过 2 个静默失效硬编码坑 | 9.2 拆分 L 形是语义断层，这次不是 |
| 2 | **形状是推导结果，不存 shape_type** | 用 `group_by_anchor()` 按需推导，避免「状态与实际不一致」 | 本项目静默失效类 bug 的一大来源就是两处维护同一语义 |
| 3 | **CutRect 模型，旧模型为子集** | 兼容层零行为变化，500+ 测试不受影响 | — |
| 4 | **识别层用 concave 坐标算 offset** | 数据一直在手边，只是换公式，不是新算法 | 原估工期 13–20 天就是误以为要写新识别算法 |
| 5 | **跨角求和取最外层级** | 阶梯的总边占用就是最外层级尺寸，内层不参与跨角约束 | 旧约束会误拦阶梯（如 tr(10)+tr(8.5) 求和 18.5 > 边长） |
