# L 形挖角设计器 — 遗留事项修复方案

> 基于 `dependency-resilience` 专家框架分析 · 约束：不改变程序原本实现的功能逻辑

## 依赖矩阵

| # | 遗留事项 | 调用方 → 被调方 | 协议 | 关键性 | 失败后果 |
|---|---|---|---|---|---|
| 1 | 画布不刷新 | `_on_pool_finished_ok` → `_apply_quiet` → `design_changed` → `set_design` | Qt Signal/Slot | 高 | 用户看到草图不刷新，以为程序无响应 |
| 2 | B/C 档边框对齐 | `apply_lshape_border_completion` → `_fill_layers_vertical_horizontal` | 函数调用 | 中 | 切边 1px 亮缝；垂直切边从 y=0 起铺越界 |
| 3 | OCR 超时 | `_multi_scale_ocr_scan` → `tesseract.image_to_data` | pytesseract | P0 | 单尺度 OCR 挂住 → 吃光 20s 预算 |
| 4 | Worker 不可中断 | `PoolRenderWorker.run()` → 全流程 | QThread | P0 | 用户取消后仍阻塞，UI 无响应 |

## 超时 / 截止预算

| 调用方 | 当前超时 | 问题 | 修复后 |
|---|---|---|---|
| `_multi_scale_ocr_scan` 全局 | 20s（`_PARSE_TIMEOUT_SEC`） | 无 per-scale 预算；一个尺度挂住吃光全部 | 20s 总预算 + **每尺度 8s 子预算** |
| `image_to_data` 单次 | 20s | 与全局预算相同 → 无叠加保护 | 降至 **8s**（per-scale 子预算内） |
| `_LShapeParseWorker.run()` | 无独立超时 | 依赖 `parse_lshape_sketch` 内部 deadline | 保留内部 deadline + Worker 层 **30s 硬超时** |
| `PoolRenderWorker.run()` | 无 | 全流程无超时 | 各阶段插入 `isInterruptionRequested()` 检查点 |

## 修复方案（逐项）

### 遗留 #1：画布不刷新

#### 根因

信号链完整存在，但有三处静默失败点：

| 断点 | 位置 | 机制 |
|---|---|---|
| **A. 空字符串 target_name_override** | `property_panel.py:516` → `generate.py:68` | `get_target_text()` 返回 `""`（非 `None`），`is not None` 通过 → `effective_target_name = ""` → Worker 无有效目标文件名 → 匹配失败或静默跳过 |
| **B. _apply_quiet 抛 ValueError** | `generate.py:489-495` | `_collect()` / `apply_ui_snapshot()` 校验失败 → `except ValueError` → `return` → `design_changed` **永不 emit** |
| **C. finished_err 替代 finished_ok** | Worker 异常 | `finished_err` 信号被连接但仅弹 MessageBox，不更新画布 |

#### 修复（不改功能逻辑，仅加防御 + 日志）

**A. 空字符串回退**（`property_panel_generate.py:68`）：

```python
# 修改前
if target_name_override is not None:
    effective_target_name = target_name_override.strip()

# 修改后：空字符串回退到 pool 面板，避免 Worker 无有效目标
if target_name_override is not None and target_name_override.strip():
    effective_target_name = target_name_override.strip()
else:
    effective_target_name = self._pool_target.text().strip()
    logger.warning("[PropertyPanel] target_name_override 为空，回退到 pool 面板目标名")
```

**B. ValueError 路径补日志**（`generate.py:490-495`）：

```python
except ValueError as e:
    message = format_design_validation_error(e)
    self._set_pool_status(message, is_error=True)
    QMessageBox.warning(self, "参数校验失败", message)
    logger.warning(f"[PropertyPanel] _apply_quiet 校验失败，design_changed 未 emit：{e}")
    # 新增：即使校验失败也尝试用旧 design 刷新画布，避免画布冻结
    self.design_changed.emit(self.design)
    return
```

**C. finished_err 路径刷新画布**：

在 `finished_err` 的 handler 中，如果 `self.design is not None`，仍然 emit `design_changed` 让画布回到上一个有效状态，而非冻结。

#### 验证测试

```
1. L 形识别成功 + target 为空 → 确认回退到 pool 面板目标名 + 日志输出
2. L 形识别成功 + 几何约束违反 → 确认 ValueError 被捕获 + 画布仍显示旧预览
3. Worker 异常 → 确认 finished_err 弹窗 + 画布不冻结
```

### 遗留 #3：OCR 多尺度循环超时

#### 现状

| 机制 | 位置 | 状态 |
|---|---|---|
| 全局 deadline | `_PARSE_TIMEOUT_SEC = 20` | ✅ 已有 |
| check_cancel 回调 | `lshape_sketch_parser.py:1525-1526` | ✅ 已有 |
| 单次 OCR timeout | `image_to_data(timeout=20)` | ⚠️ 与全局预算相同 |
| per-scale 子预算 | 无 | ❌ 缺失 |

**问题**：3 尺度 × 3 PSM × 3~4 预处理 = 27~36 次 OCR。如果第一个尺度（scale=1.0）的某次 `image_to_data` 挂住 20s，全局 deadline 到期，后续尺度（2.5x、4.0x，通常识别率更高）根本没机会跑。

#### 修复（加子预算，不改 OCR 逻辑）

`services/sketch_parser/sketch_parser_vision.py`，`_multi_scale_ocr_scan` 内部：

```python
# 在 _run_one 闭包中，新增 per-scale 子预算
_scale_start = _sp_time.monotonic()
_scale_budget = 8.0  # 每尺度最多 8 秒

def _run_one(scale, psm, variant_key):
    if check_cancel is not None and check_cancel():
        return out
    # 新增：per-scale 子预算检查
    if _sp_time.monotonic() - _scale_start > _scale_budget:
        logger.info(f"[_run_one] 尺度 {scale} 超出 {scale_budget}s 子预算，跳过剩余 PSM/变体")
        return out
    ...
```

同时将 `image_to_data(timeout=20)` 降为 `timeout=8`：

```python
# 修改前
data = pytesseract.image_to_data(img, config=f'--psm {psm}', timeout=20)

# 修改后
data = pytesseract.image_to_data(img, config=f'--psm {psm}', timeout=8)
```

效果：每个尺度最多 8s（3 尺度 × 8s = 24s，但全局 deadline 20s 会先到），高尺度仍有机会运行。单次 OCR 从 20s 降至 8s，不影响正常识别（正常 OCR 通常 <2s）。

#### 验证测试

```
1. 合成超大图（触发慢 OCR）→ 确认每尺度 ≤8s，后续尺度有机会运行
2. 正常草图 → 确认 8s 超时不影响快速识别（正常 <2s）
3. 全局 20s deadline 仍有效（最终兜底）
```

### 遗留 #4：Worker 不可中断

#### 现状

| Worker | 中断检查点 | 问题 |
|---|---|---|
| `_InnerMatchWorker` | 5 处 | ✅ 较好 |
| `_SketchDecodeWorker` | 3 处 | ✅ 较好 |
| `_LShapeParseWorker` | 1 处（`run()` 第 979 行，OCR 返回后） | ⚠️ OCR 进行中无法中断 |
| `PoolRenderWorker` | **0 处** | ❌ 全流程无中断 |

#### 修复 4a：`_LShapeParseWorker`（补中断到 OCR 回调）

`_LShapeParseWorker.run()` 已经把 `_lshape_cancel` 传给了 `parse_lshape_sketch`，`_lshape_cancel` 检查 `deadline`。但 `_lshape_cancel` **没有检查 `isInterruptionRequested()`**：

```python
# 当前（lshape_sketch_parser.py:1525-1526）
_lshape_deadline = _sp_time.monotonic() + _PARSE_TIMEOUT_SEC
def _lshape_cancel():
    return _sp_time.monotonic() > _lshape_deadline

# 修改后：同时检查 Worker 中断标志
def _lshape_cancel():
    if _sp_time.monotonic() > _lshape_deadline:
        return True
    # 新增：检查 Worker 级中断
    if self.isInterruptionRequested():
        logger.info("[LShapeParseWorker] 用户取消，中断 OCR")
        return True
    return False
```

> `_lshape_cancel` 是闭包，已捕获 `self`，改动仅 1 行，不改变 OCR 循环逻辑。

#### 修复 4b：`PoolRenderWorker`（加检查点）

在 `PoolRenderWorker.run()` 的关键阶段之间插入检查点（不改各阶段内部逻辑）：

```python
def run(self):
    # 阶段 1: 文件名解析 + 模板匹配
    ...
    if self.isInterruptionRequested(): return  # 新增

    # 阶段 2: 草图解析
    ...
    if self.isInterruptionRequested(): return  # 新增

    # 阶段 3: 素材预加载
    ...
    if self.isInterruptionRequested(): return  # 新增

    # 阶段 4: 渲染
    ...
```

在 `run()` 方法中找到各阶段的分界点（模板匹配后、草图解析后、素材加载后、渲染前），各插入一行 `if self.isInterruptionRequested(): return`。

> 这是纯加法，不改变任何阶段的执行逻辑，只在阶段之间增加退出机会。

#### 验证测试

```
1. _LShapeParseWorker: OCR 进行中点取消 → 确认 1s 内退出（而非等 20s）
2. PoolRenderWorker: 素材加载阶段点取消 → 确认立即退出
3. PoolRenderWorker: 渲染阶段点取消 → 确认立即退出
4. 正常流程不受影响（无中断时检查点为 no-op）
```
