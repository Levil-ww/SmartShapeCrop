## 三、OCR 逐角归属（`15ed92c`）— 三期核心

### 3.1 要解决的问题

9.14 解除收敛点后，识别层能检测到多个凹角，但每个角的尺寸仍由像素比例统一反推，未使用 OCR 逐个读取。三期目标：**每个角的挖角尺寸独立 OCR 归属**。

### 3.2 实现

新增两个核心函数：

| 函数 | 职责 |
|---|---|
| `_resolve_cut_pair_per_corner` | 按角位逐个解析 OCR 数字对，分配给对应 cut |
| `attribute_cut_ocr_per_corner` | 将 OCR 归属结果写回 `cuts_cm` 列表 |

数据流：

```
all_corners（几何检测，像素）
       ↓ 定位 OCR 数字位置
OCR 逐角读取（每角独立）
       ↓ 互补对 + geo_ratio 双信号校验
cuts_cm（最终消费，厘米 + source 字段）
```

每个 cut 结果携带 `source` 字段：`'ocr'`（OCR 成功）或 `'pixel_ratio'`（OCR 失败兜底）。相邻角共享边时按凹角点位置分段归属 OCR 数值。

### 3.3 防护措施

OCR 值与像素比例偏差 > 40% 时回退至像素比例，防止 OCR 误读导致尺寸严重偏离。

### 3.4 测试

新增 `tests/core/test_multi_corner_ocr.py`（315 行），9 项测试全通过，418 项回归测试通过（3 项预存失败）。

## 四、G1 闸口不变量常驻（`073153d`）

### 4.1 设计目标

9.14 装上 G1 闸口后，闸口逻辑写在识别成功路径上。问题：后续若新增 early-return 分支，可能绕过闸口。**三期目标：把 G1 固化为不变量，覆盖所有退出路径**。

### 4.2 实现

提取 `_apply_g1_invariant()` 方法，在 `parse_lshape_sketch` 的**所有**退出路径（包括异常分支）调用：

```python
# 不变量常驻：无论从哪条路径退出，G1 闸口都会执行
try:
    ...  # 识别主逻辑
finally:
    _apply_g1_invariant(result, geo, dims)
```

### 4.3 测试

新增 `tests/core/test_g1_invariant.py`（294 行），覆盖正常/异常/early-return 三类退出路径，验证 `notches_detected != notches_consumed` 时 `success` 一致降级。

## 六、草图数据识别三轮 Bug 修复（`42ca969` + 同日会话）

### 6.1 问题现象

用户反馈：OCR 识别的挖角尺寸（如 45.8×22.5 cm）未正确显示，自动识别后手动修改参数但预览未应用新值。

### 6.2 三轮修复

| 轮次 | 根因 | 修复 | 验证 |
|---|---|---|---|
| ① 像素/厘米混淆 | `_extract_multicorner_suggestions` 仅读 `all_corners` 像素数据，忽略 `cuts_cm` OCR 真值 | 三级优先级读取：`cuts_cm` → `all_corners` → 像素比例反推 | 46 个 L 形测试通过 |
| ② OCR 单信号偏差 | `_resolve_cut_pair` 仅依赖互补对信号，互补性检查阈值过严导致 OCR 值错误拆分 | 双信号（互补对 + geo_ratio）+ 阈值放宽至 15% | 95 个 L 形+水池集成测试通过 |
| ③ 四层数据管线 | success 分支未用 OCR 真值、UI 回填未读 `cuts_cm`、set_lshape_params 不同步 dict | Model 层 success 优先 `result.cuts_cm[0]`，UI 优先 `debug['cuts_cm']` | 500 个测试通过 |

### 6.3 `all_corners` vs `cuts_cm` 数据流

```
轮廓分析阶段                    OCR 归属阶段
    ↓                              ↓
all_corners（像素，几何检测产物）  cuts_cm（厘米，最终消费产物）
    └──────── 定位 OCR 数字位置 ────→
                                    ↓
                              优先 OCR，失败→像素比例反推
                                    ↓
                              source 字段标识来源
```

**旧代码问题**：只使用 `all_corners` 而忽略 `cuts_cm` 中的 OCR 真值，导致 UI 显示尺寸偏差。

### 6.4 四层 Bug 逐层定位

| 层 | Bug | 位置 | 修复 |
|---|---|---|---|
| OCR 归属核心 | 互补性检查阈值过严 | `lshape_sketch_parser.py` `_resolve_cut_pair` | 阈值调整 15% |
| OCR 逐角 | 逐角函数同样依赖单信号 | `lshape_sketch_parser.py` `_resolve_cut_pair_per_corner` | 双信号校验 |
| success 回填 | success 分支未用 OCR 真值 | `lshape_panel.py` `_on_lshape_parsed` | 优先 `result.cuts_cm[0]` |
| UI 回填 | UI 仅读 `all_corners` | `lshape_panel.py` `_extract_multicorner_suggestions` | 优先 `debug['cuts_cm']` |
