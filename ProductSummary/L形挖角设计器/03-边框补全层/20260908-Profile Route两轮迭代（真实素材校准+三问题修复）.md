# 2026-09-08：L形挖角 Profile Route 两轮迭代

## 概述

针对用户反馈的三个问题（中古雨林无边框、蔓生花色差、庄园秘境白线+黑带变细），Profile Route 经过两轮深度迭代完成修复。第一轮重写分类算法（窗口收集→尾裁→定界→分组→让位），支持 5 层结构识别；第二轮新增锚点对齐机制解决出血边错位，层深截断到 3 层（止于最外内框线），几何均值 scale 修复 ROTATE_270 缩放误差。

最终三素材全部正确：蔓生花 3 层色带与素材一致、中古雨林 L 形框线连续、庄园秘境黑带厚度恢复 114px≈素材 118px。

***

## 第一轮：真实素材校准（蔓生花 / 中古雨林）

### 用户反馈的两个问题
1. 中古雨林完全没有 L 形边框（切边纯白）
2. 蔓生花沿切边的补画颜色与原素材有色差

### 根因（真实素材 dump 剖面定位）

| # | 根因 | 量化影响 |
|---|---|---|
| 1 | 旧 `_classify_profile`「遇到 field 色段即停」 | 中古雨林黑描边后 161px 白边距 = field 色 → 结构在描边处被截断，只剩 1 层 |
| 2 | `_MAX_LAYERS=4` 装不下 5 层结构 | 蔓生花/中古雨林都是 5 层结构 |
| 3 | `_LINE_MAX_THICK=18` 小于真实细线 | 真实细线 24px，被误判为色带 |
| 4 | `_DARK_LINE_MAX_CHANNEL=170` 卡住真实线色漂移 | 真实线色 168~179，不被判为线 |
| 5 | field 容差 25 太紧 | 花田过渡段 L2≈30 漏裁 |

另一个踩坑：之前调试用的"蔓生花"jpg 其实是程序输出图（裁剪有图），不是原始素材。原始素材在 PSD 文件中，需用 psd-tools 提取。

### 修复：重写分类算法（core/lshape_border_route.py）

**五步流程：**

1. **窗口收集**（短边×15%）
   - 巨段：深色且色近 field → 限厚收录（克罗棕带直通内部）
   - 浅色巨段（花田/白底）→ 丢弃

2. **尾裁 field 段**
   - 容差放宽至 35（原 25）

3. **定界**
   - 末线后仅保留紧贴的深色平整带（描边+色带结构）
   - 其余剔除

4. **分组**
   - 线独立成层
   - 相邻非线段（边距/点带/文字带）无条件合并
   - 层数只由线位置决定，跨边稳定

5. **让位规则**
   - 首层厚黑(≥50) → V13
   - 首层黑细描边 + 深色第二层（克罗类）→ V13
   - 保护用户已认可的克罗效果

### 第一轮验证结果

| 素材 | 识别结果 | 状态 |
|---|---|---|
| 蔓生花 PSD (8268×4724) | [黑10, 米285(246,232,205), 线25, 点带123, 线25] → 5 层 | ✓ |
| 中古雨林 (5965×3602) | [黑10, 白162, 线15, 文字带124, 线14] → 5 层 | ✓ |
| 克罗印花 | None 让位 V13（现状不变） | ✓ |

- 端到端渲染：切边米色与素材一致，L 形框线连续转角
- 测试：新增合成雨林全结构夹具（描边/白边距/框线/文字带/框线），全量 **316 passed + 5 skipped**

### 踩坑备忘
- 合成夹具的周期性花纹：周期 <10px 会被「3 扫描线均值 + 滑动平均」抹平；扫描线位置不能与花纹周期对齐（同相位 → std=0 → 误判成线）
- 段 std 是平滑过的，邻段花纹的列间差异会扩散进线段（实测 17.3）→ 线判定用独立容差 `_LINE_STD_MAX=20`（真实素材线 std=0 不受影响）

## 第二轮：用户反馈三问题修复

### 用户反馈
1. 蔓生花/中古雨林 L 形只需补到「绿色箭头所指最外内框线」，点带/文字带及其内侧细线不处理
2. 程序实跑蔓生花/中古雨林仍无 L 形边框（离线样张正确）
3. 庄园秘境出现白线 + 黑边带明显变细

### 端到端诊断结论（用 pattern_library 真实素材 dump 剖面 + 切片）

#### "无效果"真因
Profile 实跑**确实触发**，但 `left` 边最外 2px 出血白边未对齐 → 四边层序错位 → 投票把颜色平均成 `(64,64,64)`/`(187,187,187)` 灰糊，补出来不是素材的黑白框 → 视觉上=无边框。

#### 庄园秘境剖面
`[6px 出血白边] → [117px 粗黑带] → [39px 米底]`

117px 粗带不被 `_LINE_MAX_THICK=32` 判为线 → Profile 判废；落到旧路径（且旧路径 `(sx+sy)/2` 在 ROTATE_270 素材下误差 100%+，黑带 226px ≠ 素材 118px）→ 白线 + 黑带变细。

### 三处修复（core/lshape_border_route.py + core/lshape_border.py）

#### 修复 1：锚点对齐
- 跳过最外出血边/裁切边，锚点=第一个「近黑+低纹理」段（不限厚度）
- `_is_anchor_seg` 用 `_BLACK_MAX_CHANNEL=90`（1px JPEG 灰过渡段 max~116 被排除，混入锚点会让四边层序错位）
- 四边层序一致 → 投票颜色真实

#### 修复 2：层深截断到第二条细线
- 描边 + 色带 + 最外内框线 = 3 层封顶
- `_MAX_LAYERS 5→3`
- line#2 之前的非线段中丢弃花纹段（std≥_FIELD_STD_TOL），只保留紧邻锚点的第一个平整带 —— 避免左 2px 出血边 + 文字带均值污染中间层
- 无第二条细线时保留 锚点+紧邻平整带（克罗式 2 层）

#### 修复 3：庄园秘境粗黑带
- 分组时锚点（th>_LINE_MAX_THICK 的粗黑带）**独立成层**，不被紧随米底平均成灰糊
- 让位判定函数 `profile_yields_to_v13` 外移到路由层：V13 命中则用 V13，V13 未命中（庄园秘境内侧无主色带→v13=None）则 Profile 接管

#### 修复 4：几何均值 scale
- `sqrt(sx*sy)` 替代 `(sx+sy)/2`
- 对 adapt_pool_material 的 ROTATE_270 稳健（旋转后 sx/sy 互换但乘积不变）
- 修复庄园秘境黑带厚度

### 第二轮验证结果

| 素材 | 识别结果 | 关键指标 |
|---|---|---|
| 蔓生花 PSD | [黑10, 米285(246,232,205), 线25] → 3 层 | 色带颜色与素材一致，止于内框线 |
| 中古雨林 100x140 | [黑10, 白147, 线20] → 3 层 | ✓ |

- 端到端渲染三素材 L 角局部均正确：白线消除、黑边厚度一致、L 形框线连续转角
- 全量测试 **320 passed + 5 skipped**

## 关键设计决策

| # | 决策 | 理由 |
|---|---|---|
| 1 | `_is_anchor_seg`（近黑不限厚）与 `_is_line_seg`（深色+薄≤32）分离 | 锚点只管"最外起笔"，线只管"细分层"，各司其职 |
| 2 | 让位判定放路由（profile_yields_to_v13）而非 detect 内部返回 None | V13 未命中时 Profile 仍能接管（庄园秘境粗黑带） |
| 3 | `_TOTAL_DEPTH_RATIO 0.30→0.50` | 粗黑带 60/300 尺寸下 105>90 被误判为图案误检 |

## 工程约定沉淀

| # | 约定 | 违反后果 |
|---|---|---|
| 1 | L形 Profile Route 锚点与线判定分离：`_is_anchor_seg`（近黑不限厚）只管最外起笔，`_is_line_seg`（深色+薄≤32）只管细分层 | 粗黑带素材（庄园秘境）被判废，落到旧路径产生白线和黑带变细 |
| 2 | 让位判定放路由层（profile_yields_to_v13）而非 detect 内部返回 None | V13 未命中时 Profile 无法接管，粗黑带素材无 L 形效果 |
| 3 | 几何缩放用 `sqrt(sx*sy)`（几何均值）而非 `(sx+sy)/2`（算术均值） | ROTATE_270 素材下算术均值误差 100%+，黑带厚度不对 |
