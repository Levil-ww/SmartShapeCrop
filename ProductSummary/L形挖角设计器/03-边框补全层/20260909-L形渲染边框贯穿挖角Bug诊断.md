# 2026-09-09：L形挖角渲染边框贯穿挖角 Bug 诊断

## 概述

用户反馈简织草图 L 形挖角"没有保持原本素材的边框，在里面色带部分加了一个L形黑边，导致挖角也没有挖干净，左下角还有色带残留，挖角部分应该是空白的，还有最外层的完整的黑边"。

经像素级比对定位，根因在 `core/lshape_border_route.py:441 _fill_layers_vertical_horizontal`：当某层累计厚度 offs[k] >= yc 时，y_lo 回退到 0，导致该层从画布顶端一直画到 yc，贯穿整个 L 形垂直切边。

当前 simplify 案（cut_h=22.5cm）因总厚度仅 181px 未触发；小切角（8cm 以下）或厚边框素材会触发。

***

## 问题描述

### 用户反馈
> "它没有保持原本素材的边框，在里面色带部分加了一个L形黑边，这就导致L形挖角也没有挖干净，左下角还有色带残留，挖角部分应该是空白的，还有最外层的完整的黑边"

期望：挖角区域纯白 + 完整外框 + 三个 cell 完整保留

### 像素级比对定位

对比两张输出图（均为 1920x1033，设计 124.8x66.7cm 横版）：

| 项 | 正确图（img1） | 错误图（img2） |
|---|---|---|
| bottom 黑色位置 | Y=1032，黑色只在外框 (左/右/底) | 底部完整画了 [0, 1918] 黑色 |
| 垂直黑色窄带 | 无 | X=[714,716] 有黑色窄带，纵向 Y=[672, 1017]，贯穿整个挖角 |

错误图中"L 形金/黑边贯穿挖角"——边框层没有在切边处停止，而是延伸进了挖角区域。

***

## 根因定位

### 代码位置
`core/lshape_border_route.py:441 _fill_layers_vertical_horizontal`

### 问题逻辑
当某层的累计厚度 `offs[k] >= yc`（切角高度）时，`y_lo` 被回退到 0 → 该层从画布顶端（y=0）一直画到 yc，**贯穿整个 L 形垂直切边**。

这就是错误图里"垂直黑色窄带贯穿挖角"的直接成因。

### 复现条件
- 任意层的累计厚度 ≥ cut_h 时触发
- 当前 simplify 案（cut_h=22.5cm = 1329px）+ 3 层总厚 181px **不会触发**
- **较小切角**（如 8cm 以下）或**厚边框素材**（边框 band 较厚）会触发
- 用户实际跑的"错误图"为某版本/配置下的输出（dpi ~152 或不同 margin）

### 类似风险
`_fill_vertical_horizontal`（`core/lshape_border.py:952`）也有类似问题：水平切边 `b[yc:yc+edge, xc:W]` 也可能穿越。

***

**结论**：程序当前对 simplify 案已正确；其他子 bug 还需要小切角场景进一步复现。

## 修复方案（建议，待执行）

### 修复 1：垂直切边（_fill_layers_vertical_horizontal）
把 offs[k] >= yc 时的 y_lo 回退到 0 改掉：超出 cut 高度的层就不画（裁掉多余深度）。

```python
# 修复前：offs[k] >= yc 时 y_lo = 0，导致从顶端贯穿
# 修复后：offs[k] >= yc 时该层跳过（或从 yc 处开始画）
```

### 修复 2：水平切边（_fill_vertical_horizontal in lshape_border.py）
水平切边 `b[yc:yc+edge, xc:W]` 也需要类似处理，防止边框层穿越挖角区域。

### 验证标准
- 挖角内不应该有任何边框层（必须等到切边处才上色）
- 外框完整保留
- 小切角（<8cm）场景下无贯穿
- 厚边框素材无贯穿
