## 任务二：代码质量健康度排查（P0-P3优先级）

### 排查范围
全项目 Python 源码（`core/`、`gui/`、`main.py`、`process_image.py` 等）

### 子问题1：静默异常吞噬（24+处，P0级）
- **问题描述**：24处以上 `except:` 无日志、无堆栈、无返回值标记的空捕获块，生产环境故障排查近乎失明。
- **典型模式**：
  ```python
  try:
      some_risky_operation()
  except:          # ← 吞噬一切，不留痕迹
      pass
  ```
- **修复建议**：
  1. 捕获具体异常类型（禁止裸 `except:`）。
  2. 至少写入 `logger.exception(...)` 记录堆栈。
  3. 返回明确的失败哨兵值（None / False / Error对象），供上层感知。

### 子问题2：Image.open() 资源泄漏风险（5处，P0级）
- **问题描述**：5处 `Image.open(...)` 未使用 `with` 上下文管理器，处理大批量图像时可能累积句柄泄漏，触发OOM或句柄耗尽。
- **典型模式**：
  ```python
  img = Image.open(path)   # ← 无 close，依赖GC回收
  result = img.resize(...)
  return result
  ```
- **修复建议**：
  ```python
  with Image.open(path) as img:
      result = img.resize(...)
      return result.copy()   # 确保脱离上下文仍可用
  ```

## 任务三：圆角右上/右下角可见白竖线修复

### 目标案例
| 案例 | 规格 | 关键问题 |
|------|------|----------|
| 用户测试用例 | 89×65cm，TL=6.5, TR=2, BL=3, BR=15cm | 右上角、右下角与外米色框交界处可见白色竖线（漏色） |

### 根因分析
**PIL `ImageDraw.pieslice` 光栅化精度缺陷**：
- 在右边界/下边界像素位置，pieslice 会**过度绘制**0~0.5px的像素（距离略大于R的像素被误填），这些像素在视觉衔接处与米色外框对比形成白边。
- 同时 `geometry.py` 中 `apply_rounded_corners_to_mask` 传入 float 坐标，十进制截断导致左右不对称泄漏。

### 修复方案（三层防线）
1. **像素对齐整数化**（`geometry.py` `apply_rounded_corners_to_mask`）：
   - Rect坐标强制转换为像素对齐的int，消除小数截断导致的不对称。

2. **严格距离裁剪后处理**（`corner/algorithm.py` `carve_corner_on_mask`）：
   - pieslice绘制后追加 numpy 二次校验：对所有已填像素，若 `dx² + dy² > R²` 则立即清零，消除过绘。

3. **有效边界裁剪**（同上）：
   - 用 `rect_bounds` 裁剪扇形结果，禁止超出合法区域的延伸。

- **验证**：用户指定参数（89×65cm，四角落混合半径）下，白竖线100%消除，圆角一致性保持。

## 任务四：圆角内部黑线（C形缺口/锯齿/延伸刺）全面修复

### 目标案例
| 案例 | 规格 | 关键问题 |
|------|------|----------|
| 用户测试用例（多角落） | 与任务三相同 | 除右下角外，其余三个角落内部可见黑色线条/锯齿/毛刺，风格与右下角的干净圆润不一致 |

### 子问题1：PIL pieslice 光栅化不精确 → C形缺口 + 锯齿
- **根因**：pieslice 是基于扫描线的离散近似，对大半径（≥9cm）会漏掉边界像素，而对某些角度又多绘，形成不规则C形缺口与锯齿状边缘。
- **修复**：**彻底替换 pieslice**，在 `carve_corner_on_mask`（`corner/algorithm.py`）中改用 **numpy 距离场法**——
  1. 在每个角落ROI上构造网格坐标 `(dx, dy)`。
  2. 距离判别：`dx² + dy² ≤ R²` 的像素标记为扇形内，逐像素数学精确。
  3. 保留 `validity_mask` 与 `rect_bounds` 裁剪，避免透明区重着色。

### 子问题2：形态学腐蚀制作10px黑边 → 135°对角延伸刺
- **根因**：`scipy.ndimage.binary_erosion` 的结构元素（正方形/十字形）在90°转弯处，沿45°对角线方向会产生约14px的"毛刺"（延伸刺），叠加在圆角弧线内部形成可见黑线。
- **修复**：**彻底替换形态学腐蚀**，在 `image_ops.py` Step 3.5 边框绘制中改用 **scipy 距离变换（EDT, Euclidean Distance Transform）**——
  1. 对内孔 mask 执行 EDT：每个像素取其到最近 mask 外像素的欧氏距离。
  2. 精确阈值化：`0 < dist ≤ 10` 的像素即构成**精确等宽10px**的黑边环。
  3. EDT天然具有各向同性，45°方向与0°/90°方向完全等宽，无延伸刺。

### 验证结果
- 四个角落视觉完全一致：弧线均匀、无黑线、无锯齿、无延伸刺。
- 10px黑边宽度：对角线方向实测为精确10px（误差<1px）。
- 109项回归测试通过，其他功能无影响。

## 经验教训
1. **PIL pieslice不适合高精度圆角需求**：对视觉衔接要求高的场景（如圆角外贴米色边框），pieslice的0~0.5px过绘/漏绘会形成可见瑕疵，应直接使用**距离场数学判别法**。
2. **形态学腐蚀≠精确等宽边界**：腐蚀操作在45°对角线处必然产生延伸刺（结构元素各向异性），凡要求精确像素等宽边界的场景，必须使用**EDT距离变换**。
3. **ROI优化必须做端到端坐标一致性审计**：global坐标与roi坐标混用是常见Bug源头，建议统一命名规范（`g_x`/`l_x`前缀）并加单测覆盖。
4. **后台线程是GUI应用的基本底线**：凡>500ms的操作都应丢入Worker Thread，否则用户体验严重下降（界面假死+误触发重复操作）。
5. **静默异常吞噬是技术债的天花板**：24+裸except意味着生产环境几乎无法定位故障，应列入下一迭代P0级技术债回补。
6. **Image.open()的with习惯**：Python Image对象的底层文件句柄不会被GC立即回收，大流量场景下极易触发OOM，建议用静态检查规则（如ruff S101变体）强制约束。
