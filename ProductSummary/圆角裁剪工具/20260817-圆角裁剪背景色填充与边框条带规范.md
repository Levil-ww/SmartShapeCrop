## 问题一：圆角裁剪后内层区域出现白色而非原图背景色（16:14）

### 现象
| 模板 | 原图背景色 | 圆角裁剪后（错误） |
|---|---|---|
| 花幔 | 米色 | ❌ 内层角落出现白色像素块 |
| 墨上花开 | 奶油色 | ❌ 内层角落出现白色像素块 |
| 中古花园 | 浅米色 | ❌ 内层角落出现白色像素块 |

白色像素集中在圆角弧线无法切入的内层角落区域（L形边框条带包围的角落）。

### 根因（双重叠加）

#### 根因1：结果图默认使用白色填充
裁剪mask为0（透明）的区域，默认填充`(255,255,255)`纯白。而实际上，原图的间隙颜色（边框层与内层花纹之间的空隙底色）才是正确的背景色。

#### 根因2：边框条带保护过宽（OR定义的副作用）
```
原边框条带定义（OR / 并集）：
左上角border_zone = 顶条(y≤T) ∪ 左条(x≤T)

后果：当圆角半径r较大（3-4cm）时，
圆角弧线的起点/终点仍被判定在border_zone内部，
→ 裁剪mask被border_zone保护而不切割，
→ 圆角弧线无法切入角落，
→ 内层角落残留大面积未切割区域，被填白。
```

实际上边框条带的目的是保护**边框本身**不被裁掉，但角落的**间隙区域**（非边框、非图案、纯背景色）应允许被圆角弧线切入。

---

### 修复方案（image_cropper.py `apply_border_only_corners`函数）

#### 修复1：间隙颜色检测 + 作为填充色

```
间隙颜色检测逻辑：
1. 采样区域：外框内侧0.5cm × 边框外侧0.5cm的环带（排除纯黑边框像素和花纹像素）
2. 聚类取众色：K-means K=3对采样像素聚类，取最大类的平均RGB值作为间隙颜色(gap_color)
3. 填充：结果图mask=0区域，用gap_color填充，而非纯白(255,255,255)
```

典型模板gap_color检测结果：
| 模板 | gap_color(RGB) | 颜色名称 |
|---|---|---|
| 花幔 | (248, 240, 225) | 米色 |
| 墨上花开 | (250, 245, 230) | 奶油色 |
| 中古花园 | (246, 241, 228) | 浅米色 |

#### 修复2：用XOR替代OR定义边框条带

```
新边框条带定义（XOR / 异或，精确保护边框本身）：
左上角border_zone = [顶条(y≤T) ∪ 左条(x≤T)]  XOR  [角落方块(x≤T 且 y≤T)]

直观理解：
- 保留顶条水平段和左条垂直段（即L形的两条边）
- 移除两条边重叠的角落方块区域（即x≤T且y≤T的正方形）

效果：
- 边框本身（水平条+垂直条）仍被保护，不会被圆角裁切穿
- 角落方块区域（间隙色背景）解除保护，允许圆角弧线切入
- 弧线正确切入角落，消除大面积未切割白色残留
```

#### 修复3：边框厚度合理性检测（防误检测保护）

当检测到的总边框厚度 > min(宽,高)的20%时，判定为"边框检测错误"（把花纹误识别成了边框层），此时：
- 不启用边框条带保护（border_zone整区域置为False）
- 按普通全图圆角方式裁剪，避免过宽的border_zone把整个画面都保护起来

典型误检测场景：边框检测深度8-12cm（实际边框仅2-3cm），此时如果启用保护，圆角完全切不动。

## 问题二：裁剪区域填充色规范为白色 + 圆角半径与边框线规范（16:45）

### 用户新规范
经过设计评审，用户调整了圆角裁剪的输出规范：
1. **被裁区域背景色统一为白色**：与设计软件（CAD/PS）导出的裁切区域背景保持一致，不再使用原图间隙色
2. **圆角半径判断条件调整**：corner_protect触发阈值从「半径 ≤ 2×总边框厚」放宽为「半径 ≤ 4cm」，简化规则，便于现场操作
3. **直角边框线和正方形保留**：非圆角区域，边框线为纯黑且线宽精确匹配原始检测厚度；正方形产品不做任何圆角处理

### 调整后的规范速查表

| 圆角半径r | 处理模式 | 说明 |
|---|---|---|
| r = 0cm | 完全不做圆角 | 四角直角，边框线原始厚度不变 |
| 0 < r ≤ 4cm | **边框专属圆角模式** | 圆角仅作用于外层边框区域（L形边框条带），内层花纹保持直角 |
| r > 4cm | **全图圆角模式** | 圆角贯穿裁切整个图（含边框+内层花纹+间隙），所有层统一按圆角半径切割 |

内层被裁的间隙区域填充色：**统一白色(255,255,255)**

---

### 修复（image_cropper.py + sector_render.py）

| 修改点 | 说明 |
|---|---|
| 结果图填充色 | 恢复为`(255,255,255)`纯白，不再使用gap_color |
| corner_protect阈值条件 | `r <= 2 * total_border_depth` → 简化为 `r <= 4.0` |
| sector_render边框重绘深度限制 | 边框专属模式下，重绘深度精确限制为原始检测到的边框厚度px值，避免超范围绘制 |
| 正方形产品跳过圆角 | 宽高相等且差≤0.5cm时，直接返回原图，不执行任何圆角处理 |

---

- 墨上花开（2.5cm→边框专属模式）：同上规范 ✅

## 经验教训
1. **背景色规范需用户确认**：技术上"保持原图间隙色"更连贯，但用户设计流程要求"与CAD/PS一致用白色"——技术决策不能替代产品规范，需提前确认
2. XOR边框条带是精确切割的精巧设计：OR保护过度（角落方块也保护了），XOR恰好只保护L形边框本身，是解决"圆角切不进角落"的关键
3. **阈值应简单可理解**：「r≤2×边框厚」对操作人员太抽象（需知道边框厚才能判断行为），简化为「r≤4cm」更直观易用，现场培训成本低
4. **间隙色检测逻辑不应删除**：虽然本次恢复了白色填充，但间隙色检测代码仍保留（注释开关），未来用户如再次改回"保持原图色"可快速切换
5. **设计规范变更需全链路同步**：填充色从gap_color改白后，需同步更新所有测试用例的预期输出（119个用例的参考图需重新生成或手动复核），避免测试误判为失败
