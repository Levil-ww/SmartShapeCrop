## 问题一：4设计v9版本源感知匹配重构（09:06）

### 现象
4个设计出现不同问题：
| 设计 | 问题 |
|---|---|
| 闲叙青釉 | 矩形区域出现多余弧线 |
| 婉卉 | 多余白色弧线 |
| 中古花园 | 角落线条过粗，与原边框不一致 |
| 玛利亚玫瑰 | 红色矩形区域出现四分之一扇形角 |

### 根因
1. `CORE_BORDER_DEPTH`机制无条件绘实心边框，导致矩形区域也出现弧线
2. 边框层匹配无源感知，无法区分真实边框层和装饰层
3. 容差和角度匹配不够精确

### 修复（sector_render.py `_redraw_border_on_corner`函数）
| 修复项 | 说明 |
|---|---|
| 删除CORE_BORDER_DEPTH机制 | 移除无条件绘实心边框逻辑，改用源感知匹配 |
| 源感知匹配 | BORDER_SIGMA = 相邻层最小距离 + 25，动态识别真实边框层 |
| R+2容差 | 圆角半径匹配容差为R+2，精确匹配目标圆角层 |
| 角度±1.5°强制匹配 | 角度差异在±1.5°内强制匹配，避免漏匹配 |
| beyond_arc阈值 | beyond_arc清底阈值为R-0.5，精确控制清底范围 |

### 验证
200项测试通过（17项历史基建缺陷，非本次引入） ✅

## 问题二：v9补充修复 - beyond_arc清底限制（09:22）

### 现象
v9版本中beyond_arc清底范围无约束，导致直边像素被误判为需要清底的区域；内层也被错误绘制。

### 根因
1. `beyond_arc`清底时无validity_arr限制，清底范围超出圆角区域
2. 内层（color_idx≥1）不应绘制，但未被跳过

### 修复（sector_render.py）
| 修复项 | 说明 |
|---|---|
| validity_arr限制清底 | beyond_arc清底范围受validity_arr限制，仅在有效圆角区域内清底 |
| 内层跳过绘制 | 内层color_idx≥1时跳过绘制，避免多余弧线 |

### 验证
直边区域无多余弧线，内层无错误绘制 ✅

## 问题三：婉卉白色弧形色差校验（09:31）

### 现象
婉卉设计在圆角处理后出现白色弧形线条，抗锯齿深棕色过渡像素被误判为间隙层。

### 根因
婉卉素材底色为奶白色，与纯白背景色接近。抗锯齿产生的深棕色过渡像素在颜色距离判定中被误判为间隙层（非边框色、非背景色），触发间隙清扫逻辑导致白色弧线。

### 修复（sector_render.py）
引入欧式距离色差校验区分过渡/装饰色带与合法间隙层：

```
色差校验逻辑：
1. 计算像素与边框色的欧式距离
2. 若欧式距离 > 30 → 判定为过渡/装饰色带，不作为间隙层处理
3. 若欧式距离 ≤ 30 → 判定为合法间隙层，正常清扫
```

### 验证
婉卉白色弧形消除，过渡色带保留 ✅

## 经验教训
1. **源感知匹配优于无条件绘制**：删除CORE_BORDER_DEPTH无条件绘实心机制，采用BORDER_SIGMA（相邻层最小距离+25）的源感知匹配，能精确识别真实边框层
2. **beyond_arc清底必须受validity_arr限制**：无约束清底会误伤直边像素，必须限制在有效圆角区域内
3. **色差校验区分过渡色与间隙**：抗锯齿过渡像素（欧式距离>30）不应被当作间隙层处理，否则会产生白色弧线
4. **内层跳过绘制避免多余弧线**：内层color_idx≥1应跳过绘制，仅绘制最外层边框圆弧
5. **V1.0版本是最佳参考**：`SmartShapeCrop-单文件圆角裁剪设计V1.0版本`的简洁直接绘制策略是圆角裁剪的最优实践
