> 两轮实施：架构审查 + 4 项快速收益优化 + 3 项 P0 工程化基础修复

## 一、项目概况

SmartShapeCrop 是面向印刷级图片裁剪的桌面工具（PyQt5 + PIL + numpy + psd-tools），核心业务是带圆角的水池裁剪设计（双面格定制产品等），功能包含：
- **圆角裁剪工具（GUI）**：上传 → 文件名自动解析（尺寸/圆角/方向）→ 模板库匹配 → 手动调整 → 预览 → 导出 JPG
- **水池设计器（GUI）**：画布尺寸/DPI → 多层边框（宽度/颜色/深度偏移/圆角）→ 内部形状（矩形/椭圆/L形挖洞）→ 图片贴附
- **独立批处理脚本**：`process_image.py` 硬编码参数批处理圆角裁剪

代码规模：~4500 行 Python（核心 4 模块 2800 行 + GUI 2 模块 1600 行），30+ 测试脚本。

## 二、问题分析（第一轮审查）

### 2.1 严重问题

| 编号 | 问题 | 风险等级 | 说明 |
|------|------|---------|------|
| P1 | **圆角算法5份重复** | 🔴 高 | `apply_rounded_corners` / `apply_border_only_corners` / `_carve_L_corners_on_mask` / `_layer_rounded_mask_arr` / `geometry.apply_rounded_corners_to_mask` 各自实现"挖正方形+填1/4圆"两步法，任一修改必不一致 |
| P2 | **死代码含 bug** | 🔴 高 | `_extend_border_to_arc` 第 699 行 `w, h = result_img` 是错误解包，一旦调用立即崩溃 |
| P3 | **两套边框检测参数不一致** | 🟠 中 | `_detect_border_layers` 阈值=15，`_scan_edge_boundaries` 阈值=25，同图可能检测出不同结果 |
| P4 | **常量散落 + 魔法数字** | 🟠 中 | DPI=300（CropConfig/脚本）vs DPI=150（UI/CropDesign）；`+1.0` 切割损耗散落在 cropper_panel 5处；8.5/1.5/2.0 阈值散落 |
| P5 | **调试 print 污染** | 🟡 低 | name_parser 15处、psd_loader 2处 生产路径 print 无法关闭 |

### 2.2 工程化缺失

| 编号 | 缺失项 | 后果 |
|------|--------|------|
| E1 | **无 pytest 单元测试** | 核心算法（圆角角度、尺寸小数解析、阈值切换）零覆盖，全靠肉眼 PNG 对比，无法回归 |
| E2 | **无统一配置模块** | 常量散落导致不一致，DPI 是典型案例 |
| E3 | **无结构化日志** | 调试用 print 不可控，生产环境无日志追溯 |
| E4 | **无 lint/format/type check** | 编码规范缺失，`except Exception:` 静默吞错 10+ 处 |
| E5 | **依赖版本未锁定** | requirements.txt 仅 `>=` 约束，无 pyproject.toml |

### 2.3 性能隐患

- `_detect_border_layers` Python 逐像素循环，300 DPI 下 55×41cm ≈ 3140 万像素时非常慢
- `apply_multi_layer_rounded_corners` 每层生成全图 mask，无 ROI 限制
- 大图渲染时 UI 主线程卡死（无 QThread/进度条）

### 受环境限制未完成

**系统 PowerShell 执行策略 = Restricted**，导致所有 RunCommand 失败（连最基础的 `Get-ChildItem` 都被包装成 .ps1 脚本加载，包括 `Set-ExecutionPolicy` 本身，形成死锁）。因此：

- ❌ 无法运行 `python -m pytest tests/ -v` 拿到用例通过率
- ❌ 无法运行 `py_compile` / 导入自检脚本

### 手动运行步骤（需要用户操作）

```powershell
# 1. 在 Trae 外部（Windows Terminal / PowerShell）解除执行策略限制（只需一次）
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

# 2. 重启 Trae 会话后，在项目目录运行测试
cd d:\SmartShapeCrop
pip install pytest  # 如未安装
python -m pytest tests/ -v

# 3. 调试时开启详细日志
$env:LOG_LEVEL="DEBUG"
python main.py
```
