# 圆角裁剪四角边框弧线白色空隙修复 — 验证报告

- **日期**：2026-09-07
- **修复文件**：`core/corner/sector_render.py`（`_redraw_border_on_corner` 中的 `near_edge` 判断）
- **验证人**：AI 辅助 + 用户反馈

---

## 一、问题描述

用户反馈：圆角裁剪工具对图片进行圆角处理后，**右下角（br）的边框弧线出现白色空隙**，而左下角（bl）的边框弧线处理正确。同一张图、同一圆角半径，不同角的处理结果不一致。

现象截图特征：右下角圆角弧线与直边边框衔接处出现白色三角/楔形区域，应为边框色的像素被白色背景取代。

---

## 二、根因分析

### 2.1 定位过程

通过排查 `core/corner/sector_render.py` 中 `_redraw_border_on_corner` 的内容保护逻辑，发现 `near_edge` 变量的计算存在**角位置不对称**缺陷：

```python
# 修复前（有 bug）
near_edge = (xx <= float(total_border_depth) * 1.5) | (yy <= float(total_border_depth) * 1.5)
```

该判断硬编码为检查 ROI 的**左边缘**（`xx <= T`）和**上边缘**（`yy <= T`），仅对 **tl（左上）** 角正确——因为 tl 角的两条直边正好在左、上两侧。

### 2.2 四角直边位置对照

| 角 | 实际直边位置 | 旧代码检查的边缘 | 正确性 |
|----|------------|-----------------|--------|
| tl | 左、上 | 左、上 | ✅ 正确 |
| tr | 右、上 | 左、上 | ❌ 右侧错误 |
| bl | 左、下 | 左、上 | ❌ 下侧错误 |
| br | 右、下 | 左、上 | ❌❌ 两侧全错 |

### 2.3 量化错位程度

通过对 100×100 ROI、边框厚度 15px 的掩码统计：

| 角 | 过度保护像素 | 保护不足像素 |
|----|------------|------------|
| tl | 0 | 0 |
| tr | 1,771 | 1,771 |
| bl | 1,771 | 1,771 |
| br | **3,013** | **3,013** |

### 2.4 为什么 bl 看似正常而 br 严重

- **bl 角**：仅一侧（下边缘）判断错误，左侧边缘判断正确，内容保护部分生效，视觉影响较轻；
- **br 角**：**两侧边缘判断全错**，`near_edge` 覆盖到圆角内部区域，导致过渡区内的内容像素被错误「保护」（不绘边框色），露出底层白色背景 → 形成可见白色空隙。

### 2.5 机制解释

`near_edge` 用于控制「过渡区内容保护」：仅在靠近直边的过渡区保护内容像素（花纹/文字），圆角内部的过渡区必须绘制边框色。

旧逻辑对 br 角把保护区域错位到圆角内部，使得本应绘制边框色的内部过渡区像素被跳过，保留了底层白色背景，从而产生白色空隙。

## 三、修复方案

### 3.1 修复内容

将 `near_edge` 改为**角位置感知**，与 `core/image_cropper_mask.py` 中 `_build_multi_layer_corner_mask` 的 `border_zone` 逻辑保持一致：

```python
# 修复后（角位置感知）
_T = float(total_border_depth) * 1.5
if corner_key == 'tl':
    near_edge = (xx <= _T) | (yy <= _T)
elif corner_key == 'tr':
    near_edge = (xx >= roi_w - 1 - _T) | (yy <= _T)
elif corner_key == 'bl':
    near_edge = (xx <= _T) | (yy >= roi_h - 1 - _T)
else:  # br
    near_edge = (xx >= roi_w - 1 - _T) | (yy >= roi_h - 1 - _T)
```

### 3.2 设计原则

1. **单一真源一致性**：与 `border_zone`（`image_cropper_mask.py`）采用相同的角→边缘映射，避免两处逻辑分叉；
2. **ROI 坐标系闭合**：使用 `roi_w - 1` / `roi_h - 1` 闭区间端点，防止越界；
3. **最小改动**：仅修改 `near_edge` 一行逻辑，不触及边框绘制、间隙清理等其他流程。

## 七、追加修复（2026-09-07 第二轮）

用户反馈两个问题仍存在：
1. **蔓生花/素锦**：圆角边框外侧多了一层与边框贴合的深色弧形缺口线；
2. **南瓜无忧**：白色空隙未完全消除。

### 7.1 问题一：深色弧形缺口线（蔓生花/素锦）

#### 根因

`_build_multi_layer_corner_mask` 中 `ring_region` 保护像素到 `dist = r + 1.5`（弧线外侧），这些像素保留了原始深色边框色；但 Step A（`_redraw_border_on_corner`）只绘制 `dist <= r`，外侧保护像素未被重绘 → 弧线外侧残留深色弧形线。

#### 修复

**文件 1**：`core/image_cropper_mask.py` — `ring_region` 上界从 `r + 1.5` 收窄到 `r + 1.0`：

```python
ring_region = (angle >= ang_min) & (angle <= ang_max) & \
              (dist >= ring_inner_bound) & (dist <= float(r) + 1.0)
```

**文件 2**：`core/corner/sector_render.py` — 最外层（d=0）绘制扩展到抗锯齿边界：

```python
if d == 0:
    d_region = valid_region & (depth < d + 1) & (dist <= float(R_total) + 1.0)
else:
    d_region = valid_region & (depth >= d) & (depth < d + 1) & (dist <= float(R_total) + 1.5)
```

#### 验证

- 弧线外侧（`dist > r + 1.0`）深色像素数：**0**
- `(r, r+1.0]` 容差带内仅 198 个深色像素（边框边缘抗锯齿，正常）
- 四角对称性：✅

### 7.2 问题二：白色空隙（南瓜无忧）

#### 根因

`protect_content=True` 时，`inner_cut` 将 `border_zone` 内 `dist <= r` 的**所有**像素切白，包括超出边框厚度的内容像素。这些内容像素不在 Step A 的绘制深度范围内（`depth > total_border_depth`），无法被重绘 → 留下白色空隙。

南瓜无忧的深色纹理背景可能触发 `_corner_sector_has_content` 返回 `True`（纹理导致 `unique_colors >= 8` 或 `variance > 800`），从而进入保护模式。

#### 修复

**文件**：`core/image_cropper_mask.py` — `inner_cut` 仅裁切边框环带，不裁切内容区：

```python
border_ring_inner = max(0.0, float(r) - float(raw_depth) - 2.0)
inner_cut = (dist <= r) & border_zone & (dist >= border_ring_inner)
```

仅裁切 `dist` 在 `[r - raw_depth - 2, r]` 的边框环带，内容区（`dist < r - raw_depth - 2`）保持直角不被切白。

#### 验证

- 强制 `protect_content=True`，内容区（`dist <= r - raw_depth - 5`）白色像素数：**0**
- 边框弧（`dist` 在 `[r - raw_depth, r]`）深色像素占比：**100%**
- 四角对称性：✅
