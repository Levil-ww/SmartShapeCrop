## 1. 需求映射与草图真值

### 1.1 示意图规格

草图标注真值为画布 185×88 cm；中心矩形洞 80×60 cm，左/右/上/下边距分别为 45/60/10/18 cm。程序输出沿用既有 1cm 损耗补偿：画布输出 186×89 cm，中心洞输出 81×61 cm，边距和挖角尺寸不变。外轮廓在一个角位形成标准单边 L 形。L 形角位允许左上（tl）、左下（bl）、右上（tr）、右下（br）。**本版支持 1–4 角**（多角），中心洞为**单洞**。

### 1.2 草图数值读数

| 标注 | 值 | 语义 |
|---|---|---|
| 185 / 88 | 185 × 88 cm | 草图外框宽 / 高 |
| 35 / 10（右上示例） | 35 × 10 cm | 角部挖角 宽 / 高（多角时每个角一组） |
| 80 / 60 | 80 × 60 cm | 草图中心洞 宽 / 高 |
| 左45 / 右60 | 45 / 60 cm | 洞的左 / 右边距 |
| 上10 / 下18 | 10 / 18 cm | 洞的上 / 下边距 |

### 1.3 数值自洽验算

```
横向：45 + 80 + 60 = 185 ✓   （草图外框宽）
纵向：10 + 60 + 18 =  88 ✓   （草图外框高）
```

程序输出补偿后的自洽关系为：`45 + 81 + 60 = 186`、`10 + 61 + 18 = 89`。

> 这是复合形状相比纯 L 形的关键优势：多出 2 个**强等式约束**（`ml + hole_w + mr == outer_w` ∧ `mt + hole_h + mb == outer_h`），OCR 误识更易被检出并回退到几何值，直接降低草图识别阶段风险。

### 1.4 形状公式

```
KEEP = Rect(outer_w × outer_h) − Σ CutRect(corner, w, h) − Hole(hole_w × hole_h, 带圆角)
```

| 区域 | x 范围 | y 范围 |
|---|---|---|
| 外框 | 0 – 185 | 0 – 88 |
| L 挖角（示例 tr） | 150 – 185 | 0 – 10 |
| 中心洞 | 45 – 125 | 10 – 70 |

**两个直接影响实现的几何事实**

1. **洞与挖角不相交、也不相邻**——挖角下沿 `y=10` 与洞上沿 `y=10` 恰好共线，但 x 区间相隔 25 cm 实心带。POC 实测：重叠 0 像素，1px 膨胀后相邻像素仍为 0。→ 10px 黑框必须**分形状各自绘制后 OR 合并**，**不能**用"整体 union 再内缩"。
2. **挖角整体落在右边距环带内**（挖角 x 起点 150 > 洞右边界 125）。→ 挖角只从"外框环带"上削掉一块，不侵入洞附近材料，几何耦合度低。

### 1.5 与现有三种模式的关系

| 现有模式 | 几何操作 | 与综合形状的关系 |
|---|---|---|
| `rect_hole` | 矩形 − 中间洞 | 提供 **洞** 这一半 |
| `rect_lshape` | 矩形 − Σ角部矩形（≤4） | 提供 **挖角** 这一半 |
| `ellipse_hole` | 矩形 − 椭圆 | 无关，独立入口 |
| **`rect_lshape_hole`（新增）** | 矩形 − Σ角部矩形 − 单中间洞 | = 前两者的**组合** |

## 2. 可行性结论

**可行。** 已有零改动 POC 实测证实：在现有几何原语上纯组合即可实现，集合代数 4 项恒等式精确成立（见 §10）。

**但"可行"不等于"零改动"**。早期短报告曾主张"无需更换数据模型、现有实现可直接复用"——该判断不成立，原因如下（详见 §12 修正说明）：

1. `mode` 是互斥枚举（[geometry.py:162](file:///f:/SmartShapeCrop/core/geometry.py#L162)、[:274](file:///f:/SmartShapeCrop/core/geometry.py#L274)），渲染入口是 `if/elif/else` 三分派（[image_ops.py:1557](file:///f:/SmartShapeCrop/core/image_ops.py#L1557)），**物理上不可能**靠"同时设两个 mode"实现复合。
2. 历史 `rect_lshape` 语义是"外框与内洞**共用 L 形掩膜**"（[design_model.py:183-184](file:///f:/SmartShapeCrop/models/design_model.py#L183) 强制 `pool_hole_transparent=True`），不是示意图要的"外 L + 中矩形洞"。
3. 全工程 19 处 `mode ==/!= 'rect_lshape'` 硬判断（含 3 处 `!=`，仅搜 `==` 会漏），必须四类分治而非批量替换。

**正确路径**：新增 `mode='rect_lshape_hole'` + `build_composite_mask()` + 19 处四类分治 + 新 `composite_sketch_parser.py` + G1 闸口扩展 + 独立面板（D1）。预计 **10–16 个工作日**（含 D2 洞填素材 +1–2 天、D1 独立面板 +1–2 天）。

### 4.1 为什么选 B 而非 C

D1 已选定 B。相比 C（L 面板内加勾选），B 的代价是多 1 天外壳工作 + 线程退役接线，但收益是：

1. **UI 清晰度**：复合草图有 10 个标注，独立入口避免 L 面板（已 1036 行）进一步拥挤。
2. **G1 闸口不必双模态化**：独立面板下识别分支无需在"L-only / L+洞"之间分叉。

#### B. 生成路由的守卫顺序（一个易错点）

复合路由分支**必须放在 `_pool_worker.isRunning()` 忙碌护栏之前**：若放之后，上一次水池渲染还在跑时点复合「生成预览」会被「⏳ 正在处理中，请稍候…」挡掉，且用户无从知道该等的是什么。当前顺序 = **先判模式改道、再判忙碌**，复合生成不受水池 Worker 占用影响。

## 7. 关键实现要点（签名级）

### 7.1 几何层

```python
# core/geometry.py
COMPOSITE_MODE = 'rect_lshape_hole'
LSHAPE_LAYOUT_MODES = frozenset({'rect_lshape', COMPOSITE_MODE})   # 类① 判断统一入口

def build_composite_mask(
    size: tuple[int, int],
    outer_rect: RectShape,                    # L 形板 = 整幅画布（不是 inner_rect！）
    cuts: list[tuple[str, float, float]],     # 1–4 角（D3：多角）
    hole_rect: RectShape,                     # 单洞（D3：不支持多洞）
    hole_corners: dict[str, float],
    outer_corners: dict[str, float],
) -> np.ndarray:
    """KEEP = L形(outer_rect, cuts) − 洞(hole_rect, 带圆角)，返回 bool mask。"""
```

> ⚠️ **最易写错**：现有 `rect_lshape` 把 `inner_rect` 当作 L 形外轮廓（边距被强制为 0，两者相等）。复合模式下 **L 形外轮廓必须是 `outer_rect`**，`inner_rect` 改为表示洞。**两处基准矩形互换**是本次改造最易出错的地方。推荐为复合模式新增独立 `hole_rect` 字段而非重载 `inner_rect`，避免旧路径污染。

### 7.2 渲染管线
