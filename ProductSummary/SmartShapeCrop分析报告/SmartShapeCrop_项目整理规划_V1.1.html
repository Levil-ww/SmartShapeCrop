3问题清单

P1 — 必须处理

01 · .workbuddy/ 81.9 MB 被 Git 追踪P1

工具数据目录整体进了版本库，是 .git 膨胀到 119 MB 的直接原因。明细： wheels_backup/ 54.3 MB（PyQt5 的 whl 备份）、tmp_samples/ 27 MB（e2e 与 colorfix 临时样本图）。

处理：D 档 git rm --cached .workbuddy/ + 补 .gitignore。不重写历史，已入库 blob 需 git gc 释放。
02 · 归档图片仍在库内，_archive/ 规则失效P1

.gitignore 第 37 行的 _archive/ 对已追踪文件无效，实测仍在库里的有： scripts/_archive/test_cropper_output/ 13 张图 4.74 MB、 scripts/diagnose/_archive/output_images/ 38 张图 0.43 MB、 ProductSummary 配图 1.16 MB。共 94 个疑似误追踪文件，88.1 MB。

处理：D 档对这些路径执行 git rm --cached（只动索引，工作区文件保留）。
03 · ProductSummary 双维度目录打架P1

154 个文档由两套正交的分类体系平级混放：按模块（水池设计器 86 / 圆角裁剪工具 26 / L形挖角设计器 11 / 分析报告 20） 与按日期（2026-08 / 2026-09，共 11 份月度横向总结）。新文档往哪放没有唯一答案，这正是目录持续变乱的根因。

处理：C 档统一定为「模块为主 + 月度总结单列子目录」，需你先拍板用哪种。

6执行顺序与回滚保障

  1. 快照基线 —— 记录当前 git status --short 与 git rev-parse HEAD， 导出完整文件清单存进 _archive/ 作为可追溯底稿。
  2. A 档执行 —— 先 ls -1 列出待删清单核对无误再删；空目录用 rmdir（非空会失败，天然防护）。 dist/ 与 scripts/_archive/ 一律跳过。
  3. B 档归档 —— 全部用 mv，跨目录时把原路径编进文件名； 随即改写 README 索引与 html 的 src= 图链。
  4. 四项完整性验证 —— ① git diff --stat HEAD -- core gui tests main.py 必须为空（源码零改动证据） ② ast.parse 全量语法校验（不用 py_compile，避免重新生成刚清掉的 pyc） ③ PYTHONDONTWRITEBYTECODE=1 QT_QPA_PLATFORM=offscreen 下模块导入冒烟 ④ 体积与 git status 复核。
  5. 出报告交付你核对 —— 完整变更清单 + 回滚命令，你确认后这一轮才算收尾。
