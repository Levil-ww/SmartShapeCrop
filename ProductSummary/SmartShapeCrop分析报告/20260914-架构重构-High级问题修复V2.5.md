## 四、三项重点改动详解

### 4.1 H-13｜新增 `LShapePanelBridge` 信号桥接适配器

**这是本次唯一新增的源文件**（54 行），也是当日架构层面最有前瞻价值的产物。

**问题**：`LShapePanel` 对外暴露 **13 个细粒度信号**（`sketch_*` / `target_*` / `lshape_*`），`PropertyPanel.set_lshape_panel()` 需要逐一连接，对外契约过重。

**方案**：把所有信号翻译合并为统一的粗粒度信号：

```python
class LShapePanelBridge(QObject):
    lshape_action_requested = pyqtSignal(str, object)  # (action, params)

    def __init__(self, panel, parent=None):
        super().__init__(parent)
        self._panel = panel
        # (action 名, 参数个数)；0 = 无参信号
        _SIGNALS = (
            ('lshape_params_changed', 0),
            ('lshape_applied', 1),
            ('lshape_recognize_started', 0),
            ('lshape_recognize_finished', 1),
            ('sketch_pick_requested', 0),
            ('sketch_clear_requested', 0),
            ('sketch_view_requested', 0),
            ('sketch_load_requested', 1),
            ('target_changed', 1),
            ('target_pick_requested', 0),
            ('target_clear_requested', 0),
            ('generate_requested', 0),
            ('save_requested', 0),
        )
        for action, nargs in _SIGNALS:
            sig = getattr(panel, action)
            if nargs == 0:
                sig.connect(lambda a=action: self.lshape_action_requested.emit(a, None))
            else:
                sig.connect(
                    lambda *args, a=action: self.lshape_action_requested.emit(
                        a, args[0] if args else None
                    )
                )
```

**PropertyPanel 侧收敛**：原来 60+ 行的逐一连接代码，替换为 3 行：

```python
from gui.lshape_panel_bridge import LShapePanelBridge
self._lshape_bridge = LShapePanelBridge(panel, self)
self._lshape_bridge.lshape_action_requested.connect(self._on_lshape_action)
```

再新增 `_on_lshape_action(action, params)` 统一分派 —— 各分支调用**原有 handler / 委托方法**，行为与原逐一 `connect` **完全等价**。

**关键设计要点**：

- **`LShapePanel` 本身零改动** —— 所有信号定义、`emit` 点保持原样；桥接为**纯加法**、行为等价
- 这是「不改业务代码也能解耦」的典型手法，风险极低

### 4.2 H-10｜`DesignModel.apply_ui_snapshot()` —— Model 驱动组装

**问题**：`gui/property_panel_layers.py` 的 `_collect()` 直读 `SpinBox` / `ComboBox` / 颜色按钮组装 `CropDesign`，**业务规则（模式判断、素材同步、多洞几何重建）混入 UI 层**。

**方案**：UI 层只负责把控件当前值提取为**纯值 dict**（`snap`），业务规则全部集中在 Model 内执行。

`snap` 键约定（不含任何 UI 控件引用）：

```

outer_margin_cm
inner: {'top','bottom','left','right'}
lshape: {'corner','cut_w_cm','cut_h_cm'} 或 None
corners: {'tl','tr','bl','br'}
ellipse: {'rx','ry'}
colors: {'outer','hole'}
images: {'outer','hole'}（str 或 None）
text: {'enabled','text','font_size_px','color','mirror_bottom'}
hole_mode: 'blank'|'image'|None
multihole: {
    'active_count': int,
    'holes_w': [float], 'holes_h': [float], 'gaps': [float],
    'mt': [float|None]*n, 'mb': [float|None]*n,
    'ml': [float|None]*n, 'mr': [float|None]*n,
} 或 None
```

**副作用（已知新增债）**：`apply_ui_snapshot` 本身 **319 行**，成为当前超长函数 Top 3，需要二次拆分。这是 H-10 MVC 重构的合理副产物 —— 把散落在 UI 层的业务规则集中到一个地方，**集中后再拆比分散着拆安全**。

### 4.3 H-08｜缓存键加入内容指纹

**问题**：缓存键仅依赖 `mtime` —— 文件内容不变但 `mtime` 变化会失效、`mtime` 相同但内容变化**可能误用过期缓存**。

**方案**：引入**文件大小 + 前 64KB 的 sha256 摘要**作为缓存键补充：

```python
def _get_image_content_fingerprint(image_path: str) -> str | None:
    """[H-08] 图像内容指纹：文件大小 + 前 64KB 的 sha256 摘要。"""
    try:
        size = os.path.getsize(image_path)
        with open(image_path, 'rb') as f:
            head = f.read(64 * 1024)
        import hashlib
        digest = hashlib.sha256(head).hexdigest()
        return f"{size}:{digest}"
    except Exception:
        logger.debug("[_get_image_content_fingerprint] 忽略异常", exc_info=True)
        return None
```

**设计权衡**：只读**前 64KB** 而非全量 —— 避免大图（`蔓生花_full.jpg` 8268×4724）的全量读取开销。读取失败返回 `None`（**降级为仅 mtime**），保证不因指纹计算失败而破坏缓存功能。

两个缓存键函数同步改造：

```python
# _get_cache_key
-    return (image_path, mtime, round(target_w, 1), round(target_h, 1), _ALGO_VERSION)
+    fingerprint = _get_image_content_fingerprint(image_path)
+    return (image_path, mtime, fingerprint, round(target_w, 1), round(target_h, 1), _ALGO_VERSION)

# _get_consistent_cache_key
-    return (image_path, mtime, _ALGO_VERSION)
+    fingerprint = _get_image_content_fingerprint(image_path)
+    return (image_path, mtime, fingerprint, _ALGO_VERSION)
```

### 4.4 H-05｜`classify_gap_layers` 提取 5 个判定谓词

把内联 if 链改为**具名谓词函数**，每个谓词对应一条不变量（`INV-*`），可单独测试：

```python
def _is_innermost_layer(i: int, n: int) -> bool:
    """[INV-B4] 最内层 (i=n-1) → 实心（结构性不变量：间隙需要两侧边框夹住，最内层无内侧邻居）"""
    return i == n - 1

def _is_too_thick_layer(t: int) -> bool:
    """[INV-G2] 厚度 > GAP_MAX_THICKNESS → 实心（不可能是间隙）"""
    return t > GAP_MAX_THICKNESS_GLOBAL

def _is_outer_dark_layer(i: int, max_rgb: float) -> bool:
    """[INV-G1] 最外层(i=0) 深色边框 max(RGB) ≤ SENTINEL_OUTER_DARK_MAX_RGB → 实心（S-1 安全锚）"""
    return i == 0 and max_rgb <= SENTINEL_OUTER_DARK_MAX_RGB

def _is_sandwich_gap(i, n, d_left, d_right) -> bool:
    """中间层 (0 < i < n-1)：两侧都有邻居 AND 与两侧差异均 > GAP_NEIGHBOR_MIN → 间隙"""
    ...

def _is_outer_sentinel_gap(i, max_rgb, d_right, d_bg, d_content) -> bool:
    """sentinel 外层 (i=0)：浅色 AND 与下一层差异 > 阈值 AND (接近BG 或 接近内容) → 间隙"""
    ...
```

调用侧变为语义直读：

```python
# Step 1. [INV-B4] 最内层(i=n-1) -> 实心（结构性不变量）
if _is_innermost_layer(i, n):
    continue
# Step 2. 厚度太大 -> 实心
if _is_too_thick_layer(t):
    continue
# Step 3. [INV-G1] 最外层深色边框 -> 实心 (永不间隙)
if _is_outer_dark_layer(i, max_rgb):
    continue
# Step 4. 中间层 sandwiched -> 间隙
if _is_sandwich_gap(i, n, d_left, d_right):
    is_gap_layer[i] = True
    continue
```

**价值**：`classify_gap_layers` 的每条判定规则从「藏在 if 链里」变成「有名字、有不变量编号、可单独断言」—— 这是**把注释变成可执行契约**的典型重构。
