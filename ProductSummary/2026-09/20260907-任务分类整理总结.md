## 二、圆角裁剪仅外层边框圆角化（T1，上午）

### 问题
`apply_border_only_corners` 会沿圆弧重绘内层装饰/深色带，导致圆角处出现紧贴黑色外框的深色弧形；且当角外侧扇形被判断为纯色背景时，`_corner_sector_has_content` 返回 False 关闭保护，内层矩形框/装饰带也被圆角化，与"仅边框圆角"语义冲突。

### 修复（`core/image_cropper_border.py`）
1. `apply_border_only_corners` 的 Step A 调用 `_redraw_border_on_corner` 时传入 `only_outermost=True`，只补绘与最外层边框颜色接近的像素
2. 所有有效圆角统一启用 `protect_content=True`，不再依赖自动判断
3. `apply_rounded_corners` 保持 `only_outermost=False`，整体圆角仍重绘多层边框

### 验证
- `tests/core/test_image_cropper.py`、`tests/border/test_border_fix.py`、`tests/border/test_complex_pattern_safety.py` 通过
- 合成样例 `corner_outermost_demo.py`：仅最外层黑边圆角化，内层棕边保持直角

## 三、圆角白线与内层误圆角修复（T2，上午）

### 问题
1. 圆角接缝处出现竖向/横向白色细线（BR/TR 角 0°/360° 绕接处角度判定未包含边界像素）
2. 大半径（6.5cm）时内层花纹/文字带仍被圆角化，`apply_border_only_corners` 仍使用完整 `border_layers` 构建 mask，导致 border_zone 过宽

### 修复
1. `core/corner/algorithm.py`：新增 `_angle_in_corner_sector()` 统一处理 0°/360° 绕接
2. `core/image_cropper_mask.py`：移除本地 `_angle_in_corner_sector()`，改为从 `algorithm.py` 导入；`_post_cleanup_gap_regions` 也改用该 helper
3. `core/corner/sector_render.py`：`_redraw_border_on_corner` 的 `valid_angle` 改用 `_angle_in_corner_sector()`
4. `core/image_cropper_border.py`：`_redraw_outer_border_on_corners` 的 `in_angle` 改用 helper；`apply_border_only_corners` 仅用最外层边框层构建 mask / validity_mask / 重绘 / cleanup，`raw_depth` 也仅用最外层厚度

### 验证
- 全量相关测试通过（47 passed / 5 skipped）
- 合成样例 `large_radius_no_inner_round_demo.py`（1200×2100，r=6.5cm）：外层黑边圆角化、内层文字带保持直角、四个角无白线

## 四、圆角边界白线残留修复（T3，上午）

### 问题
用户反馈 TR/BR/BL 圆角边界仍有 1–2px 白色竖线/横线，TL 正常。

### 根因
`_build_border_paint_mask` 的角度容差 `tol=1.0` 与 `_redraw_border_on_corner` / `_redraw_outer_border_on_corners` 的 `tol=2.0` 不一致，导致边界像素在 validity_mask 中为 0 却被 redraw 判定覆盖，随后被 `beyond_arc` 误清成背景白色。

### 修复
`core/image_cropper_mask.py` 中 `_build_border_paint_mask` 的 `paint_region` 使用 `_angle_in_corner_sector(..., tol=2.0)`，与重绘逻辑保持一致的边界容差。

### 验证
- 全量相关测试通过（47 passed / 5 skipped）
- 合成样例 `white_line_check_demo.py`（奶油底+60px 黑边+r=6.5cm）四个角放大图无白线

## 五、蔓生花/素锦深色弧线 + 南瓜无忧白隙修复（T4，上午）

### 问题一：深色弧形缺口线（蔓生花/素锦）

| 项 | 内容 |
|---|---|
| 现象 | 圆角边框外侧多了一层与边框贴合的深色弧形缺口线 |
| 根因 | `_build_multi_layer_corner_mask` 中 `ring_region` 保护像素到 `dist = r + 1.5`（弧线外侧），这些像素保留原始深色边框色；但 Step A 只绘制 `dist <= r`，外侧保护像素未被重绘 → 弧线外侧残留深色弧形线 |
| 修复 1 | `image_cropper_mask.py`：ring_region 上界从 `r + 1.5` 收窄到 `r + 1.0` |
| 修复 2 | `sector_render.py`：最外层（d=0）绘制扩展到 `dist <= R_total + 1.0` |
| 验证 | 弧线外侧（dist > r+1.0）深色像素数：**0** |

### 问题二：白色空隙（南瓜无忧）

| 项 | 内容 |
|---|---|
| 现象 | 内容区出现白色空隙 |
| 根因 | `protect_content=True` 时，`inner_cut` 将 border_zone 内 `dist <= r` 的所有像素切白，包括超出边框厚度的内容像素。这些内容像素不在 Step A 绘制深度范围内，无法被重绘 → 留下白色空隙 |
| 修复 | `image_cropper_mask.py`：`inner_cut` 仅裁切边框环带 `dist ∈ [r - raw_depth - 2, r]`，内容区（dist < r - raw_depth - 2）保持直角不被切白 |
| 验证 | 内容区白色像素数：**0**；边框弧深色像素占比：**100%** |

## 六、深色弧线未消除根因——ring_region 限于 border_zone（T5，中午）

### 问题
T4 修复后用户反馈蔓生花/素锦的深色弧线仍未消除。

### 根因
ring_region 在圆角 mask 中保护了弧线外侧的深色边框残留，**没有区分直边区域与弧线区域**。直边区域的 border_zone 需要保护（直边边框不能切），但弧线外侧的区域应该切到白底，否则会残留深色弧线。

### 修复（`core/image_cropper_mask.py`）
- **无条件定义 border_zone**（之前可能因条件判断未定义）
- **ring_region 限于 border_zone**：确保弧线外侧区域不被 ring_region 保护，从而被正确切到白色背景
- 直边边框（border_zone 内）仍受保护，不被误切

### 验证
- 受影响素材（蔓生花、素锦）非 border_zone 深色像素：**0**
- 所有回归测试通过，零新增失败

### 工程约定沉淀（写入 memory）
> 圆角 mask 的 ring_region 必须限于 border_zone（直边区域），防止保护弧线外侧深色边框残留。

## 七、草图三识别精度修复（T6，下午）

### 问题
草图三数据识别不准确：外框和挖角尺寸识别错误。

### 三重根因

| # | 根因 | 影响 |
|---|---|---|
| 1 | MORPH_CLOSE 形态学操作（iterations=2）导致数字标注与 L 形轮廓合并 | 凹角检测错误，OCR 结果错误归属 |
| 2 | OCR 误识别小数（47.5→475） | 尺寸数量级错误 |
| 3 | 过大的 bbox 噪声导致 OCR 结果误归属 | 尺寸分配错误 |

### 修复（`core/pool_designer/lshape_sketch_parser.py`）
1. **删除 MORPH_CLOSE** 操作，避免数字标注与轮廓粘连
2. **新增凸包差法**（convex hull difference）检测挖角区域，替代受干扰的轮廓检测
3. **过滤大 bbox 噪声**：移除面积过大的候选框
4. **数量级一致性检查**：OCR 结果与几何推断的数量级不匹配时标记异常
5. **几何一致性检查**：挖角尺寸必须小于外框尺寸，否则降级处理

### 验证
- 全部 46 个 L 形识别单元测试通过
- 草图三正确识别：外框 143×47.5cm，挖角 42.3×15cm

## 八、L 形 GUI 卡死 3 分钟修复（T7，下午）

### 问题
L 形 GUI 界面在后台运行时冻结近 3 分钟。

### 双重根因

| # | 根因 | 量化影响 |
|---|---|---|
| 1 | DiskCache 未持久化 dir_mtime，每次启动强制全量扫描 210k+ 文件 | 启动耗时 149 秒 |
| 2 | 主线程阻塞在模板库预热（warmup.wait） | UI 完全无响应 |

### 修复

**修复 1：DiskCache dir_mtime 持久化**（`core/parser/template_matcher.py`）
- 在 DiskCache 中增加 `dir_mtime` 字段的磁盘持久化
- 启动时先比较根目录 mtime，未变则快速跳过（2ms），避免全量扫描
- 用户需删除旧缓存文件（`C:\Users\Administrator\.smartshapecrop\caches\*.cache.pickle`）使新 schema 生效

**修复 2：信号槽机制异步预热**（`gui/property_panel_generate.py`）
- 主线程不再阻塞等待模板库预热完成
- 改用 signal-slot 机制：预热完成后通过信号触发 Worker 启动
- UI 在预热期间保持响应

**修复 3：挖角尺寸识别增强**（`core/pool_designer/lshape_sketch_parser.py`）
- 当外切边尺寸值不可用时，从内挖角区域提取尺寸作为备选
- 提高识别鲁棒性

### 验证
- 启动时间从 149 秒降至秒级（dir_mtime 命中时 2ms 跳过扫描）
- GUI 在预热期间保持响应，无冻结
- 挖角尺寸识别在边缘值缺失时仍能正确工作
