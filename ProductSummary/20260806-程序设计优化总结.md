## 任务三：8cm 大半径圆角裁剪 4 类质量问题

**背景**：用户用 8cm 半径圆角（超过原 8.5cm 全层圆角临界点），一次性暴露出 4 个叠加的图像质量问题。

### 子问题 3.1：多层圆角阈值过高 → 中等半径仅外框圆角

| 项目 | 内容 |
|------|------|
| **问题现象** | 4~8cm 半径圆角时，内层边框/花纹图案未做圆角，仅最外框被圆角，导致内层直线边与外层圆弧不衔接，视觉上出现"阴影遮挡"感 |
| **根因** | 原阈值 `BORDER_ONLY_THRESHOLD_CM = 8.5cm`：≥8.5cm 才对所有嵌套层做圆角，<8.5cm 只做边框区（1.5cm 深度）圆角。4~8cm 是印刷常用半径区间，原方案覆盖不足 |
| **解决方案** | 阈值从 **8.5cm 下调至 4.0cm**：<br>• `radius ≥ 4.0cm`：所有嵌套层统一做圆角（有效半径算法：`R_eff = max(0, R_original - max(dx, dy))`，`dx/dy` 为该层到图像边缘的 x/y 距离）<br>• `radius < 4.0cm`：仅边框区（1.5cm 深度）圆角，内部保持直角<br>有效半径算法修正：用 `max(dx, dy)` 而非 `min(dx, dy)` —— 原 `min` 会导致内层 mask 侵入外层保留区，产生白色扇形角 |
| **代码参考** | [compute_inner_corner_radii L264-L297](file:///d:/SmartShapeCrop/core/geometry.py#L264-L297)、[compute_border_bands L343-L349](file:///d:/SmartShapeCrop/core/geometry.py#L343-L349) |

### 子问题 3.2：边框厚度估算无上限 → 假厚边框阴影遮挡

| 项目 | 内容 |
|------|------|
| **问题现象** | 大半径圆角下，图像内部的花纹/图案被误识别为"边框层"，被整层涂色覆盖，看起来像"阴影遮挡"了内部内容 |
| **根因** | `_get_border_layers_robust()` 的 fallback 分支中，边框厚度估算**无上限**：从边缘向内扫描直到颜色变为背景色，如果内部花纹是深色连续的，会被估算成数百像素的"超级厚边框"，后续重绘时整层涂色侵入内层 |
| **解决方案** | 在 [core/corner/detection.py L108-L122](file:///d:/SmartShapeCrop/core/corner/detection.py#L108-L122) 增加严格上限：<br>`fallback_max_thickness = max(MIN_LAYER×2, min(MAX_DEPTH//3, max(30, min(w,h)//20)))`<br>两层保护：<br>① 绝对上限：`BORDER_SCAN_MAX_DEPTH_PX // 3`（默认 300//3 = 100px）<br>② 相对上限：`min(w, h) // 20`（图尺寸的 5%）<br>扫描时 `thickness >= fallback_max_thickness` 立即 `break` |
| **代码参考** | [_get_border_layers_robust L106-L122](file:///d:/SmartShapeCrop/core/corner/detection.py#L106-L122) |

### 子问题 3.3：圆弧重绘未保护透明区 → 扇形内折+色差复发

| 项目 | 内容 |
|------|------|
| **问题现象** | 修复子问题 2.1 后，大半径圆角下扇形内折+色差在特定检测场景仍偶发复发 |
| **根因** | `_redraw_border_on_corner()` 在圆角弧线上重新绘制多层边框时，**没有保护已裁掉的 L 形尖角背景区**：即使 mask 裁对了，后面的涂色步骤又把那些本应是背景色的像素重新涂上了边框颜色 |
| **解决方案** | 引入 `validity_mask` 保护机制（[core/corner/sector_render.py L222-L276](file:///d:/SmartShapeCrop/core/corner/sector_render.py#L222-L276)）：<br>① `_redraw_border_on_corner` 新增可选参数 `validity_mask: Image.Image \| None`（L 模式）<br>② 每层构建 `mask_bool` 后，必须 `mask_bool &= valid_arr`（L309-L313）——**只有 validity_mask > 0 的像素才允许被修改**<br>③ 注入点：`apply_rounded_corners`（L164-L170）和 `apply_border_only_corners`（L251-L255）调用时，**必须传入 final_mask 作为 validity_mask**<br>效果：本应裁掉的 L 形尖角区（mask=0）绝对不会被重绘涂色侵入 |
| **代码参考** | [_redraw_border_on_corner L217-L330](file:///d:/SmartShapeCrop/core/corner/sector_render.py#L217-L330) |

### 子问题 3.4：边框颜色采样不准 → 圆弧色差/偏色

| 项目 | 内容 |
|------|------|
| **问题现象** | 圆角圆弧上的边框颜色与直线边框有肉眼可辨的色差：TL/TR 角偏灰、BL/BR 角偏黑 |
| **根因** | 3 个因素叠加：<br>① **抗锯齿污染**：采样范围包含最边缘 2px 抗锯齿过渡带（半透明混合色），拉低了平均值<br>② **角落无感采样**：4 条边全部采样，会采到对面边的内部花纹/背景色（如 TL 角采到 bottom/right 边，污染中位数）<br>③ **均值不鲁棒**：用平均值易被离群抗锯齿像素带偏 |
| **解决方案** | 重写 `_sample_border_color()`（[core/corner/sector_render.py L131-L214](file:///d:/SmartShapeCrop/core/corner/sector_render.py#L131-L214)），4 项改进：<br>① **角落感知采样**：只采样该角物理衔接的两条直线边（TL: top+left、TR: top+right、BL: bottom+left、BR: bottom+right）<br>② **跳过抗锯齿带**：跳过最外层 2px<br>③ **厚度中心 ±35% 范围 + 中段纯直线**：采样深度定位在边框厚度中心，左右各 25% 留白（取中间 50% 直线段，避开角点）<br>④ **中位数统计**：用 `np.median()` 替代平均值，抗离群像素<br>综合效果：采样颜色与直线边框颜色欧氏距离 < 3（肉眼不可辨） |
| **代码参考** | [_sample_border_color L131-L214](file:///d:/SmartShapeCrop/core/corner/sector_render.py#L131-L214) |
