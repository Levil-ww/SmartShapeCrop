### 关键教训（方法论）
1. **本机 PowerShell 工具 stdout 捕获为空**，返回 `exit code 0` 却无任何输出。
   子代理据此把「命令无输出」误判成「`git status` 为空、工作树 == HEAD」，
   进而推出错误结论「失败用例是已提交的真实回归」。
   → **状态判定类命令必须用可回显的方式复验**：`Bash` + `.venv\Scripts\python.exe` 调 `subprocess`
   并 `print(repr(...))`；绝不以「无输出」作为「无内容」的证据。
2. **决定性问题用「HEAD 里有没有这段代码」来判**，比争论工作树状态更硬：
   `git show HEAD:<path>` 后做子串判断，一锤定音。
3. 成员结论冲突时**主理人必须自己实测**，不能按信任度采信。
