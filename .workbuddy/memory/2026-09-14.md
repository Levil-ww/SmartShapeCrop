**关键判断：几何本身不难，难的两层是「边框补全走线」与「草图识别」。**
- 几何上多角 = `矩形 − cut1 − cut2 − ...`，纯布尔差集，mask 天然支持 → 1–2 天
- `lshape_border.py` 6 个函数 cut_corner 贯穿，多角时每个凹角要独立检测边框带 + 补边，
  相邻凹角还会互相干扰 → 1–2 周
- 草图识别要从「整图找唯一凹角」升级为「找全部凹角 + 各自尺寸 + 尺寸标注归属」，
  且会放大已有软肋 SR-1（OCR 标注 D/C 归属错位）→ 1–2 周

**结论（已告知南烛，未执行）**：**建议扩展现有 L 形面板，不单开面板。**
理由：难点全在 core 的几何/边框，不在 UI；新面板仍要写同一组 `l_*` 字段、走同一个 `render_design`，
只会多一份 UI + 多一套历史源 + 多一处穿透读写 —— 正是《多洞面板拆分可行性分析 V1.0》里
点名的"寄生 + 四条链路穿透"结构。L 形面板当初独立是**模式级隔离**（与水池互斥 + 历史第三源），
不是参数级隔离，多角属于同参数族扩展。

**待补的健壮性**：`_validate_lshape_geometry` 的 `cut < outer-2cm` 需升级为**逐边约束**
（如上边 `cut_tl_w + cut_tr_w < outer_w - 2cm`），否则相邻两 cut 相接会退化。

**过渡方案（文档 SR-3 已有）**：零星定制单可「单角渲染两次 + 外部合成」顶着，频次高了再做。

## ⚠️ 重要修正：识别层多角能力「基本已实现，只是被收敛机制屏蔽」（2026-09-14 实测）

**上面 V1.0 报告把「草图识别多角化」估为 1–2 周，本次实测证明偏保守。**
用真实尺寸链造合成草图（143×62.8，tr cut 28×8，bl cut 30×12.8，4 px/cm）跑现有函数，结果：

1. **`_detect_lshape_geometry` 返回 `success` 语义下的单角结果**：`corner='bl'`,
   `cut=29.5×12.75cm`（真值 30×12.8 ✓），`n_verts=6` —— **右上那个 28×8 被静默吞掉，
   没有报错、没有告警**。这是最危险的失效模式：识别错了还显示「L 形识别成功」。
2. **凸包差异法的 `gap` 连通域天然就是 2 个**（每个凹角一个），且尺寸方位全对：
   区域1 = 27.5×8.0cm 触碰【右、上】→ tr 挖角；区域2 = 29.5×12.8cm 触碰【左、下】→ bl 挖角。
   但 `_detect_by_convex_hull` 里 `best_label = 1 + argmax(areas)` **只取了最大的一个**。
   → **判据：连通域面积 ≥ bbox 的 0.5% 且触碰 ≥2 条 bbox 边 = 真凹角**（实测 100% 区分）。
3. **`_collect_approx_candidates` 的 tier2 里躺着 7 个 n_verts=8 / 凹角数=2 的候选**，
   凹角坐标 (115.2, 8.0) 与 (29.8, 50.0)，与真值 (115,8)/(30,50) 误差 <0.2cm。
   但 `chosen_list = _tier1 or _tier2 or _tier3` —— **tier1 被滑动窗口+凸包法（各只返回 1 个角）霸占，
   tier2 永远短路不到**。

**结论：三条通道里两条已算出多角数据，只在「收敛点」被掐成 1 个。**
改造点收敛为一处语义：把 3 处收敛（`argmax(areas)` / `_tier1 or _tier2` / `max(score)`）
换成**「按 bbox 四角分桶，每桶留最优 1 个，最多 4 个」**。判定逻辑 = 凹角计数，不是猜。
现有硬约束（`dist_ratio<0.40` 到最近 bbox 角、cut 比例 [0.03,0.75]）**天然适配多角**，无需改动。

## L 形切边补边「切角处画超」根因定位（2026-09-14 下午，只诊断未改码）

**现象**：南烛给的界面截图（L形面板 + corner='tr' / 挖角 10.2×9.0cm）+ 一张角部放大图，
报「垂直切边或水平切边的某一层在切角处画超了，进入了不该画的区域」。

**像素级实测（对截图只读分析，未跑渲染）**：
- 截图坐标下缺口左边界 `x=417`、缺口下边界 `y=79`、产品（花纹）顶边 `y=62`
- 逐列统计「y=40..97 内纯米色(247,233,206) 的行数」：
  `x=388..400 → 11~20/58`（正常花纹），`x=402..416 → 54~57/58`（**被纯色覆盖**）
  → 缺口左侧存在一条 **宽 ≈15–16px 的纯色竖条**，把该处的花纹与顶部点状边框整体盖掉
- 该竖条 y 范围从画布顶端一直延续到 y≈97（含缺口下边界以下的 16px，即内凹角填充区）
- 对照：水平切边覆盖 `x∈[417,465) × y∈[81,97)`，厚度与竖条一致 → **同一套 layer 厚度（T≈16px）**

**根因（代码级）**：垂直切边各层的 y 起点写成 `0`，跨度 `[0, yc)`，而 `yc` 因
「cut 扩展到画布边缘」而包含了**产品顶边之上的画布边距**，于是该层在 y 方向越过产品有效边界。

| 位置 | 代码形态 |
|---|---|
| `core/lshape_border.py:1098` | `b[0:yc, xc-edge:xc] = black` —— 硬编码从 y=0 起铺 |
| `core/lshape_border.py:1100` | `b[edge:yc, xc-T:xc-edge] = color` —— 同上 |
| `core/lshape_border_route.py:462-467` | `y_lo = offs[k] if offs[k] < yc else 0`；`y_hi = yc+1` 同病 |
| `core/image_ops.py:1266` | `cut_h_px = lshape.cut_h + _ir_y`（cut 扩到画布边缘，yc 因此越过产品顶边） |
| `core/image_ops.py:1286/1294` | `outer_rect=_canvas_rect` 传整个 canvas → 子图 = 全画布，补边无产品边界可裁 |

**已排除**：缺口内越界 = 0（受控实验 60×60 合成画布实测，两条路径都 0 像素越界）；
内凹角 `max(dx,dy)` 切比雪夫分层经形态学验算 = 方形结构元腐蚀的**正确**结果，非 bug。

**次要缺陷（一并记录）**：
1. `lshape_border_route.py:473` 水平切边从 `yc+1` 起算，而垂直切边到 `yc` 结束
   （`:465` `y_hi = yc+1`）→ 缺口下边界留 **1px 亮缝**；V13 路径（`:1102`）用 `yc` 起算，两者口径不一致。
2. 两条路径「顶部让位」口径不同：V13 用 `edge`，Profile 用 `offs[k]`（即 `edge`），
   当多层时 Profile 的 `y_lo` 逐层递增而 V13 固定 `edge` → 层序可能错位。

（缺口边缘相对画布边缘的内缩量，调用侧 = `inner_rect.y` / `W - inner_rect.right`），
把垂直切边 y 起点与水平切边 x 终点裁进产品边界；默认 0 → 完全向后兼容。
