### 二、根因1（已确证）：venv 的 PyQt5 处于版本混合损坏状态

**现象**：`from PyQt5.QtCore import ...` → `ImportError: DLL load failed ... 找不到指定的程序`（0xc0000139）

**证据链**：
- `QtCore.pyd` = Aug 3 14:50（Qt **5.15.2** 编译的绑定）
- `PyQt5/Qt5/bin/Qt5Core.dll` = Aug 3 14:50，6.0MB（Qt **5.15.2**，159 个 DLL）→ 与 pyd 匹配 ✓
- `PyQt5/Qt5Core.dll` = Sep 1 14:48，4.9MB（Qt **5.15.11**，36 个 DLL）→ 混入 ✗
- pip 元数据：PyQt5 = 5.15.11，PyQt5-Qt5 = **5.15.2**（版本不一致）
- 决定性验证：
  - 先 ctypes 加载 `Qt5/bin/Qt5Core.dll` 再 import → **成功**（Qt=5.15.2）
  - 先 ctypes 加载根目录 `Qt5Core.dll` 再 import → **失败**
- 机制：`PyQt5/__init__.py` 的 `find_qt()` 把 `Qt5/bin` 加入 PATH，但 `QtCore.pyd` 位于 PyQt5 根目录，Windows 加载扩展模块时**扩展模块所在目录优先**，故默认命中根目录的 5.15.11 → 符号缺失崩溃

**注意**：VC++ 运行库齐全（msvcp140/vcruntime140/concrt140 均在 System32），不是运行库问题；清洗 PATH 也无效，确属包内版本冲突。

**修复方向**：干净重装 PyQt5（先卸载 PyQt5 / PyQt5-Qt5 / PyQt5-sip，删除残留目录，再装匹配版本）。

### 三、根因2（代码缺陷）：ExportSaveWorker 缺少退出保护

- `PreviewCanvas` 有 `shutdown()`（wait 渲染线程），且 `main.py` 有 `app.aboutToQuit.connect(w.canvas.shutdown)`
- 但 `main.py` **没有处理** `_save_worker`：`_save_cleanup()` 直接 `self._save_worker = None`，无 `isRunning()` 检查、无 `deleteLater()`、无 `closeEvent`
- 后果：导出 JPG 进行中关闭窗口 → "QThread destroyed while running" 崩溃
- 对比：`_retire_worker()` 已是正确范式（requestInterruption + finished→deleteLater），导出线程未遵循
