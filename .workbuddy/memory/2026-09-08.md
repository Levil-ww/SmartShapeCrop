# 2026-09-08

## L 形挖角 Profile Route —— 真实素材校准（蔓生花 / 中古雨林）

### 用户反馈的两个问题
1. 中古雨林完全没有 L 形边框（切边纯白）。
2. 蔓生花沿切边的补画颜色与原素材有色差。

### 根因（用真实素材 dump 剖面定位）
- 旧 `_classify_profile`「遇到 field 色段即停」：中古雨林黑描边后是 161px 白边距
  (= field 色) → 结构在描边处被截断，只剩 1 层。
- `_MAX_LAYERS=4` 装不下 5 层结构；`_LINE_MAX_THICK=18` 小于真实细线（24px）；
  `_DARK_LINE_MAX_CHANNEL=170` 卡住真实线色漂移（168~179）；
  field 容差 25 太紧（花田过渡段 L2≈30 漏裁）。
- 之前调试用的"蔓生花"jpg 其实是程序输出图（裁剪有图），不是原始素材——
  原始素材在 `F:/失败-异形制图/DesignAutoMation/蔓生花80-140.psd`（psd-tools 提取）。

### 重写后的分类算法（core/lshape_border_route.py）
1. 窗口收集（短边×15%）；巨段：深色且色近 field → 限厚收录（克罗棕带直通内部），
   浅色巨段（花田/白底）丢弃。
2. 尾裁 field 段（容差放宽 35）。
3. 定界：末线后仅保留紧贴的深色平整带（描边+色带结构），其余剔除。
4. 分组：线独立成层，相邻非线段（边距/点带/文字带）无条件合并 —— 层数只由
   线位置决定，跨边稳定。
5. 让位规则：首层厚黑(≥50) → V13；首层黑细描边+深色第二层（克罗类）→ V13，
   保护用户已认可的克罗效果。

### 真实素材验证结果
- 蔓生花 PSD (8268×4724) → 5 层 [黑10, 米285(246,232,205), 线25, 点带123, 线25]
- 中古雨林 (5965×3602 等 3 个版式) → 5 层 [黑10, 白162, 线15, 文字带124, 线14]
- 克罗印花 → None 让位 V13（现状不变）
- 端到端渲染：切边米色与素材一致，L 形框线连续转角。
- 测试：新增合成雨林全结构夹具（描边/白边距/框线/文字带/框线），
  全量 316 passed + 5 skipped。

### 踩坑备忘
- 合成夹具的周期性花纹：周期 <10px 会被「3 扫描线均值 + 滑动平均」抹平；
  扫描线位置不能与花纹周期对齐（同相位 → std=0 → 误判成线）。
- 段 std 是平滑过的，邻段花纹的列间差异会扩散进线段（实测 17.3）→
  线判定用独立容差 `_LINE_STD_MAX=20`（真实素材线 std=0 不受影响）。

## L 形挖角 Profile Route 第三轮（用户反馈 3 问题）修复

### 用户反馈
1. 蔓生花/中古雨林 L 形只需补到「绿色箭头所指最外内框线」，点带/文字带及其内侧细线不处理；
2. 但程序实跑蔓生花/中古雨林仍无 L 形边框（离线样张正确）；
3. 庄园秘境出现白线 + 黑边带明显变细。

### 端到端诊断结论（用 pattern_library 真实素材 dump 剖面 + 切片）
- **"无效果"真因**：Profile 实跑**确实触发**，但 `left` 边最外 2px 出血白边
  未对齐 → 四边层序错位 → 投票把颜色平均成 `(64,64,64)`/`(187,187,187)` 灰糊，
  补出来不是素材的黑白框 → 视觉上=无边框。
- 庄园秘境剖面：`[6px 出血白边] → [117px 粗黑带] → [39px 米底]`。
  117px 粗带不被 `_LINE_MAX_THICK=32` 判为线 → Profile 判废；落到旧路径
  （且旧路径 `(sx+sy)/2` 在 ROTATE_270 素材下误差 100%+，黑带 226px ≠ 素材 118px）
  → 白线 + 黑带变细。

### 三处修复（core/lshape_border_route.py + core/lshape_border.py）
1. **锚点对齐**：跳过最外出血边/裁切边，锚点=第一个「近黑+低纹理」段（不限厚度）。
   `_is_anchor_seg` 用 `_BLACK_MAX_CHANNEL=90`（1px JPEG 灰过渡段 max~116 被排除，
   混入锚点会让四边层序错位）。四边层序一致 → 投票颜色真实。
2. **层深截断到第二条细线**：描边 + 色带 + 最外内框线 = 3 层封顶。
   `_MAX_LAYERS 5→3`。line#2 之前的非线段中丢弃花纹段（std≥_FIELD_STD_TOL），
   只保留紧邻锚点的第一个平整带 —— 避免左 2px 出血边 + 文字带均值污染中间层。
   无第二条细线时保留 锚点+紧邻平整带（克罗式 2 层）。
3. **庄园秘境粗黑带**：分组时锚点（th>_LINE_MAX_THICK 的粗黑带）**独立成层**，
   不被紧随米底平均成灰糊。让位判定函数 `profile_yields_to_v13` 外移到路由层：
   V13 命中则用 V13，V13 未命中（庄园秘境内侧无主色带→v13=None）则 Profile 接管。
4. **几何均值 scale**：`sqrt(sx*sy)` 替代 `(sx+sy)/2`，对 adapt_pool_material 的
   ROTATE_270 稳健（旋转后 sx/sy 互换但乘积不变）。修复庄园秘境黑带厚度。

### 验证结果
- 蔓生花 PSD → `[黑10, 米285(246,232,205), 线25]` 3 层（yields=False 走 Profile）→
  色带颜色与素材一致，止于内框线，不再补点带/内细线。
- 中古雨林:100x140 → `[黑10, 白147, 线20]` 3 层；:10x100 → `[黑3, 白40, 线4]`。
- 庄园秘境:30x115 → `[黑116, 米32]` 2 层；黑带厚度恢复 114px≈素材 118px。
- 端到端渲染三素材 L 角局部均正确：白线消除、黑边厚度一致、L 形框线连续转角。
- 全量测试 320 passed + 5 skipped。

### 关键设计决策
- `_is_anchor_seg`（近黑不限厚）与 `_is_line_seg`（深色+薄≤32）分离：
  锚点只管"最外起笔"，线只管"细分层"，各司其职。
- 让位判定放路由（profile_yields_to_v13）而非 detect 内部返回 None，
  使 V13 未命中时 Profile 仍能接管（庄园秘境粗黑带）。
- `_TOTAL_DEPTH_RATIO 0.30→0.50`（粗黑带 60/300 尺寸下 105>90 被误判为图案误检）。
