## ⚠️ 事故：`git rm` 触发 tests/ 整目录连带删除（2026-09-11）

**现象**：执行 `git rm tests/border/test_border_fix.py`（只删 1 个文件）后，
`tests/` 目录下**全部 29 个文件**从工作区消失（`git status` 一片 ` D`），
连 `tests/` 目录本身都没了。我只想删 1 个，结果整个目录被清空。

**恢复**：所有文件仍在 git 索引里，`git checkout -- tests/` 一次性全量恢复，无内容损失。

**副作用**：`git checkout` 从**索引**恢复，导致我之前未暂存的
`test_gap_fix_verification.py` assert 修改被覆盖丢失，**不得不重做第 1 项**。

**教训（重要）**
1. **`git rm` 在本机有连带删除风险。** 后续改用普通 `mv` / `rm` 单文件 + `git add -A`，
   减少对 git 索引的写入面。第 5 项改名用 `mv` 就完全正常（git 仍能识别为 R）。
2. **改文件后立刻 `git add`**，别让修改长时间处于未暂存状态 —— 否则任何
   `git checkout --` 恢复操作都会把它冲掉。
3. **每步删除后立即验证**：`git ls-files <dir> | wc -l` + `ls <dir> | wc -l` 对比，
   确认只少了预期的那一个。
4. 这是本机**第二次**非预期文件丢失（第一次是 `git gc` 清空 `.git`）。
   本机对 git 写操作存在环境级干扰，做批量/破坏性操作前先确认可恢复路径。

**三个必踩的环境坑（测试侧解决，源码零改动）**
1. **离屏**：`QT_QPA_PLATFORM=offscreen` 必须在 QApplication 创建**前**写入 os.environ，
   否则报 "could not connect to display"。放 tests/gui/conftest.py 顶层。
2. **退出崩溃 exit 127**：PropertyPanel 构造时若"上次模板库目录"存在，
   启动 `_WarmupScanWorker`；解释器退出时线程仍在跑 → 进程崩溃码 127。
   二分定位法（`WHICH=prop/main` 逐个测退出码）定位到 PropertyPanel。
   解法：teardown `findChildren(QThread)` 全部 quit/wait。
3. **配置污染 + 网络盘**：AppSettings 走 QSettings（注册表），默认模板库是
   `\\192.168.1.199\...`（21 万张图）。用独立 org/app 的测试实例替换

**可复用技巧**
- **信号连接断言**：`signal.disconnect(slot)` 未连接会抛 TypeError，
  先 disconnect 再 connect 复原 → 可验证"已连到这个槽"，且不改对象状态。
- **控件定位**：本项目 GUI 控件基本无 objectName，只能按内容找
  （`find_combo_containing(widget, '矩形嵌套挖洞')` / `find_spinbox(w, 72, 600)` 按范围）。
- **信号清单探测**：`type(getattr(cls,n)).__name__ == 'pyqtSignal'` 比
  `hasattr(attr,'emit')` 可靠（后者会漏，曾漏掉 sketch_view_requested / target_changed）。
