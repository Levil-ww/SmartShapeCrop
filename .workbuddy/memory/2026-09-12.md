### 最重要的发现：P0-01 今晨三次真实崩溃（昨日报告称"未复发"）

`crash.log` 中记录 2026-09-12 三次崩溃（09:46:55 / 09:47:12 / 09:59:15），同一根因：

```
main.py:307 in _on_rendered
TypeError: unsupported format string passed to IFDRational.__format__
```

- 根因：`f"{img.info['dpi'][0]:.0f}"` 对 PIL 的 `IFDRational` 类型格式化。该类型**不支持任何格式说明符**（`d`/`f`/`.0f`/`.1f`/`g` 全抛 TypeError），只有空格式可用。
- 触发：上传带 **EXIF 分辨率标记**的图片（手机/相机/微信/PS 保留 EXIF）→ `Image.open()` 出来 dpi 元素即 `IFDRational`。
  两条路径：`main.py:331 _on_sketch_loaded`、`main.py:314 _on_cropped_image`，都把 `Image.open()` 产物 emit 给 `_on_rendered`。
- **项目自有 204 张图的 dpi 全是 int**（程序生成），所以靠项目素材永远复现不出 → 长期潜伏。
- 关键对比：同一项目 `core/image_ops.py:1697-1701`（save_jpg）**已经做了 `int(round(dpi[0]))` 防御**，唯独 main.py:307 漏了。
- 修复口径：与 save_jpg 同源（`float()` / `int(round())` 包裹 + 类型/长度兜底）。
- 探针实证：Qt 槽内异常会被 `sys.excepthook`（main.py:507）写入 crash.log；`_probe_crash.log` 复现出同样内容。
