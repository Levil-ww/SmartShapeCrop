## 综合形状（中间挖洞 + L 形挖角）实现方案分析 V1.0

**起因**：南烛给出综合草图 `E:\智能裁剪设计器\测试草图文件-综合中间+L形\吸水皮革-定制-裁剪有图-白色大理石8;88x185CM裁剪有图.png`
（外框 185×88，右上挖角 35×10，中间洞 80×60，边距 上10/下18/左45/右60），问「新建项目还是单开面板」。

**产出**：`F:\SmartShapeCrop\综合形状_中间挖洞+L形挖角_实现方案分析_V1.0_20260915.md`（576 行）

**核心结论**
1. **否决新建项目**。图形引擎/三级边框路由/OCR/打包都是重资产，新建 = 复制 ~1.5 万行 + 永久双份维护。
2. **把决策拆两层**：引擎层（新 mode `rect_lshape_hole` + 几何组合，**无选择余地**）与外壳层（新 Tab / L 面板内加勾选，**可延后决策**，切换成本极低）。
   建议先走"L 面板内加分组"（~1 天），按实际订单频次再升级为独立 Tab。
3. **草案与既有规划对齐**：本需求 = 既有 `规划 F-1（多 L 形挖角 + 中间洞复合支持，P2，原估 3–4 周）`，
   也是软肋 `SR-3` 的正式化解方案。因"边框补全逐角调度"已由 `7524f30`/`300c3dc` 还清，
   工期可从 3–4 周下修到 **8–14 个工作日**。
4. **与既有 V1.1 多角分析 §8「不要单开面板」的关系**：该结论针对"多角 vs 单角"（同参数族）；
   本问题"L + 洞"是**新增几何实体**，其四条理由中 ②③ 不成立、①④ 成立 → 结论不能直接移植，
   文档 §8 做了逐条对照。

**关键技术发现（本报告新增证据）**
- `mode` 判断全工程 **19 处**（不是 16 处）：`core/image_ops.py` 9、`gui/property_panel_generate.py` 6、
  `core/geometry.py` 2、`models/design_model.py` 2。**其中 3 处是 `!=`**（`design_model.py:114`、
  `property_panel_generate.py:220`、`:327`），只搜 `== 'rect_lshape'` 会漏掉。
  必须**四类分治**：①渲染语义(8，改 membership) ②分派点(2，必须新增独立分支)
  ③展示/同步(4，扩展) ④参数守卫(5，重写逻辑)。
- **类② 若误改成 membership 会得到"并集"而非"差集"**（洞被填满）且不报错 —— 最隐蔽的坑。
- 隐藏耦合两处：`gui/property_panel.py:926` 硬编码索引映射 `{'rect_hole':0,'rect_lshape':1,'ellipse_hole':2}`
  （不同步 → 模板加载静默回落 rect_hole）；`core/app_settings.py:317` 未知 source **静默回落 cropper**
  （新增第 4 历史源必须同步白名单）。
- 几何基准互换风险：现有 `rect_lshape` 分支把 `inner_rect` 当 L 形外轮廓（因边距被强制 0）；
  复合模式 L 形外轮廓必须是 `outer_rect`，`inner_rect` 改为表示洞。
- **G1 闸口需扩展**：V1.1 的 `notches_detected/consumed` 只防"漏角"；复合模式要新增"洞是否被识别"断言，
  否则会出现"挖角全对、洞被静默丢弃却报成功"的新盲区（洞在做品上比角更显眼）。

**零改动可行性验证（已执行，通过）**
