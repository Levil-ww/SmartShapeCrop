四、项目优势（已确认）

① 圆角算法单一可信源
carve_corner_on_mask 用距离场精确刻画 1/4 圆，规避 PIL pieslice 锯齿/缺口；三处入口统一委托，架构清晰。
② 健壮日志系统
RotatingFileHandler + 幂等保护 + 文件不可写时自动降级控制台，不阻断程序。
③ 全局崩溃钩子
sys.excepthook → crash.log 为无控制台冻结包提供排障入口（本次崩溃即被其捕获）。
④ OCR 容错设计
safe-import、缓存优先、公开函数永不抛异常，整体降级链路设计良好。
⑤ 输入校验较全
草图扩展名/大小/像素上限 + 几何自洽 + 方向标签多重校验流程严谨。
⑥ 资源路径抽象
resource_path/PathResolver 区分源码与 sys._MEIPASS 冻结模式，定位正确。
⑦ 异步渲染模式
render_id 版本号丢弃过期结果 + LOD 分级 + requestInterruption，避免卡顿/过期覆盖。
⑧ 无可变默认参数
全仓未现 f(x=[]) 类 bug，CropDesign 用 field(default_factory=…)。
⑨ 测试基数可观
152 个 test_ 覆盖圆角/解析/裁剪/模板匹配等核心算法。
⑩ 主路径解炸弹防御
Image.MAX_IMAGE_PIXELS=2亿 防御解压炸弹；load_image_rgb 处理 EXIF 方向。
⑪ 配置集中化
core/config.py 统一常量单一来源，消除散落魔法数字。
⑫ 打包脚本现代化
packageV2.0.py 改用相对路径 + collect-all + 自动 PyInstaller，比旧 .spec 完善。

五、风险与缺陷明细

编号等级问题 / 位置风险修复建议
F1严重 预览管线崩溃（已复现）
geometry.py:237 fill_rect_mask → image_ops.render_design → canvas._render_lod		 当 inner_rect 退化（x1<x0，边距过大或 LOD 下采样取整反转）时 d.rectangle 抛 ValueError，预览静默失败；crash.log 已记录真实栈。 所有 fill_rect_mask / 圆角入口前统一守卫：inner_rect 宽高必须 >0，否则 clamp 或跳过绘制；LOD 缩放后对坐标做 min/max 归一。
F2高 requirements.txt 缺失 pytesseract
requirements.txt:1-6（README 表格却列出）		 干净安装后 pip install -r requirements.txt 不含 pytesseract，OCR 全局静默失效（仅“Python 包未安装”日志），草图识别功能不可用。 补充 pytesseract>=0.3.10；并在 README/打包说明中明确需要系统 Tesseract 引擎。
F3高 sketch 先解码后校验（解炸弹顺序错）
sketch_parser.py:2201 _load_image 全量解码 → 2227 validate		 cv2.imread 无像素上限，恶意/异常图在尺寸校验前已全量解码进内存，可能 OOM；该模块从未设 Image.MAX_IMAGE_PIXELS。 把 validate_sketch_file 提前到解码前（仅 PIL.open 读头）；并在模块内设置 Image.MAX_IMAGE_PIXELS 纵深防御。
F4高 共享 CropDesign 跨线程读写
property_panel.PoolRenderWorker 写 design._cached_* / canvas 主线程渲染同一对象		 同一 CropDesign 被子线程改写字段、主线程同时读取渲染，存在数据竞争（字段撕裂、渲染结果错乱）。 worker 内深拷贝 design 或仅回传不可变结果；用信号把结果传回主线程，杜绝原地改共享对象。
F5中 Tesseract 缺失不降级几何估算
sketch_parser.py:1890；packageV2.0.py:387 / README 措辞		 文档声称“未安装自动降级为几何估算”，实际 OCR 为空即返回 success=False，整次解析失败——功能缺失 + 文档误导。 实现真正的几何兜底分支，或更正所有文档/提示文案，明确“OCR 不可用则识别失败需安装引擎”。
F6中 _PARSE_TIMEOUT_SEC 定义但从未使用
sketch_parser.py:30		 无真实超时；某张触发 OCR 长时间卡死的草图会让 worker 线程永久挂起，“解析中”状态永不结束且无法取消。 worker 内加 QTimer 超时或在主循环累计耗时提前退出，超时返回降级结果。
F7中 死代码 _fill_corner_boundary_pixels
algorithm.py:198（全仓无调用）		 README / ProductSummary 仍声称其“大半径额外后处理”，实际从未执行；误导维护者以为有额外 C 形缺口保护。 删除死代码，或补上调用；统一文档，避免维护误判。
F8中 inverse=True 分支永不触发 / 未测试
geometry.py:299 恒传 inverse=False		 carve_corner_on_mask(inverse=True) 是内层精确挖空逻辑，全仓无调用、无测试；将来启用极易引入圆角挖空错误而无人察觉。 补单测覆盖 inverse 路径；若当前用不到，加注释说明其保留意图，防止误用。
F9中 椭圆模式多层边框退化成矩形逻辑
geometry.py:362 仅 rect_lshape 早返，ellipse 落入 rect_hole		 椭圆挖孔若走多层边框路径，会产生“矩形洞”边框带而非椭圆边框带，视觉错误；属未覆盖边界模式。 为 ellipse_hole 显式实现椭圆边框带；或文档明确“椭圆模式不支持多层边框”并在 UI 禁用。
F10中 依赖 opencv-python（完整版）而非 headless
requirements.txt:5		 完整版自带 Qt 插件，与 PyQt5 的 Qt 在 Windows 上可能冲突或加载异常，且膨胀包体；本项目只用 imread/cvtColor/resize。 改用 opencv-python-headless。
F11中 陈旧 .spec 硬编码绝对路径
智能裁剪设计器.spec:6,17,50		 旧 spec 写死 D:/SmartShapeCrop/…，换机 pyinstaller 智能裁剪设计器.spec 必然失败；与良好的 packageV2.0.py 矛盾，易误导打包。 删除或归档旧 spec；统一使用 packageV2.0.py（已用相对路径）。
F12中 硬编码绝对路径散落
process_image.py:23-24；config.py:165-166		 process_image.py 写死 D:\SmartShapeCrop\psd_demo 示例源/输出；config.py 含 D:\Tesseract-OCR 兜底路径——锁死作者机器，降低可移植性。 示例脚本改用相对路径 / 命令行参数；Tesseract 兜底仅作候选列表，不写死盘符。
F13中 simple_resize 实为“拉伸”却标注“推荐”
image_cropper.py:1657 src.resize((tw,th))		 默认模式直接非等比拉伸填满目标尺寸，源图宽高比 ≠ 目标时图像变形；但 UI 描述为“简单缩放 / 保持图片完整性（推荐）”，与用户预期冲突。 测试显式断言是否允许变形；UI 加“拉伸会变形”提示；或默认改为等比 cover/contain。
F14中 大量裸 except 静默吞错
sketch_parser.py 多处 / image_ops.py:34		 热路径中 except Exception: 无日志，隐藏真实异常（缓存键、进度回调、颜色增强等），生产排障困难。 至少 logger.debug 记录被吞异常；仅对确属“可忽略”的降级点静默。
F15低 调试脚本混入 tests/
tests/ 下 9 个文件 0 个 test_ 函数		 test_corner_analysis_simple / test_diagnose / test_gui_sim / test_sketch_fix 等调试脚本污染 pytest 收集与 CI 判定。 移入 scripts/ 或加 pytestmark = pytest.mark.skip；tests/ 仅保留真实回归用例。
F16低 PreviewRenderWorker 未正确清理
canvas_widget.py:112-142		 旧 worker 仅 requestInterruption() 即被替换引用，可能触发“QThread destroyed while running”警告，无 finished 清理。 等待 finished 或 deleteLater() 后再释放；统一 worker 生命周期管理。
F17低 pytest.ini 忽略 DeprecationWarning
pytest.ini:7-8		 掩盖 Pillow/numpy 即将移除 API 的信号，增加升级（如 Python 3.13 兼容）风险。 移除 ignore，或将告警转为显式技术债跟踪。
F18低 文档与实现不符（日志级别）
log_setup.py docstring vs :64		 docstring/注释称默认 WARNING，代码实为 LOG_LEVEL 默认 INFO，开发者调试预期偏差。 统一文档与代码表述。
F19低 运行产物缺乏自动清理
logs/(125) / debug_output/(76) / ProductSummary/		 草图诊断截图、调试中间图、日志持续累积，无滚动/清理策略，长期占用且混杂交付物。 增加产物上限/自动归档；区分“交付物”与“调试产物”目录。
